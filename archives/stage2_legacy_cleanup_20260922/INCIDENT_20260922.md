# 事故记录：2026-09-22 误删测试文件

## 发生了什么

在执行「删除 v3–v3.4 版本」时，我用了一个正则启发式来挑选"只测试被删版本的测试文件"：

```python
re.search(r"semantic_prompts(_v3[1-4]?)?['\"\s]|semantic_prompts_v3[1-4]\b", body)
```

这些文件的导入正是 `from prompts.versions.semantic_prompts import ...`（v3 基线），
匹配成功，于是它们被**连带删除**：

| 文件 | 原因 |
| --- | --- |
| `tests/test_observability.py` | 导入 v3 基线的 prompt 模块 |
| `tests/test_brix_real_regression.py` | 同上 |
| `tests/test_brix_retest_regression.py` | 同上 |

**且这 12 个被删的测试文件在执行前都没有备份**（只备份了 5 个 prompt 版本文件和 registry.py）。
`tools/report_constraints_v2/` 在 git 中是未跟踪状态，因此没有 git 历史可恢复。

## 恢复状态

好消息：`tests/__pycache__/` 中这 12 个文件的 `.pyc` 字节码**全部存活**。

已用上游 Decompyle++（`pycdc`，支持 3.12）反编译。**部分成功，但不完整**：

| 文件 | 反编译 | 缺口 |
| --- | --- | --- |
| `test_brix_real_regression.py` | 90 行 | 3 处 `with` 块被压坏；断言名可从 `pycdas` 取回 |
| `test_observability.py` | 161 行 | 4 处 `with` 块被压坏 |
| `test_brix_retest_regression.py` | 127 行 | **`variables()` 方法体整个丢失**（仅剩 `pass`），5 个测试依赖它 |

反编译产物保存在 `/tmp/recovered/`（含 `.dis` 反汇编）。

结论：**无法逐字还原**。方法体丢失的部分只能重写，不能恢复。

## 教训

删除文件前必须**先备份再匹配**，且**不用启发式正则**挑选删除目标——只按显式名单删除。
