## 实质问题及本地证据

### Kinetiq：I 对，P 尚不完整

I 表达调用确认函数且提款专用暂停时不得 `hype_withdrawn`；该观察量明确包含提款完成与 token 转出。限定候选 P 下，与窄核心义务的 XOR 为 UNSAT。没有把暂停失败简单写成“所有正常提款都应成功”。但 P 漏通用合同未暂停条件；一些作者声称的能力因“没有实际 incident”被整体降为 potential，不能混淆能力主张与已发生事件。

### SukukFi：拒绝合法无授权请求也会违反模型 I

模型 I 为 `sender != owner => caller_allowance >= shares`。这直接要求输入已获授权，没有把要求限定到成功花费。报告对应的安全义务应禁止**未授权成功花费**，允许合约正确拒绝未授权请求。

只读数学差异赋值：sender 与 owner 不同、shares=1、self allowance=1、caller allowance=0、burned=0、transferred=0。此时“不发生未授权花费”成立，模型 I 却为假。这是规范层数学赋值，不证明代码执行了正确拒绝。

正式拒绝位置：联合盗窃 claim 的 effects 子来源分别引用 burned/transfer 陈述，但 properties.effects.source_ids 只有 direct_theft，引用关系不一致。P 没有足额授权不足条件，受害者/receiver 关系仍未完整约束。模型还称 withdraw 同样受影响“不明”，与报告明确命名 withdraw 不一致。

### Merkl：窄 I 正确，但不能算候选整体成功

I 为 `callback_amount == transferred_toSend`，与窄参考一致，数学 XOR 为 UNSAT。模型没有编码完整“callback 等于累计权益”关系，仅表达 callback 与实际转账不等；参考中的累计与实际金额分离仅部分覆盖。

P 的 `claim_index > 1` 缺 `args.0` 来源映射，正式拒绝。附加检查发现 `transferred_toSend` 含大写字母，不符合当前前端符号命名规则。这是额外缺项，不冒称本轮正式校验已走到该处。

### Hybra：方向正确，表达与前提仍不足

主 I 为 `withdraw_time < deposit_time+lock_period => !withdraw_succeeds`。但 timestamp 与 seconds 在当前严格同单位前端不能相加；这是前端支持边界与输出单位规范不一致，不能简单说冷却意图理解错误。类型检查失败不计为完整公式对应。

P 使用 `withdraw_succeeds => withdraw_time >= maturity_time_caller`，把实际成功后的 guard 关系当成前提，而没有表达有效存款、正冷却期和提款时间顺序。子来源也缺项。第二 claim 禁止任何未成熟时奖励捕获，强于“不能提前退出流动性”，需要独立依据，不能自动当正常安全规则。

### GTE：only when 被翻成反向蕴含

报告指出合法正金额被误判并回退。对应安全义务应为“合法非零交易不应因该检测而回退”。模型选择“阻止真正零成本交易”，不足以表达误拒绝问题。

I 文本为 “blocks ... only when ... zero-cost”，AST 却是 `zero_cost_trade => trade_blocked`，而 only-when 应是 `trade_blocked => zero_cost_trade`（仍需定义实际零成本）。原正式关系查询 `P && V && !I=UNSAT`、`P && V && I=SAT` 正确提示该坏效果满足模型 I。

本地差异赋值：两个非零 flag=true、bitwise-zero flag=true、实际零成本=false、trade_blocked=true。候选 I 成立，窄参考 I 不成立。flags 没有数字定义，bitwise 支持缺项被模型明确保留，不证明数值代码可达。

## 数学诊断边界

评估程序只读原始候选。根据助手人工符号映射，在候选 P 下比较窄 I，数字观察量额外限制非负。Kinetiq/Merkl XOR 为 UNSAT，Sukuk/GTE 为 SAT，Hybra 为 type_error。**没有静默修补拒绝的候选，也没有将这些诊断计为正式链路完成。**

相同抽象上下文中的等价不证明所有自然语言细节、P 完整性、代码变量绑定或真实漏洞效果。金额为数学整数、地址为身份，没有代码转移关系 T 或 EVM 执行。
