UniswapPriceOracle.validatePrice() TWAP always equals spot price due to algebraic self-cancellation, rendering all V2 slippage protection non-functional

## Finding description and impact

UniswapPriceOracle.validatePrice() is intended to compare the current pool spot price against a Uniswap V2 TWAP to detect pool manipulation. If deviation exceeds a caller-supplied slippage tolerance, it should return false. However, the TWAP calculation contains an algebraic error that causes it to always equal the current spot price, meaning the function unconditionally returns true.

The function reads cumulativePriceLast (call it C) from the Uniswap V2 pair, then computes:


https://github.com/valory-xyz/autonolas-tokenomics/blob/bbec5ac12721a62672fb7a5ffba5c40f5a46d8cb/contracts/oracles/UniswapPriceOracle.sol#L77-L82

The stored cumulative history C cancels out. timeWeightedAverage always equals tradePrice (the spot price), so derivation is always 0, and the function always returns true.

A correct TWAP requires two cumulative-price snapshots separated in time. This oracle reads one snapshot from the pair but never stores a prior snapshot of its own — it fabricates the second data point from the current spot price, collapsing the calculation into a tautology.

## Impact on downstream callers:

BuyBackBurner._buyOLAS() (line 185) — the pre-swap require(IOracle(poolOracle).validatePrice(maxSlippage), ...) always passes, allowing V2 swaps to execute at arbitrarily manipulated prices.

LiquidityManagerETH._checkTokensAndRemoveLiquidityV2() (line 170) — the oracle guard never reverts, and the subsequent removeLiquidity call uses amountAMin = 1, amountBMin = 1, providing zero effective protection.

LiquidityManagerOptimism._checkTokensAndRemoveLiquidityV2() (line 232) — same issue; the Balancer exitPool call uses minAmountsOut = [1, 1].

An attacker can flashloan assets to manipulate pool reserves, trigger any of these operations, and profit from the skewed prices — the oracle gate that was supposed to prevent this passes unconditionally.
