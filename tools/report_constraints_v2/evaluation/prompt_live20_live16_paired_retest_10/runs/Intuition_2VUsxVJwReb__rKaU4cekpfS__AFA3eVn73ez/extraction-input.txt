_getPersonalUtilizationRatio first-time claimant 100% bonus unreachable for pure veTRUST holders  first-epoch rewards   permanently underallocated

## Summary

  `_getPersonalUtilizationRatio` contains a documented first-timer protection:

  "If the user had nothing claimable last epoch, don't penalize them as it's their first ever claim"

  This protection is structurally unreachable for users who lock veTRUST but do not interact with the MultiVault, because the
  delta-based early-return fires first. Every new veTRUST locker who does not deposit in the MultiVault during their first claimable
  epoch receives personalUtilizationLowerBound (30%) instead of the intended 100%, losing 70% of their first epoch's rewards to the
  protocol sweep.

  ---
  ## Vulnerability Detail

  personalUtilization in MultiVault is only modified by `_addUtilization` (called on deposit) and `_removeUtilization` (called on redeem).
  A user who never calls deposit or redeem always has `personalUtilization[user][*] = 0`.

  getUserUtilizationInEpoch returns personalUtilization[user][history[0]] where history[0] is the most recent active epoch. For a pure
  veTRUST holder with no MultiVault activity, this is always 0 for every epoch query.

  Control flow in _getPersonalUtilizationRatio for a pure veTRUST holder:

  userUtilizationBefore = getUserUtilizationInEpoch(user, epoch-1) = 0
  userUtilizationAfter  = getUserUtilizationInEpoch(user, epoch)   = 0
  rawUtilizationDelta   = 0 - 0 = 0

  Line 516: if (rawUtilizationDelta <= 0)          ← fires ALWAYS
  Line 517:     return personalUtilizationLowerBound  ← returns 30%, DONE
               // Lines 526-529 never evaluated

  The protected codepath (lines 526–529) requires rawUtilizationDelta > 0:


  Exact scenario where the design intent is violated:

  Consider Alice who locks 100,000 wrapped TRUST in epoch N (first-ever lock), claims for epoch N in epoch N+1, and never touches
  MultiVault:

  - eligible[epoch N-1] = 0 (she had no veTRUST before epoch N)
  - userClaimedRewardsForEpoch[Alice][epoch N-1] = 0 (never claimed)
  - rawUtilizationDelta = 0 (no MultiVault activity)

  Line 517 fires. Alice receives 30%.

  The first-timer condition at lines 526–529 would return 100% IF delta were > 0: target == 0 AND eligible[prev] == 0 — exactly Alice's
   situation. But the delta check blocks evaluation.

  Bob in the same epoch with the same lock size, but also deposits 1 ETH into MultiVault:
  - delta > 0 (the deposit incremented his personalUtilization)
  - reaches lines 526–529: target == 0, eligible[prev] == 0 → returns 100%

  Scope limitation (important for severity):
  - This 70% loss only applies to a user's first claimable epoch where they have zero prior veTRUST balance in the previous epoch.
  - In all subsequent epochs, personalUtilizationLowerBound (30%) is the intended behavior for users not growing their MultiVault
  position (delta = 0 with prior claim history → correct).
  - If the user had veTRUST in the previous epoch but did not claim, they fall into the "chose not to claim" branch regardless of the
  delta check, so the first-timer protection would not have applied anyway.

  ---
  ## Impact

  Every new veTRUST locker who does not interact with MultiVault during their first claimable epoch loses 70% of that epoch's rewards
  to the protocol sweep.

  Example (default test configuration):
  - Alice locks 100,000 wTRUST, sole locker in epoch N
  - emissionsForEpoch(N) = 1000 TRUST (system utilization ratio assumed 100% for simplicity)
  - Alice's eligible raw rewards ≈ 490 TRUST
  - Expected (per code comment): 490 TRUST × 100% = 490 TRUST
  - Actual (bug): 490 TRUST × 30% = 147 TRUST
  - Lost to protocol sweep: 343 TRUST (70%)

  The user has no recourse. No admin action can retroactively correct the claim.

  ---
 ## Recommended Fix

  Move the first-timer eligibility check to also execute in the delta <= 0 branch:

  This preserves the existing penalty for:
  - Users who had eligible rewards last epoch but chose not to claim (eligible[prev] > 0, target == 0)
  - Users with established claim history but no position growth (target > 0, delta = 0)
