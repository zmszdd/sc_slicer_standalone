Batch Transfers Bypass KYC Verification Completely

## Vulnerability Details

The `WERC7575ShareToken` contract implements KYC requirements for all token recipients in standard ERC-20 operations:

**KYC Protected Functions:**
- `mint()` - Line 363: `if (!isKycVerified[to]) revert KycRequired();`
- `transfer()` - Line 474: `if (!isKycVerified[to]) revert KycRequired();`  
- `transferFrom()` - Line 489: `if (!isKycVerified[to]) revert KycRequired();`

However, the batch transfer functions completely bypass this critical security control:

**KYC Bypass Functions:**
- `batchTransfers()` - Line 700: **NO KYC CHECK**
- `rBatchTransfers()` - Line 1119: **NO KYC CHECK**

Both batch functions update `_balances` for creditors (recipients) without verifying their KYC status. This creates a complete bypass of the platform's regulatory compliance controls.

### Root Cause
The batch transfer functions directly manipulate the internal `_balances` mapping without calling the standard transfer functions that include KYC checks. The validator (a trusted but potentially compromised role) can send tokens to ANY address, regardless of KYC status.

### Attack Scenarios

**Scenario 1: Compromised Validator Key**
1. Attacker compromises validator private key
2. Calls `batchTransfers()` to send tokens to sanctioned addresses
3. Bypasses all KYC controls completely
4. Platform unknowingly facilitates transactions to sanctioned entities

**Scenario 2: Malicious Insider**
1. Malicious validator/insider uses `batchTransfers()`
2. Sends tokens to non-KYC'd addresses for money laundering
3. No audit trail of KYC violations
4. Platform faces regulatory action

**Scenario 3: Regulatory Compliance Failure**
1. Even legitimate batch operations can violate compliance
2. If validator mistakenly includes non-KYC'd address
3. Platform automatically violates regulatory requirements
4. No prevention mechanism exists

### Impact

**Direct Security Impact:**
- Complete bypass of KYC-based access control
- Sanctioned/blacklisted entities can receive tokens
- Money laundering vector created
- Regulatory compliance completely broken

**Platform-Level Risks:**
- Platform shutdown by regulators
- Criminal investigation for AML violations
- Loss of operating licenses
- Massive legal/financial penalties
- Reputational destruction

**Business Continuity:**
- Even if validator is trustworthy, compromised key = instant regulatory violation
- No technical safeguard against accidental or malicious KYC bypass
- Single point of failure for entire compliance framework
