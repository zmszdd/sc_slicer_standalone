LP funds can be permanently burned by swapping to address(this)

## Finding description and impact

The `Covenant.swap` function allows BASE-out transfers to any `to` address without prohibiting `to == address(this)`. When a user swaps synths (e.g., aToken) to BASE with `swapParams.to == address(Covenant)`, the function first reduces the market’s accounted base supply (`ms.baseSupply -= amount + protocolFees`) and only then executes `safeTransfer(to, amount)`. For standard ERC20 tokens, transferring to self results in no net balance change for the contract. As a consequence:

- The on-chain ERC20 balance of the contract remains the same (no tokens actually leave),
- The internal accounting (`baseSupply`) is decremented by `amount`,
- The difference becomes “orphaned” tokens in the contract that are not reflected in any market accounting nor in `protocolFeeGrowth`.

This is a griefing attack that causes immediate, direct economic damage to LPs of the affected market. Liquidity providers lose claims to the orphaned portion of base tokens because `baseSupply` is lowered as if the tokens were paid out, but the tokens never leave the contract and cannot be reclaimed (no sweep/rescue mechanism exists). The attacker does not need to profit; simply setting `to = address(this)` burns LP value by removing it from the claimable accounting while leaving funds stranded in the contract.

The same root cause pattern exists in `redeem` (BASE-out to `redeemParams.to`), so the griefing effect is reproducible via both BASE-out paths.
