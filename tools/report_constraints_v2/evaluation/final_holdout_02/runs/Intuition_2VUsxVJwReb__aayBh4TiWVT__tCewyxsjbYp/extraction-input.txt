Epoch-boundary lock inclusion backdates ve-balance into prior epoch, enabling over-claim and reclaim underflow

## Finding description and impact

### Summary
`TrustBonding` computes prior-epoch rewards using epoch-end snapshots at `epochTimestampEnd(epoch)`, while `VotingEscrow` snapshot lookup is inclusive (`<= timestamp`).
Because of this, a lock action performed exactly at epoch boundary can be counted into the previous epoch entitlement window.

The claim path then adds user rewards into `totalClaimedRewardsForEpoch[prevEpoch]` without an epoch-cap guard, allowing `totalClaimedRewardsForEpoch(epoch)` to exceed epoch emissions.

When reclaim logic computes unclaimed as `epochRewards - claimedRewards`, epochs with over-claimed totals underflow and revert.

### Root cause details

1. Inclusive prior-epoch balance reads:
- [`totalBondedBalanceAtEpochEnd` / `userBondedBalanceAtEpochEnd`](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/protocol/emissions/TrustBonding.sol#L194-L213)

2. Eligibility uses those values:
- [`_userEligibleRewardsForEpoch`](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/protocol/emissions/TrustBonding.sol#L475-L491)

3. No epoch-cap in claim aggregate accounting:
- [`claimRewards` aggregate increment](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/protocol/emissions/TrustBonding.sol#L348-L387)

4. Reclaim underflow point:
- [`getUnclaimedRewardsForEpoch` subtraction](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/protocol/emissions/TrustBonding.sol#L320-L340)

5. Inclusive timestamp lookup in ve snapshots:
- [`_find_timestamp_epoch`](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/external/curve/VotingEscrow.sol#L544-L576)
- [`_find_user_timestamp_epoch` + `_balanceOf`](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/external/curve/VotingEscrow.sol#L590-L638)

### Impact
A boundary-time injector can claim prior-epoch rewards despite not being a genuine prior-epoch participant, causing over-distribution and reclaim failures.

Observed PoC outputs:
- `epoch1_emissions = 1000000000000000000000`
- `first_claim = 1000000000000000000000`
- `second_claim = 999666777562686266743`
- `total_claimed = 1999666777562686266743`
- `excess_bps = 9996`

Boundary sensitivity:
- `offset 0` gives positive retroactive claimable.
- `offset +1s` gives `0` retroactive claimable.

Severity rationale:
- Impact is material once triggered (over-claim + reclaim DoS on affected epoch).
- Exploitability is constrained by exact boundary timing (`offset == 0`), so Medium is appropriate.
