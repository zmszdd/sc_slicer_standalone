Incorrect bitwise logic causes false ZeroCostTrade reverts, enabling DoS via valid disjoint-valued trades

## Finding description and impact

The CLOB contract contains a flawed check intended to catch zero-cost trades, but it uses a bitwise AND operation to determine whether either token amount is zero:
This condition is incorrect and overly aggressive: a & b == 0 returns true even when both a and b are non-zero, as long as they have disjoint binary representations (e.g., a=2^60, b=2^61).

This causes legitimate trades to revert with a ZeroCostTrade() error. Attackers can leverage this to strategically place orders with values that cause matching attempts to fail, leading to:
- Denial-of-Service (DoS) on matching logic
- Inability to take certain valid limit orders
- Market liveness failures in edge cases

This is especially dangerous for CLOB designs where tick size or pricing makes disjoint binary values likely (e.g., powers-of-two price increments).
