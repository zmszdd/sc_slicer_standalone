`netStaked` is incorrectly calculated in `stake` function.

## Finding description and impact

`stakingLimit` is responsible for limiting the total staked amount in the system, which is a well known mechanism. The issue is that, performed calculations in `stakingLimit`, overestimate the total `netStaked` `HYPE` in the protocol, because it does not consider `totalSlashing`.


We can see that `netStaked` is calculated as `(totalStaked + rewardsAmount - totalClaimed)`.

- `totalStaked` represents total amount ever staked in the protocol
- `totalClaimed` represents total amount ever claimed from the protocol
- `rewardsAmount` represents total amount of rewards ever earned in the protocol

There is no `slashedAmount` which represents total amount ever slashed in the protocol. Total slashing affects staking limit because it "removes" `HYPE` from the protocol making space for new deposits. However it is not included in the calculations, which leads to overestimation of the `netStaked`, which can prevent new deposits. New deposits allow earning new rewards, which is essential for the protocol, that's why the `stakingLimit` check is very important.

Assume that `stakingLimit` is 500:

- totalStaked is 400
- totalClaimed is 100
- totalRewards is 200

Now the stakingLimit is achieved, because `400 + 200 - 100 = 500`

If we consider that totalSlashed is 50 the `stakingLimit` shows that there is no space for new deposits, however the `REAL` HYPE amount in the protocol is equal to `450`, which allows depositing additional `50` HYPE.

`netStaked` is incorrectly calculated in the `stake` function, overestimating the real total `HYPE` amount in the system, preventing potential new deposits.
