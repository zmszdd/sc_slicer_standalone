Invalid reverts in process limit order functions, due to bitwise disjointness in the variables.

## Finding description and impact
In CLOB.sol the functions [_processLimitBidOrder](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L503) and [_processLimitAskOrder](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L544) are used to process buy and sell limit orders, respectively, these functions execute the order to return the `quoteTokenAmount` and `baseTokenAmount`.These amounts represent the amounts sent in or received, depending on the kind of order.
These function have a check meant to ensure that these values (`baseTokenAmountReceived` and `quoteTokenAmountSent`) are either both equal (or zero) or if one is of them is greater than zero,then the other can never be zero.
The `issue` here is based on ` bitwise disjointness`. 
These functions use the bitwise AND operator. The AND operation under the hood simply compares each bit of two numbers, bit-by-bit, and returns 1 only if `both` bits are 1, or zero otherwise.
Bitwise disjointness results from the fact that two numbers A and B will produce A & B == 0 if and only if they have no overlapping 1 bits.
Therefore, in a situation where the resultant `baseTokenAmountReceived` and `quoteTokenAmountSent` are  bitwise disjointed values, that is in each value the bits are in such a way that there is `no` position in which there is 1 in both values at the same time. 
There are lots of numbers that can occur during conversion, in which their bits align in such a way that their AND will give zero, despite these values being perfectly valid, resulting in wrong reverts of the limit order
Since the `quotetoken` and `basetoken` may be of different decimals in the order book, the conversion can happen at any price provided by the makers or takers. 

Any limit order being placed which gets filled partially, which results in `baseTokenAmountReceived` and `quoteTokenAmountSent` that are bitwise disjoint values, although perfectly normal, will revert due to their AND returning zero.
