Minimum Order Amount Can Exceed Lot Size - Order Amendment Failure

## Summary

The `setMinLimitOrderAmountInBase()` function lacks validation to ensure the minimum order amount doesn't exceed the lot size, which can create orders that pass minimum size checks but fail lot size validation during amendments, causing perpetual revert loops.

## Finding Description

This vulnerability exists in the market configuration system where `minLimitOrderAmountInBase` and `lotSizeInBase` are treated as independent parameters without cross-validation. This breaks the system's order lifecycle guarantee by creating impossible-to-amend orders after partial fills.

The issue manifests through the following sequence:
1. An operator sets `minLimitOrderAmountInBase` to a value larger than `lotSizeInBase` (e.g., min=100, lot=50)
2. A large order gets partially filled, leaving a remainder that meets the minimum size requirement but isn't aligned to lot size boundaries
3. When the system attempts to amend the remaining order, it passes the minimum size check but fails the lot size validation
4. The amendment operation reverts, leaving the order in an unusable state

The validation logic in `setMinLimitOrderAmountInBase` only checks against a global minimum but doesn't validate against the current lot size.

## Impact Explanation

This is a **Medium** severity issue because:
- It can permanently break the order lifecycle for legitimate large orders
- Orders become stuck in states where they cannot be amended or completed
- It affects order book liquidity by preventing proper order management
- While it doesn't directly cause fund loss, it can lock liquidity in unusable states

## Likelihood Explanation

The likelihood is **Medium** because:
- It requires specific configuration where minimum order amount exceeds lot size
- Market operators may inadvertently create this configuration during routine parameter adjustments
- The issue only manifests during partial fills of orders, which is a common trading scenario
- There are no warnings or validations preventing this misconfiguration
