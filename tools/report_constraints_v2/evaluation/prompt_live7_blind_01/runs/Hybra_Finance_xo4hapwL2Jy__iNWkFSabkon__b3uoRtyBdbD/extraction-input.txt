Unclaimed Bribes Permanently Lost When Merging veNFTs

## Finding description and impact

When users merge veNFTs using *VotingEscrow.merge()*, the source NFT is permanently burned without claiming or migrating accumulated bribes. This results in permanent loss of user funds because:

The source NFT is burned and ownerOf() returns address(0)
Users cannot claim bribes for burned tokens due to access control
Even if access control was bypassed, bribes would be sent to address(0) and burned

### Root Cause Analysis
### 1: VotingEscrow.merge() Burns Source Without Claiming Bribes
File: ve33/contracts/VotingEscrow.sol 
After _burn() is called:

Result: ownerOf(_tokenId) now returns address(0), making the NFT permanently inaccessible.

### 2: VoterV3._reset() Does NOT Claim Bribes
File: ve33/contracts/VoterV3.sol 
Users must ensure !voted[_from] before merging. They do this by calling reset():
Result: After reset(), voting weight is removed but unclaimed bribes still exist in the Bribe contracts, tied to the tokenId.

### 3: GaugeManager.claimBribes() Fails for Burned Tokens
File: ve33/contracts/GaugeManager.sol 

### Why the check fails:

 VotingEscrow.sol - _isApprovedOrOwner()

## IMPACT
Users  lose unclaimed bribes when merging veNFTs.
Estimated loss ranges from $0 to $5,000+ per user, depending on accumulated rewards.
