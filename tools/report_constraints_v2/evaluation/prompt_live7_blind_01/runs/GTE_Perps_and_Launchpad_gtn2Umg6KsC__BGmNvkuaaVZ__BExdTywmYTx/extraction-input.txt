Users Can Lose Tokens Through Dual Token Input in Swap Function Leading to Silent Fund Loss and Fee Manipulation

## Finding description and impact

The `swap()` function in the GTELaunchpadV2Pair contract contains a critical vulnerability that allows users to inadvertently lose tokens by sending both token0 and token1 simultaneously. The root cause lies in the flawed input amount calculation logic:

When a user sends both tokens to the contract before calling swap, the calculation can result in one amountIn being zero while the other remains positive. The revert condition only triggers when both amounts are zero, allowing the transaction to proceed with one token being processed normally while the other is effectively lost.

### Impact

Silent Token Loss: Users can lose significant amounts of tokens without receiving any value in return, as the "lost" tokens remain in the contract but are not accounted for in reserves or swap calculations.
