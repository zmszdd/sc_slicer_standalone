Missing Access Control on `rebalanceFunds()` Allows Unauthorized Vault Rebalancing and DoS Attacks

## Finding description and impact

The `rebalanceFunds()` function in `FastAccessVault` lacks access control, allowing any address to trigger vault
 rebalancing operations. This enables attackers to front-run legitimate rebalancing calls, manipulate fund 
 transfers to the custodian, and spam the function to grief the system by flooding event logs and wasting gas.
  The function performs critical state changes including token transfers and event emissions that trigger 
  off-chain custodian actions, making unrestricted access a significant security risk.


The `FastAccessVault` contract maintains a liquidity buffer for instant iTRY redemptions. The `rebalanceFunds()` 
function is responsible for maintaining optimal buffer levels by either requesting top-ups from the custodian 
(when underfunded) or transferring excess funds back to the custodian (when overfunded).



Unlike other critical functions in the contract that use access control modifiers
 (`onlyOwner` for configuration functions, `onlyIssuer` for `processTransfer()`), the `rebalanceFunds()`
  function has no access restrictions:


**Why This Matters:**

1. **State-Changing Operations**: The function performs actual token transfers (line 176) when the vault is overfunded, moving funds to the custodian address.

2. **Event-Driven Architecture**: The function emits events that trigger off-chain custodian actions. The `TopUpRequestedFromCustodian` event signals the custodian to deposit funds, while `ExcessFundsTransferredToCustodian` confirms transfers.

3. **Dynamic State Dependencies**: The function reads live on-chain state (`getCollateralUnderCustody()`) that can change between calls, making timing critical.

4. **No Rate Limiting**: There are no mechanisms to prevent repeated calls, allowing unlimited spam.

## Impact

Attackers can front-run legitimate rebalancing operations to control when excess DLF tokens are transferred 
to the custodian, disrupting the FastAccessVault's buffer management and causing the custodian's off-chain event 
monitoring system to miss legitimate rebalancing signals,
 while unlimited spam calls flood `TopUpRequestedFromCustodian` and `ExcessFundsTransferredToCustodian` events, 
 creating a denial-of-service vector against the custodian's infrastructure.
