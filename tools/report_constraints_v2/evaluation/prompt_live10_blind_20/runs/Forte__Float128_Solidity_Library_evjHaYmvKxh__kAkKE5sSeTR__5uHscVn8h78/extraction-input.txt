calculating logs of negative numbers without reverting

## Finding description and impact


The `Ln` library does not properly account for the sign bit (`MANTISSA_SIGN_MASK`) when processing inputs. Specifically, the masks used to extract the mantissa and exponent (e.g., `MANTISSA_MASK | MANTISSA_L_FLAG_MASK`) do not include the sign bit, leading to incorrect handling of negative values. This allows users to pass negative numbers to the `ln()` function, which mathematically should revert since the logarithm of a negative number is undefined. Instead, the function silently processes the input, returning an invalid result.

### Root Cause
- The `ln()` function does not check if the input's sign bit (`MANTISSA_SIGN_MASK`) is set. This omission allows negative values to bypass validation.
- Masks used during bitwise operations exclude the sign bit, leading to incorrect assumptions about the input's positivity.

### Impact
- **Incorrect Calculations**: The function returns invalid results for negative inputs,the natural log function is only defined for positive real numbers. Allowing negative inputs breaks mathematical correctness.
