Minimum Reward Check Uses Gross Amount, Allowing Campaigns with Net Below Minimum

## Finding description and impact

The `_createCampaign()` function validates the minimum reward requirement against the gross `amount` before fee deduction, but stores the net `realAmount` after fees. This allows campaigns where the effective reward rate falls below the intended minimum.

**Impact:** Campaign creators can create campaigns that pass validation with gross amounts just above minimum, but deliver rewards below minimum after fees. This undermines the minimum reward threshold designed to prevent dust campaigns and wasted gas for claimers.

## Vulnerability details

In `DistributionCreator.sol`:


When fees are deducted, the actual stored `realAmount` can be significantly below what passed validation. With a 10% fee, a campaign passing with 101 tokens/hour gross actually delivers only 91 tokens/hour.

**Root cause:** The check at L544 uses `amount` (gross), but `realAmount` (net) is what's actually distributed.
