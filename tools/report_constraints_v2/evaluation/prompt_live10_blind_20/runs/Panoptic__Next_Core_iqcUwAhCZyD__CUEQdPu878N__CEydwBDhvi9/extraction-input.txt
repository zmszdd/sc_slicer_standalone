Permissionless BuilderWallet.init allows attacker to seize admin and sweep builder fee tokens

## Vulnerability details

### Finding description

While analyzing `contracts/RiskEngine.sol`, I observed that `BuilderWallet` uses an external `init()` function to set the privileged `builderAdmin`, but `init()` is **permissionless** and **re-initializable**:


The same wallet exposes a `sweep(token, to)` function that transfers the wallet’s entire ERC20 balance to an arbitrary address, gated solely by `builderAdmin`:


Because `init()` has **no access control** and **no one-time initialization guard**, any attacker can overwrite `builderAdmin` at any time and immediately call `sweep()` to drain any ERC20 held by the wallet.

### Why this matters here :

`RiskEngine` computes a builder fee recipient derived from a **builder wallet address** (builderCode → `_computeBuilderWallet(builderCode)` → fee recipient). Builder wallets are therefore intended to custody value (e.g., CollateralTracker share tokens / builder-related ERC20 balances). Once a builder wallet accumulates any ERC20 balance, an attacker can steal it with two calls:

1) `BuilderWallet.init(attacker)`  
2) `BuilderWallet.sweep(token, attacker)`

### Impact

- **Direct theft** of any ERC20 held by builder wallets (including CollateralTracker share tokens).
- **No privileges required**; takeover is a single permissionless call.
- Any deployed/funded builder wallet can be drained.
