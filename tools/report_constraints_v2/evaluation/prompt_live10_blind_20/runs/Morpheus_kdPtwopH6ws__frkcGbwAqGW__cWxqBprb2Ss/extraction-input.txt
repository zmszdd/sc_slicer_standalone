Integer Underflow in Morpheus distributeRewards Function

# Finding description and impact

Root Cause: The vulnerability exists in the yield calculation logic within the distributeRewards() function in Distributor.sol (approximately line 390). The contract performs an unchecked arithmetic subtraction without protecting against underflow:


When balance_ is less than depositPool.lastUnderlyingBalance, this calculation triggers an integer underflow. Since Solidity 0.8+ has built-in overflow protection, the transaction automatically reverts with panic code 0x11.

## Impact

* Complete Protocol DOS: The vulnerability causes total failure of the reward distribution system, affecting all users regardless of their permissions or stake amounts.

* Persistent Failure State: Once triggered, the condition persists indefinitely. Every subsequent call to distributeRewards() will fail until manual intervention occurs.

* Natural Trigger Scenarios: The underflow can occur through common DeFi mechanisms including:

* AAVE slashing events where aTokens lose value due to protocol penalties

* Token fees charged on transfers or holdings

* Deflationary token mechanics that reduce supply

* Liquidation events that reduce held balances

* Protocol upgrades affecting token balances
