Attackers can DoS the `ShareTokenUpgradeable::unregisterVault` by front running and directly transferring asset in the vault

## Finding description
When unregistering a vault there are some checks made in the function before the function can finish executing- one of those checks is that the transaction will rvert if the vault has any balance i.e `balanceOf > 0`.

A malicious user can exploit this by front running the owner's tx of `unregisterVault` by directly transferring dust amount of asset to the vault which will make the balance of the contract non zero resulting in DoS

## Impact
Denial of service of core functionality of the protocol. If by any reason the owner wants to remove the vault, he wont be able to do so
