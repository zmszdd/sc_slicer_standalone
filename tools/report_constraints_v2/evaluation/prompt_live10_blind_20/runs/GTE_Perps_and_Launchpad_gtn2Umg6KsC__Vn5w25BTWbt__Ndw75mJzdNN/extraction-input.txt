Attacker can front-run pair creation to disable rewards accrual for launch token stakers

## Summary

The `GTELaunchpadV2PairFactory` allows anyone to create pairs for any token combination. When a pair is created by an address other than the launchpad contract, the pair is initialized with `launchpadLp` and `launchpadFeeDistributor` set to `address(0)`, which disables rewards accrual. This creates a vulnerability where an attacker can front-run the launchpad's pair creation for launch tokens, permanently disabling rewards for stakers.

## Finding Impact

**Impact: High**

The impact is assessed as high for the following reasons:

1. Stakers of launch tokens will permanently lose their rewards as the pair will never accrue fees for distribution.
2. There is no recovery mechanism to re-enable rewards accrual for affected pairs.
3. This can affect all launch tokens, not just a single instance.
4. The economic impact is significant as rewards from swap fees are a core incentive for stakers in the protocol.
5. It indirectly affects token launchers (projects partnering with GTE) as their token's staking rewards mechanism is broken.

## Finding Likelihood

**Likelihood: High**

The likelihood is assessed as high for the following reasons:

1. The attack requires minimal resources - only the gas fee to pre-deploy the target pair.
2. The attacker can predict the launch token's address in advance since it's created using the `new` operator with predictable nonce.
3. The attack can be performed before a token is even launched or during its bonding period.
4. There are no protective measures in place to prevent this attack.
5. The attack doesn't require special permissions or complex technical knowledge beyond understanding the contract's mechanics.

## Finding Description

The vulnerability exists in the interaction between `Launchpad` and `GTELaunchpadV2PairFactory`. When a token graduates from the bonding curve, the launchpad attempts to create a trading pair for it. However, anyone can front-run this process by creating the pair first, which will disable rewards accrual.

### Written Proof of Concept

1. An attacker monitors the launchpad for new token launches or predicts future launch token addresses using the launchpad's nonce.
2. Before a token graduates from its bonding phase, the attacker calls `GTELaunchpadV2PairFactory::createPair()` to create a pair for the launch token and quote token.
3. Since the attacker is not the launchpad contract, the pair is initialized with `launchpadLp = address(0)` and `launchpadFeeDistributor = address(0)`.
4. When the token graduates and the launchpad tries to create a pair in `_createPairAndSwapRemaining()`, the call to `createPair()` fails with "UniswapV2: PAIR_EXISTS".
5. The launchpad falls back to using the existing pair created by the attacker.
6. All swaps through this pair will have `launchpadFee0 = 0` and `launchpadFee1 = 0` because `launchpadFeeDistributor == address(0)`.
7. Stakers receive no rewards from swap fees, permanently losing their expected earnings.
