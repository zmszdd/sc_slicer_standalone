injectAndCall Can Be Called Directly, Acting on Router Balance Instead of Wallet

## Finding description and impact

The `injectAndCall` function is intended to inject a user wallet’s balance into a target contract call only in a delegatecall context, as documented in the `ITrailsRouter::injectAndCall`. its comments (`/// @notice Injects balance and calls target (for delegatecall context)`). This design ensures that the function operates on the caller’s wallet balances, not the router contract’s storage.

**Root Cause:**  
The root cause of the issue is that `injectAndCall` lacks a restriction to delegatecall-only execution `onlyDelegatecall`. As a result, anyone can call this function directly on the router contract. When called this way:

- The contract itself becomes the caller, so `_getSelfBalance(token)` reads the router’s balance instead of the intended user wallet’s balance.
- Arbitrary target calls may be executed with injected balances from the router instead of the wallet.
- This violates the intended security model, as the router’s funds can be misused.

**Impact:**  

- **Direct balance manipulation:** Attackers can invoke `injectAndCall` directly and potentially drain ETH or ERC20 tokens from the router.  
- **Loss of intended wallet isolation:** User wallet balances remain untouched, breaking the expected behavior.
