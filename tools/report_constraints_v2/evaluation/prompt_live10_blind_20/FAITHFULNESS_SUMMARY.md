# P/I/V 报告忠实度复核小结

## 本次标准调整

本次只判断已生成公式是否忠于漏洞报告。评分不再因影响覆盖清单不完整、未形式化项或求解器状态而扣分。缺少公式的 P/I/V 标为 `not_evaluable`。此前的 `BLIND_REVIEW.json` 与 `REPORT.md` 按覆盖和忠实度混合标准形成，作为历史记录保留；本结果另存于 `FAITHFULNESS_REVIEW.json`。

复核脚本为 `faithfulness_review.py`，全局标准已写入 `evaluation/README.md`。

## 20 例复核结果

- 整体：6 例 faithful，9 例 weakened，5 例 not_evaluable；本轮没有评为 unfaithful。
- 共评 56 个 claim。每个 P/I/V 角色中有 23 个因没有公式而无法评估。
- 有公式的角色评分：P 为 pass 29、partial 4；I 为 pass 26、partial 7；V 为 pass 27、partial 6。

这些结果只说明可评公式与报告的语义一致程度，不衡量系统有没有覆盖所有报告影响。

## 发现的问题

9 个 weakened 案例中，复核指出的主要问题是：

- **因果方向或违反关系改变**：例如把“预测地址不匹配导致调用回滚”表达成地址相等，或将安全性质缩窄到特定条件下才成立。
- **必要条件遗漏或凭空增加**：例如省略直接调用上下文、把报告中的可能触发机制加入 P 作为必需条件，或在 I 中增加报告没有要求的合取条件。
- **影响限定被弱化**：例如省略报告中的 `0 shares`、100% 范围或明确数值，使表达变成一般性条件。

改动只调整忠实度评分口径与复核脚本，没有改动阶段二的生成逻辑或形式化门槛。本轮盲评仍使用与生成相同的模型家族，不是独立人工金标准；结论应视为问题定位结果。
