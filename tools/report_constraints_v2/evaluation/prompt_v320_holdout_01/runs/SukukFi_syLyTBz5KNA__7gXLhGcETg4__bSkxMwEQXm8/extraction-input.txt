Vault Unregistration with Invested Assets Locks User Funds

## Finding description and impact

Missing validation checks in `ShareTokenUpgradeable.unregisterVault()` will cause complete loss of user fund access as the contract owner will unregister vaults while assets are invested in external investment vaults, leaving users unable to redeem their shares.

## Finding Description

In `src/ShareTokenUpgradeable.sol`, the `unregisterVault()` function performs insufficient validation before unregistering a vault:


This check only verifies that the vault's **physical token balance** is zero, but fails to check:
1. Outstanding user shares representing claims on invested assets
2. Assets invested in the investment vault via `investAssets()` (tracked by `getInvestedAssets()`)
3. Investment vault positions held by the ShareToken contract

When assets are invested via `investAssets()`, they are transferred to an investment vault, causing the main vault's balance to become zero. The function `totalAssets()` also returns zero by design (excludes invested assets to prevent double-counting). This allows unregistration to succeed even though:
- Users hold shares representing claims on the invested assets
- The ShareToken contract tracks invested assets via `getInvestedAssets()`
- Assets physically exist in the investment vault
