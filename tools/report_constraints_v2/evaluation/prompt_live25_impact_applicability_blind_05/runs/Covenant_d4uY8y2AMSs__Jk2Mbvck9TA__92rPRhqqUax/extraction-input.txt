## Finding description and impact

### Root Cause

The protocol uses an Exponential Time-Weighted Average Price (ETWAP) mechanism to limit how fast users can redeem tokens. The redemption cap is calculated as:


The vulnerability exists because ETWAP updates **on every transaction** based on elapsed time since the last transaction:


Users can force ETWAP updates by initiating transactions. Each update moves ETWAP closer to the current (smaller) market size, which unlocks additional redemption capacity.

### Impact

- Creates systematic unfair advantage for users exploiting the issue
- Regular users making single redemptions: ~30-40% exit rate per hour
- Users exploiting the issue (redemptions every 5 minutes): **71% exit rate per hour**
- Speed advantage: **2.8x faster exit** than regular users
- Accelerates market collapse instead of preventing it

**Real-World Example:**
In a $10M market during crisis:
- Regular user: Exits with ~$3.5M in first hour (35%)
- User exploiting the issue: Exits with **$7.1M in first hour (71%)**
- **Advantage: $3.6M more extracted by exploiting the bypass**

### Why This is Not Intended Behavior

1. **Code documentation explicitly states the limit:** "limits amount that can be burned in ETWAP_MIN_HALF_LIFE minutes"
2. **Calculation shows ~50% per hour maximum:** Based on 25% every 30 minutes with half-life decay
3. **Actual results exceed this by 42%:** 71% achieved vs 50% intended
4. **The mechanism's purpose is defeated:** Designed to prevent fast exits during bank runs, but allows 2.8x faster exits through timing games
