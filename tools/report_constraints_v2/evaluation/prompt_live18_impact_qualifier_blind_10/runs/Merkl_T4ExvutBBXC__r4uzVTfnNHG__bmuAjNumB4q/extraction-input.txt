Distributor._claim silently ignores callback failures, causing stuck funds for integrating contracts

## Finding description and impact

The `Distributor` contract supports a callback mechanism via `onClaim` for recipients that are smart contracts. This is intended to allow integrating protocols (like vaults or staking contracts) to be notified when they receive rewards.

However, the `_claim` function wraps this callback in a `try/catch` block that **silently swallows any revert**:

Impact: If a recipient contract's onClaim function reverts (e.g., due to logic checks, paused state, or gas limits), the Distributor ignores the error and considers the claim successful.

1. Tokens are transferred: The safeTransfer happens before the callback.

2. Accounting fails: The recipient contract (which reverted) does not update its internal accounting to reflect the deposit.

3. Funds Stuck: The tokens end up in the recipient contract, but the contract doesn't "know" they belong to the user. The user loses access to these rewards.
