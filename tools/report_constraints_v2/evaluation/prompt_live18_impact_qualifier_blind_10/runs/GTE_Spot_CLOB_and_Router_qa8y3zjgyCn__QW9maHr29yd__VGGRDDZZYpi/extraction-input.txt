## Finding description and impact


From the above code, we can see that the removal of non‑competitive orders is only performed when the bidTree size is exactly equal to maxNumLimitsPerSide.
The bidTree size represents the number of distinct price levels on one side of the book, and maxNumLimitsPerSide is an immutable value.

Assume maxNumLimitsPerSide == 2.
We have two price levels on the bid side: 1e18 and 1e18 + 1e15.
Here, 1e18 is the worst price.
If we add 10 more orders at 1e18, these will not trigger the non‑competitive order removal logic because we still only have one distinct worst price level.

Now, if we place a new order at a new price of 1e18 + 2e15, the removal logic will be triggered, and one order from the 1e18 price level will be removed.
As a result, the book now contains three distinct price levels.
Subsequent orders will no longer trigger the removal logic because the number of price levels has already exceeded the maxNumLimitsPerSide limit (2).

From the sponsor’s comment, we can understand that the developer’s intention behind this code was to prevent the bidTree from growing without bound.
However, it is clear that this intended purpose is not achieved under the current implementation.
