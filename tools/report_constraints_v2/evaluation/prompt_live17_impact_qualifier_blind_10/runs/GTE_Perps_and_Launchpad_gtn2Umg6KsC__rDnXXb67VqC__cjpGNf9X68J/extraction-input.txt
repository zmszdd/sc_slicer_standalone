## Finding Description and Impact
When a user buys launchToken, slippage may occur.

### Assumptions
1.User1 bought launchTokens equivalent to 90% of the BONDING_SUPPLY from the launchpad.
2.User2 attempts to buy launchTokens equivalent to 20% of the BONDING_SUPPLY from the launchpad. User2 uses the quoteQuoteForBase() function in SimpleBondingCurve.sol to calculate the required amount of quoteToken and sets slippage protection accordingly.

### Description
Let's examine User2's buying process:
In the buy() function of launchpad.sol, since 90% of the launchTokens from the BONDING_SUPPLY have already been sold, the remaining 10% is allocated to User2 using the bonding curve.
Subsequently, because the total sold launchTokens have reached the BONDING_SUPPLY, the contract attempts to swap the remaining 10% and give it to User2.
Although a slippage check is performed during the swap, if slippage occurs, the function does not revert. Instead, it treats the swap as unsuccessful and returns the tokens. This results in the loss of the intended slippage protection functionality.

See _createPairAndSwapRemaining function in launchpad.sol.
### Impact
Consequently, User2 ends up receiving only 10% of the BONDING_SUPPLY (at a higher price than initially calculated) instead of the intended 20%.
A more critical issue is that since the sold launchToken amount has reached the BONDING_SUPPLY, _launches[buyData.token].active is set to false, User2 can't sell launchToken again.
Finally, slippage may occur.
