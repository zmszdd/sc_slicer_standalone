prevOrderId Not Persisted in _updateLimitPostOrder, Breaking FIFO Order Linking, effectively making Head Order unfillable

## Description
In `BookLib::_updateLimitPostOrder`, when appending a new order to an existing limit, the code correctly updates the previous tail’s `nextOrderId` and sets `order.prevOrderId = tailOrder.id` on the in-memory Order struct but ir  never writes that updated `order` back into storage. Because order lives only in memory at that point, its prevOrderId is never persisted. As a result, every newly added order ends up with a zero prevOrderId , breaking the doubly-linked list succession.
