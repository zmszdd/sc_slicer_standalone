Late Staking Reward Exploit in `TrustBonding.sol`

## Summary

In the `TrustBonding.sol` contract, users can claim their rewards for Bonding TRUST tokens. These rewards can be claimed on the next epoch based on the utilization rate of the system and the users. For the first epoch , the utilization ratio is set to the maximum for all the users 
and after that, it changes based on their personal utilization ratio.

But there is a critical flaw when calculating the rewards for the user. The vulnerability exists in the `TrustBonding` contract's reward calculation logic that allows users to bond TRUST tokens at the very end of an epoch and receive the same rewards as users who bonded for the entire epoch. This undermines the fairness of the reward distribution and can be exploited for disproportionate gains.

## Description
The contract calculates user rewards in the `claimRewards()`. This function uses the internal `_userEligibleRewardsForEpoch()` function to calculate the rewards eligible for the user in the previous epoch. The flaw is in the where the user balance is calculated using `userBondedBalanceAtEpochEnd()` which in turn uses `_balanceOf(account, _epochTimestampEnd(epoch))` which does not account for the duration a user was bonded during the epoch.

## Exploit Scenario

The exploit shown below is clearly demonstrated in the Poc given below.

1. Alice bonds at the start of epoch N.
2. Charlie waits until the last second of epoch N, then bonds the same amount.
3. Both claim rewards for epoch N in epoch N+1.
4. Both receive the same rewards, despite Charlie being bonded for only 1 second.


## Impact
- Users can game the system by bonding at the last moment(at the very last second of the epoch), receiving full rewards for minimal participation Basically stealing rewards from the other users

- This can lead to unfair reward distribution and undermine the protocol's intended incentives.
