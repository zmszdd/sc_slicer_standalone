Using  '&'  to check for zero Cost trades may deny orders that should succeed.

## Finding description and impact
 When posting orders that are not post-only, the contract ensures that there are no zero cost trade where a user receives or sends an amount of money but sends or receives zero amount respectively.

[Link to Code](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L503-L505)

This is enforced in the above check, where the amounts(received/sent) are not the same, the contract uses bitwise operator '&' to ensure that one of the values is not zero, but this is not true that operator '&' only returns zero when one of the values is zero, it can return  zero with some values that have been properly calculated and due to this check the contract will revert dosing a user's order that should succeed.


### Impact
Denial of services where orders that should succeed are reverted.
