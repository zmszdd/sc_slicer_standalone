## Finding description and impact

Merkl allows creators to override campaign parameters, with some limitations: creators cannot change the start timestamp of the campaign if it already started, and they cannot set the end timestamp to a time in the past.
But when checking these constraints, the function `overrideCampaign` uses the initial campaign(`_campaign` which comes from `_campaignLookup[_campaignId]`) as a reference point for the start time, instead of the most recent compaign(`campaignOverrides[_campaignId]`).
So in the case in which a creator postpones a campaign, and then, for whatever reason, they decide to postpone it again, they are not allowed to do so if they do it after what was the initial start timestamp.

## Vulnerable scenarios

1. creator sets up a campaign with start time x
creator overrides the campaign and sets its start time to y
creator tries to override the campaign at a time after x but before y, but can't, even though they should

2. creator sets up a campaign with start time x
creator overrides the campaign and sets its start time to y
creator tries to override the campaign and set its duration to a time that if added to y is in the future, but added to x is in the past, but can't, even though they should

## Impact

Users of Merkl are unable to access some Merkl functionalities. The inability to postpone or cut the duration of a campaign could make Merkl users unsatisfied with the protocol, and it can cause problems for them because the campaign may not proceed in the ways they had intended it to go.
