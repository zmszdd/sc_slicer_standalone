Broken Linked List Pointers Allow Mismatched Orders to Drain User Funds

## Finding description and impact

If an order is posted and another order already exists at the same price, the prevId and nextId fields are not updated, which completely breaks the linked list.
In the CLOB contract, when a user submits a limit order, it is added to the book by calling BookLib.addOrderToBook.

This function creates the order and then updates the price level (limit) as follows:

If an order already exists at that price, it updates tailOrder.
It also sets the prevOrderId and nextOrderId of the new order.

The issue is that the order stored in storage is never updated—the changes occur only in memory, as indicated by the function signature.

As a result, the linked list becomes invalid after the call: the order’s prevOrderId and nextOrderId both remain zero. This is dangerous because it can create a discrepancy between the price applied and the actual price of an order when the CLOB matches orders, as shown in the PoC.
