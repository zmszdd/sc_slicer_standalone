The allocated voting power may differ from the expected amount

## Finding description and impact

The allocation of voting power for each pool is determined by the user’s input weight array.
However, if a pool is inactive, the loop skips it during processing. This can cause the actual allocation to differ significantly from the user’s expectations.

For example, suppose there are three pools: `pool1`, `pool2`, and `pool3`.
The owner intends to assign weights of `[10, 30, 60]`, corresponding to 10%, 30%, and 60% of the total voting power.

If `pool2`’s gauge is killed before the owner invokes `vote`, the system recalculates the weights as `[10, 60]`.
This changes the proportions to `10/70 ≈ 15%` and `60/70 ≈ 85%`, which deviates significantly from the owner’s intended distribution.

Moreover, the total base of the weights is not validated.
If the user provides a very small total weight base, the resulting allocation error can become significantly larger.
