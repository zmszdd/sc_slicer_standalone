Epoch-Boundary Utilization Gaming Enables Reward Extraction

### Finding Description and Impact

Personal utilization for rewards is derived from epoch-to-epoch utilization deltas without time weighting or minimum holding duration. As a result, utilization added immediately before epoch end is treated as if it represented meaningful epoch participation.

This how the vulneralbility arises :

1. Attacker performs a boundary deposit right before epoch end `e`.
   - `deposit()` adds utilization using full `msg.value` before reward calculations:

2. Utilization is written directly into current epoch buckets.

3. At epoch transition, rollover preserves prior epoch exposure snapshots and supports boundary sensitivity.

4. In epoch `e+1`, claim logic always targets `prevEpoch = e`.

5. Personal utilization ratio is driven by epoch delta, not hold time.

6. `userUtilizationTarget` is last epoch claimed rewards, allowing large one-epoch jumps to max ratio.

7. Attacker exits shortly after claim; removal impacts current epoch (`e+1`) accounting, not already-claimed epoch `e`.

8. Net effect:
   - Epoch `e` claim remains boosted from boundary deposit.
   - Round-trip cost is mostly fees/slippage paid on unwind in epoch `e+1`.
   - In one run, reward differential already exceeds realized unwind cost.

Attack path :

1. Attacker keeps baseline stake comparable to passive users.
2. At `epochTimestampEnd(e) - 1`, attacker makes a temporary deposit to increase personal utilization for epoch `e`.
3. In epoch `e+1`, attacker calls `claimRewards` and receives boosted rewards for epoch `e`.
4. Attacker exits the temporary position shortly after boundary.
5. PoC demonstrates one-run impact using this boundary method.

Timeline example :

1. End of epoch `e`: attacker deposits to inflate `personalUtilization[user][e]`.
2. Start of epoch `e+1`: attacker calls `claimRewards`, which computes rewards for epoch `e`.
3. Same epoch `e+1`: attacker redeems temporary position and realizes bounded trading/fee loss.
4. Result: reward delta from boosted ratio can exceed realized unwind loss

The impact because of this issue are inflated reward capture by boundary-timing users, dilution of honest users who do not run the timing strategy and extraction pressure on emissions distribution from boundary-timing behavior.
