External FastAccessVault::rebalanceFunds Allows Front-Running to DoS User Redemptions

## Description
The `FastAccessVault` contract has a critical race condition vulnerability where anyone can call `rebalanceFunds()` to drain excess funds immediately before a user's redemption, causing the redemption to fail and defeating the vault's purpose of providing instant redemptions.
The `rebalanceFunds()` function is external with no access control, allowing anyone to trigger it.  When called, it immediately transfers excess funds above the target buffer to the custodian. 

The `IFastAccessVault` contract also lacks the onlyOwner check making this attack possible
An attacker can monitor the mempool for redemption transactions and front-run them by calling `rebalanceFunds()` to drain the vault's buffer. When the user's redemption transaction executes, `processTransfer()` will revert with `InsufficientBufferBalance` because the vault no longer has sufficient funds 

## Impact
* Undermines the core purpose of `FastAccessVault`: "instant iTRY redemptions without custodian delays"
* Creates a denial-of-service condition for legitimate users
* An attacker can consistently block large withdrawals at little cost, disrupting protocol operations.
* Can be exploited repeatedly to disrupt protocol operations
