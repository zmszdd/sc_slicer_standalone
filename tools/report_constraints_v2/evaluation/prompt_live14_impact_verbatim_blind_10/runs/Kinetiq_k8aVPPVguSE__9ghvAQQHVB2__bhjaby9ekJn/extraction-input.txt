Deauthorized Contracts Remain Unpaused, Allowing Unintended Interactions

## Finding description and impact

## Description
The `PauserRegistry::deauthorizeContract` function removes a contract from the list of authorized contracts but fails to automatically pause it. This oversight allows deauthorized contracts to remain fully operational, even though they should no longer be accessible.

While the system includes a separate pause function, it can only be called on authorized contracts. This creates a logical gap: once a contract is deauthorized, it cannot be paused, leaving the protocol exposed to unintended interactions.
Deauthorization of a contract should also pause a contract 
## Impact 
- Unauthorized Access: Deauthorized contracts remain active, allowing users to interact with them despite their revoked permissions.
- Financial Risk: If a contract is deauthorized due to security concerns (e.g., a compromised StakingManager), users could still deposit funds, leading to potential losses.
  
## Example 
1.The StakingManager is initially authorized for staking operations.
2.Due to a discovered vulnerability (e.g., reward calculation flaw), it is deauthorized via deauthorizeContract.
3.However, since the contract is not automatically paused, users continue depositing funds, exposing them to exploitation
