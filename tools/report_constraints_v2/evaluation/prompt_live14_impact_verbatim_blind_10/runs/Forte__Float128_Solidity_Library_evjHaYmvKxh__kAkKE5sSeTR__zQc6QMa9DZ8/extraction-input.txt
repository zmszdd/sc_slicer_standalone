ln() incorrectly handles negative and zero inputs

## Finding description and impact

**Problem:**
The natural logarithm `ln(x)` is mathematically defined only for **positive real numbers**. For negative numbers or zero, it is undefined in the real number domain (though it has solutions in the complex domain). Standard libraries handling real numbers typically revert or return an error/NaN for non-positive inputs.

The reference Python code snippet (`ln128_prec`) in the research paper reflects this mathematical domain by including an `assert digits > 0`, explicitly requiring positive inputs.


However, the Solidity `Ln.ln` function **lacks input validation** and fails on negative or zero inputs.


**Observed Behavior & Discrepancy:**

1. **Negative Inputs:**
  
  - **Solidity:** When a negative number (e.g., `-10.0`) is provided, the assembly block in `Ln.ln` extracts the mantissa bits *without* checking the sign bit (`MANTISSA_SIGN_MASK`). The subsequent calculations proceed using the *absolute value* of the input.
  - **PoC Result:** `Ln.ln(-10.0)` returns the exact same result as `Ln.ln(+10.0)`, approximately `2.302585`. This is incorrect; `ln(-10)` is undefined for real numbers (its value in complex numbers is `~2.302 + πi`).
  - **Discrepancy:** This contradicts the mathematical domain and the `assert digits > 0` in the Python reference, which would prevent negative inputs.
2. **Zero Input:**
  
  - **Solidity:** When the input is `0`, the function does not revert. It proceeds down the main calculation path with `mantissa = 0`.
  - **PoC Result:** `Ln.ln(0)` returns a negative finite number (`Mantissa ≈ -1.878e37`, `Exponent = -33`. Roughly equal to -18781). This is incorrect as `ln(0)` is -infinity.
  - **Discrepancy:** This violates the mathematical domain and the `assert digits > 0` in the Python reference.

**Impact:**

1. **Incorrect Calculations:** The function returns mathematically incorrect and misleading results for all non-positive inputs. It gives `ln(|x|)` for negative `x` and a finite negative number for `x=0`.
2. **Masked Errors:** The failure to revert on invalid domain inputs hides critical errors, potentially leading to silent failures and unexpected behavior in protocols relying on the library.
3. **Deviation from Specification/Expectation:** The implementation deviates from standard mathematical behavior, the common expectation for logarithm functions operating on real numbers, and the explicit assertion in the provided reference implementation in the paper and python implementation.
