# 阶段二新报告预注册小测

本批 8 份 `report.json` 在当前规则与 prompt 修改完成后选定，分别来自 8 个项目；在选样时，案例 ID 不在既有评测文件或已保存运行的 provenance 中。按项目分层，在每个选定项目内对满足 exact-submission、正文长度 300–12,000 字符且未用过的案例，以固定种子哈希排序取第一份。项目层面的选择不是随机总体抽样，因此本批只能作为**前瞻性小测**，不能外推到所有漏洞报告。案例、报告 SHA、阶段二输入 SHA、提示哈希、关键实现文件哈希及无重试设置均冻结在 [manifest.json](manifest.json)。没有预填 P/I/V 标准答案。

用户明确授权后，本批八例已按冻结的 v3 输入策略和零重试设置各运行一次；结果见[首次测试报告](REPORT.md)。**4/8 要素提取、1/8 完整到 Z3，语义准确率未知。** Morpheus 的无标题修复建议被 v3 错误纳入发送文本，详见报告；现已本地修复为 v4，未继续外部调用。原始 v3 输出不可用当前默认 v4 命令重刷或替换。后续受控恢复必须另建开发批次，保留本批全部失败和成功结果。

离线验收命令不会调用模型：

```bash
PYTHONDONTWRITEBYTECODE=1 /root/.local/share/uv/tools/halmos/bin/python \
  tools/report_constraints_v2/evaluation/fresh_holdout_01/evaluate.py
```

`evaluate.py` 重新计算原报告和输入哈希，核对 prompt 哈希，并对已有结果核对来源、阶段状态和离线重放。工程指标分开报告提取、形式化、Z3 与完整重放的成功率；未运行时成功率为 `null`，不会伪装成 0% 模型失败。

语义评分必须另用独立审核记录，而不是 Z3 输出或原模型自评。每例六维：

| 维度 | 只看报告与编号证据时需要回答的问题 |
| --- | --- |
| `P_evidence` | 所有抽取的前提是否有原文支持；是否将攻击结果提前假定为前提？ |
| `P_semantics` | 必要角色、触发状态与条件是否完整且不过度扩大？ |
| `I_evidence` | “应满足”的方向和范围是否来自报告，而非通用规则猜测？ |
| `I_semantics` | 性质是否表达报告声称的核心安全边界？ |
| `V_evidence` | 直接违反行为／结果是否由报告描述支持？ |
| `V_semantics` | V 是否在同一 P 下直接使 I 为假，而非仅为下游损失？ |

每维取 `pass`、`partial`、`fail`、`unknown`、`not_evaluable`，附证据 ID 和理由。`unknown` 不强判错误；没有提取结果只能标 `not_evaluable`。评分文件若传给 `evaluate.py --ratings FILE`，需列全 8 例、评分者类型与身份、六维结果、理由，以及与该例 `status.json`、`elements.json`、`formalization.json` 相符的 SHA-256（缺文件时填 `null`）。只有人工独立审核且六维均可判定的子集才会计算严格全对比例；它也只是这 8 例的比例，不是总体准确率。模型审核只能给临时提示，不能冒充金标准。

本阶段不读取合约或执行 PoC；所谓“语义准确”仅指**对报告声称内容的提取和规则化**，不是漏洞真实性。
