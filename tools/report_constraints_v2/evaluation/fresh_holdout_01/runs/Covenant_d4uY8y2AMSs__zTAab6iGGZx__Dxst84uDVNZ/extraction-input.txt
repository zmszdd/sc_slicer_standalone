Missing L2 sequencer uptime check in ChainlinkOracle enables stale price exploitation

## Description:
The protocol will be deployed on Optimism (an L2 network), but the `ChainlinkOracle` implementation does not include a check for the L2 sequencer's uptime status. This is a critical omission because L2 sequencers can experience downtime, during which Chainlink price feeds on L2 cannot be updated with fresh prices from the mainnet. The vulnerability exists in the `_getQuote()` function in `ChainlinkOracle.sol (EulerChainlinkOracle)`:
While the code checks for price staleness via `maxStaleness`, it does not verify whether the L2 sequencer was down.
According to Chainlink's official documentation, protocols deployed on L2 networks should implement sequencer uptime checks to prevent exploitation during and immediately after sequencer downtime.
https://docs.chain.link/data-feeds/l2-sequencer-feeds

## Impact:
After sequencer restart, prices may pass staleness checks but still be outdated
Attackers can interact with the protocol using prices that don't reflect true market values
The grace period (determined by `maxStaleness`) provides a predictable exploitation window
