## P/I/V 初步语义检查

唯一完整候选 [Ekubo 生成的要素](runs/Ekubo_3FTodhsvBkM__NCCWNLzZ86f__7bsvmSWT5Sx/elements-ids.json)大体抓住“恶意代币在付款中重入、清掉输入债务、未付款取得输出”的报告主线，但[形式计划](runs/Ekubo_3FTodhsvBkM__NCCWNLzZ86f__7bsvmSWT5Sx/formal-plan.json)遗漏关键限定：

- 形式 P 只用了 3 条前提，未用恶意输入代币、池流动性、先取输出再付输入的 3 条已提取条件。
- 形式 I 实际是 `debt_input_before > 0 ⇒ debt_input_after ≠ 0`。报告要求的是**没有真实支付时**不能把债务清零并退出；合法付款后债务本来可以清零。生成公式未表示“是否付款”，因此 I 过强。
- 形式 V 仅表示债务从正数变为零，未表示“未付输入仍保留输出”这一核心违例。`P∧V∧I = UNSAT` 只能证明这组过强公式内部互斥，不能证明它忠于报告。

程序已将该例路由 `review`，理由包括未认领的未付款影响和漏用的 P，未自动放行。以上是助手对一例的**问题定位**，不是独立人工金标准，不能把 0/1 或 1/8 写成语义准确率。其余三例有要素文件但无形式化，不能评估端到端约束准确性。

## 输入边界偏差与修复

这批首次运行使用的 v3 按 Markdown 标题过滤 PoC/修复建议。Morpheus 报告把 `Recommended mitigation steps` 写成**无 Markdown 标记的普通行**，所以该行之后的一段修复建议进入了实际发送文本；这超出了本次仅发送标题、描述和影响片段的授权范围。未发现合约文件或 PoC 代码字段作为模型输入，但不能把此次 Morpheus 上传描述为完全符合数据范围。已停止额外外部调用。

本地新增 `report-json-input/4`：过滤无标题的 PoC/修复建议段落，仍保留后续独立影响段落；Morpheus 的新输入不再含该修复建议。历史 v3 解析和原运行产物保持不变、可离线重放；评测器明确标记当前代码与冻结版本的差异。修复后回归 248/248 通过。**没有拿 v4 结果替换这批 v3 首次结果。**
新增[本地输入预览工具](../../preview_report_input.py)，供后续新来源在发送前检查确切文本，不调用模型。

## 结论与后续

当前主要瓶颈首先是模型调用稳定性与合法 JSON 输出，其次是形式约束未保留报告中的“无付款”限定。下轮应另建开发批次：对超时／空响应做有上限的受控恢复，缩短或分解第二步输出，同时测试跨状态条件（如“债务清零仅当付款到账”）是否被完整表达。不能在本批事后补跑并改写 1/8 的首次完成率；语义准确率需对足够多的完整候选做独立审核后再报告。
