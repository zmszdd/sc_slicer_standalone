Initializer functions allow permissionless takeover of governance for uninitialized proxies

## Finding description and impact

When I checked the initialize function in DistributionCreator, I noticed it only uses the initializer modifier and has no access control on the caller. Distributor follows the same pattern. Both contracts are set up for use behind UUPS proxies, where the constructor with initializer runs only on the implementation, not on each proxy instance.

Because of that, every freshly deployed proxy starts with the initialized flag at zero, and the first external address to call initialize gets to set the accessControlManager (and also the distributor address and default fees in DistributionCreator). If an attacker deploys a malicious accessControlManager that always treats them as governor or guardian, they can initialize the proxy to point to this contract. From that point on, all onlyGovernor, onlyGovernorOrGuardian, and onlyUpgradeableInstance checks are effectively under attacker control, giving them full admin over DistributionCreator and Distributor.
