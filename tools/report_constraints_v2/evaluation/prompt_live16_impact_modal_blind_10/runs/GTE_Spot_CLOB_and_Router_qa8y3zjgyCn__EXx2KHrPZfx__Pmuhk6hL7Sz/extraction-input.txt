Incorrect Quote-Denominated Order Matching Results in Permanent Fund Loss

## Finding Description   
A discrepancy in order expiration handling between price checking and order matching allows expired orders to block new post-only orders, potentially disrupting market operations.

 
The CLOB implements an order book with price-time priority matching. The system maintains bid and ask orders in separate Red-Black trees, with `getBestBidPrice()` and `getBestAskPrice()` used to find the most competitive prices. For post-only orders, these functions check if the order would immediately fill against existing orders.

The issue arises because:
1. Price checking functions ([`getBestBidPrice()`](https://github.com/code-423n4/2025-07-gte-clob/blob/2783108d14010ae50f2a5f65c3a9c94e2e7845b9/contracts/clob/types/Book.sol#L427-L429)/[`getBestAskPrice()`](https://github.com/code-423n4/2025-07-gte-clob/blob/2783108d14010ae50f2a5f65c3a9c94e2e7845b9/contracts/clob/types/Book.sol#L432-L434) ) return the best price without verifying if the corresponding order is expired
2. However, the matching engine (`_matchIncomingBid()`/`_matchIncomingAsk()`) correctly skips expired orders during actual matching
3. This creates a scenario where a post-only order is rejected due to an expired order that wouldn't actually match against it
4. [`_executeBidLimitOrder()`](https://github.com/code-423n4/2025-07-gte-clob/blob/2783108d14010ae50f2a5f65c3a9c94e2e7845b9/contracts/clob/CLOB.sol#L574-L604) checks `limitOrderType == POST_ONLY` and compares `ds.getBestAskPrice()` (still *P*) to the incoming bid price. Because *P* ≤ bid price, the function reverts with `PostOnlyOrderWouldFill`.  
The highest impact occurs when:
1. An attacker places a small, soon-to-expire order at the top of the book
2. After expiration, the order remains in the price tree but is skipped during matching
3. New post-only orders at the same or better price are rejected due to the expired order still being considered in the best price check


In [Book.sol](cci:7://file:///Users/0xniloy/Desktop/c4/2025-07-gte-clob/contracts/clob/types/Book.sol:0:0-0:0), the `minimum()` and `maximum()` functions in the RedBlackTree implementation return the best prices without checking order expiration, while the matching logic in [CLOB.sol](cci:7://file:///Users/0xniloy/Desktop/c4/2025-07-gte-clob/contracts/clob/CLOB.sol:0:0-0:0) does check for expiration.



This vulnerability allows an attacker to perform a low-cost denial-of-service attack on post-only orders by placing and letting small orders expire at the top of the book, disrupting normal market operations and potentially manipulating market behavior.


## Impact Explanation  
High. The vulnerability can be exploited to disrupt normal market operations with minimal cost, potentially enabling market manipulation and preventing legitimate trading strategies from functioning as intended.
