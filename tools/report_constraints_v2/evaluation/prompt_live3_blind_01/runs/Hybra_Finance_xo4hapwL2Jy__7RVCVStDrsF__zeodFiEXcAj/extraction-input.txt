Incorrect order of operations in deposit() causes share dilution and enables theft of user funds

## Finding description

The `deposit()` function within the `GovernanceHYBR` contract is intended to allow users to deposit HYBR tokens and receive proportional gHYBR shares representing their ownership in the underlying veNFT. However, the function contains a critical logical flaw in the order of operations:

The function adds the depositor's funds to the veNFT before calculating how many shares to mint. This means when calculateShares() is called, totalAssets() returns the veNFT balance that already includes the new deposit:

This means the function's behavior systematically dilutes all depositors after the first:
Current Behavior: Shares are calculated using totalAssets() that already includes the new deposit, resulting in fewer shares minted than the depositor should receive.

Expected Behavior (based on ERC4626 standard and fair share distribution): Shares should be calculated before adding funds to the veNFT, ensuring depositors receive shares proportional to their contribution relative to the pool's value at the time of deposit.


## Root Cause

The root cause is an incorrect sequence of operations in the `deposit()` function.


## Impact

The impact of this logical error is critical and enables direct theft of user funds:
Systematic Dilution of All Subsequent Depositors:

- Every user who deposits after the first depositor receives fewer shares than they should
- The dilution compounds with each deposit, as the bug affects all subsequent users
- Users receive proportionally less ownership for their deposited amount

Weaponizable First Depositor Inflation Attack:
This bug can be exploited through a deliberate attack sequence:

1. Attacker becomes first depositor with minimal amount:
- Attacker deposits 100 wei (minimal amount)
- Receives 100 shares (1:1 ratio for first deposit)
- Total assets: 100 wei
- Total supply: 100 shares

2. Attacker inflates the veNFT balance:
- Attacker calls VotingEscrow.deposit_for(veTokenId, amount) directly
- This is a public function that allows anyone to add funds to any veNFT
- Attacker adds ~1000 HYBR directly to the veNFT
- Total assets: 1000 HYBR
- Total supply: 100 shares (unchanged - no shares minted for direct deposit)
- Share price: 10 HYBR per share

3. Victim deposits and gets severely diluted:
- Victim deposits 1000 HYBR
- Funds added to veNFT first → total assets become 2000 HYBR
- Shares calculated: (1000e18 * 100) / 2000e18 = 50 shares
- Victim receives only 50 shares instead of expected ~100 shares

4. Attacker extracts profit:
- Attacker owns 100 shares (66.67% of 150 total)
- Victim owns 50 shares (33.33% of 150 total)
- Attacker withdraws 99 shares (keeping 1 to maintain position)
- Attacker receives 1306.8 HYBR (after 1% fee)
- Attacker still owns 1 share worth 13.33 HYBR
- Total value: 1320.13 HYBR
- Attacker profit: ~320 HYBR (~32% gain)

5. Victim's loss:
- Victim's 50 shares now worth: 666.67 HYBR
- Victim invested: 1000 HYBR
- Victim loss: ~333 HYBR (~33% loss)

Operational Impact:
- Protocol cannot function fairly for multiple depositors
- Long-term holders have their positions systematically diluted
- Penalty rewards distributed unfairly (heavily favor attacker)
- Trust in the protocol is destroyed once users realize deposits are diluted

## Severity Justification

HIGH. This vulnerability:

- Enables direct, systematic theft of user funds
- Affects core protocol functionality (deposits)
- Requires no special permissions to exploit
- Can be executed by the first depositor on every pool
- Results in significant financial loss for victims (~33% in the PoC)
- Attacker can withdraw almost entire position immediately
