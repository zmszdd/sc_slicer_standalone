`FastAccessVault.rebalanceFunds()` is permissionless and enables griefing / denial-of-service on fast redemptions

## Finding description and impact

The function `FastAccessVault.rebalanceFunds()` is declared external with no access control.
Any address (including malicious bots or griefers) can call it at any time.
This allows an attacker to force-drain all excess liquidity from the on-chain `FastAccessVault` to the off-chain custodian immediately after large mints, leaving only the exact target buffer (e.g. 5%) on-chain.

Result:
All subsequent redemptions are forced onto the slow, manual, off-chain custodian path
The “fast redemption” feature that users rely on is effectively disabled until the issuer manually tops up the vault again
UX is destroyed during high-volume periods or bank runs

Even though no funds are stolen, this is a classic griefing / denial-of-service vector and violates the principle of least privilege.

## Impact
- Random EOAs should never be able to move protocol liquidity
- Attacker drains buffer exactly when liquidity is needed most
- Bot can spam `rebalanceFunds()` after every mint which kills fast redemptions
- Users expect instant redemptions suddenly wait minutes/hours
