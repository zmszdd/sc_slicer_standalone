Malicious token in distributor `addRewards` can used to drain the distributor

## Finding description and impact


The `addRewards()` function in the Distributor contract fails to validate that the `quoteAsset` parameter matches the stored `rs.quoteAsset` in the reward pool. This allows attackers to use any malicious token as the quote asset parameter.

### Vulnerable Code Location


## Attack path
* calls addRewards with a valid launch token and a malicious token 
* launch token amount = 0 and malicious token amount = millions of unit
* The token get transferred in and the pending rewards amount is increased
* this new invalid amount is used in the reward tracker this inflates the `accQuoteRewardPerShare` of the quotetoken
* when claim rewards is called, the attacker is able to drain the contract off all USDC as their share is overvalued.
