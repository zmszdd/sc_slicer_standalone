BuilderWallet.init() lacks access control, allowing anyone to become admin and steal all funds

## Finding description and impact

The `BuilderWallet.init()` function in `RiskEngine.sol` lacks any access control mechanism, enabling any external actor to:

1. **Take over admin privileges** by calling `init()` with their own address
2. **Steal all tokens** in the wallet by calling `sweep()` after becoming admin
3. **Lock out the legitimate admin** who can no longer access the funds

### Root Cause


**Missing security controls:**
- No `onlyFactory` modifier
- No `msg.sender == FACTORY` check  
- No `initialized` flag to prevent re-initialization
- No check if `builderAdmin` is already set

### Impact

This is a **critical vulnerability** that results in **direct theft of funds**. All tokens accumulated in any `BuilderWallet` (builder fees) can be stolen by an attacker with a single transaction.

**Attack Scenario:**
1. `BuilderFactory.deployBuilder()` deploys a `BuilderWallet` and calls `init(legitimateAdmin)`
2. Builder fees accumulate in the wallet over time (e.g., 100,000 USDC)
3. Attacker calls `wallet.init(attackerAddress)` - becomes the new admin
4. Attacker calls `wallet.sweep(USDC, attackerAddress)` - steals all funds
5. Legitimate admin tries to sweep but gets `NotBuilder` error

## Recommended mitigation steps

**Option 1: Add initialization guard and factory-only restriction**


**Option 2: Set admin in constructor (recommended)**
