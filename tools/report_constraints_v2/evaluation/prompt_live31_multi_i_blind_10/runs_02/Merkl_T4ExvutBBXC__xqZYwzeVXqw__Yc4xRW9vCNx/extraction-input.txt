Using USDT as dispute token can lead to some severe impacts

### Finding Description and Impact

Based on [C4 docs](https://docs.code4rena.com/competitions/severity-categorization#unsupported-non-standard-tokens-and-fee-on-transfer-tokens) :

> The only exceptions is USDT, which should be considered in-scope despite non-standard behavior.
> 

Since there are no statement on the `README` about token in-scope, i believe this statement on C4 docs hold.

Jump into the issue, using `USDT` as dispute token will cause an issue. Consider scenario below :

1. The root was updated with the wrong value with `updateTree()` function, which caused the wrong user can claim the token in Distributor contract.
2. Attacker knowing this, he made a dispute using `disputeTree()` function
3. After that, attacker make his address blacklisted
4. Merkl team has two severe impacts here, if it does resolve with `true` it can’t happen because disputer address in this case attacker, already blacklisted. This lead to distributor contract `DoS’ed` because `resolveDispute()` always revert and next tree can’t be update. If it does resolve with `false` , this lead to wrong user can claim the token in Distributor contract.

### Recommended Mitigation Steps

Consider create intermediary contract to be a bridge between the disputer and the distributor contract
