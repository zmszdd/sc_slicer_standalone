Blacklisted Disputer Forces Governor to Falsify Dispute Outcome and Confiscate Bond

## Finding description and impact

The `Distributor` contract allows users to dispute a Merkle tree update by posting a bond (`disputeAmount`) in a `disputeToken`. If the dispute is valid, the Governor calls `resolveDispute(true)`, which refunds the bond to the disputer and reverts the tree.


If the `disputeToken` has a blacklist mechanism (e.g., USDC, USDT) and the `disputer` address is blacklisted during the dispute period, the `safeTransfer` call in the `valid` branch will revert.

This creates a dilemma where the Governor **cannot** resolve the dispute as `valid` (true), even if the Merkle tree is objectively incorrect. To unblock the system (clear the `disputer` variable), the Governor is **forced** to call `resolveDispute(false)`.

**Impact:**

1.  **Forced Falsification:** The Governor is forced to record a `DisputeResolved(false)` event on-chain for a valid dispute, breaking the trust and accuracy of the governance log.
2.  **Unfair Confiscation:** The honest disputer loses their bond (`disputeAmount`), which is sent to the Governor instead of being returned.
