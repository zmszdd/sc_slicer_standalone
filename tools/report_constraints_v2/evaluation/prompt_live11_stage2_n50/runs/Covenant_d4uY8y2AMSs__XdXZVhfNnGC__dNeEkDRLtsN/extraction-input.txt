Multicall `delegatecall` opens reentrancy risk between batched operations

## Finding description and impact

Here's the problem - when you use `delegatecall` in multicall, every operation runs with the Covenant contract's full authority. The market-level locks are solid, but they don't cover the gaps between different operations in the same multicall batch.

Think about it this way: an attacker could slip a malicious call into the batch that calls back into the contract before the next operation executes. This could let them manipulate state in between legitimate operations, potentially messing with fee calculations or market states.

What worries me is that while each individual market operation is locked down, the multicall wrapper itself isn't guarded. It's like having a secure building where each room has a lock, but the hallway connecting them doesn't.

The damage could range from minor state inconsistencies to someone gaming the system for financial advantage. It's one of those "shouldn't happen" things that becomes a real headache when it does.
