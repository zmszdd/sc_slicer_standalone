Critical Access Control Bypass in WERC7575Vault Allows Theft of Funds from Users with Self-Allowance

## Finding description and impact

### Root Cause

The `WERC7575Vault` contract fails to implement standard access control checks for the `withdraw` and `redeem` functions.

In a standard ERC4626 implementation, if the caller (`msg.sender`) is not the owner of the shares (`owner`), the vault must check and decrease the allowance that the owner has granted to the caller (`allowance[owner][msg.sender]`).

However, the `_withdraw` function in `WERC7575Vault.sol` only calls `_shareToken.spendSelfAllowance(owner, shares)`. This function specifically checks and decrements `allowance[owner][owner]`. While this enforces the protocol's requirement that users must have a "self-allowance" (platform permission) to move funds, it **completely ignores** the relationship between the caller and the owner.


### Impact

This vulnerability allows **arbitrary theft of funds** from any user who has set up their account for normal operation.

According to the project documentation (`USE_CASE_CONTEXT.md` and `KNOWN_ISSUES.md`), users are **required** to set a "Self-Allowance" via `permit` to perform transfers or withdrawals. This means valid users will almost always satisfy the `spendSelfAllowance` check.

An attacker can call `vault.redeem(shares, attackerAddress, victimAddress)`.

1. The vault checks if the victim has self-allowance (`spendSelfAllowance`). This passes because the victim is a legitimate user.
2. The vault **fails** to check if the attacker has allowance from the victim.
3. The vault burns the victim's shares.
4. The vault transfers the underlying assets to the attacker.

This is a critical severity issue as it leads to direct and unrestricted loss of user funds.
