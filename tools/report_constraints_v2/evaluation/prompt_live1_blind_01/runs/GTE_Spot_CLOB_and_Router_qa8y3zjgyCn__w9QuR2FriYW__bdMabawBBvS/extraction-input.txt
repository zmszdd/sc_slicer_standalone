Users cannot amend orders to a price where they would be filled (partial amend-to-fill blocked)

## Finding description and impact

The `CLOB` contract implements a central limit order book (CLOB) for spot trading, supporting limit and fill orders, as well as order amendments and cancellations. The amendment logic is handled by the `amend()` function, which allows users to modify their existing orders' parameters, such as price, amount, and side, provided certain checks pass.

A key restriction in the amendment logic is that only `POST_ONLY` orders can be amended (`amend()` enforces `if (args.limitOrderType != LimitOrderType.POST_ONLY) revert AmendNonPostOnlyInvalid();`). But if a `POST_ONLY` order has a price which would immediately fill the order (even partially) the function will revert with `PostOnlyOrderWouldFill()` via the `_executeBidLimitOrder()` or `_executeAskLimitOrder()` internal calls.

**Summary of the flow:**
- Users can only amend orders to be `POST_ONLY` orders.
- If a user tries to amend an order to a price that would result in an immediate match (even partial), the transaction reverts.

**Impact:**
- Users are unable to amend their orders to a price where they would be filled, even if this is their intention (e.g., to cross the spread and take liquidity).
- This restricts one of the main usages of amending an order, to move the order to the current price so it gets filled
