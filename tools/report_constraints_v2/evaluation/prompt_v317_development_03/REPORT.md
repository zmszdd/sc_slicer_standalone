# semantic-v3.17 五例开发回归报告

日期：2026-09-21

## 1. 测试目的与边界

本次测试用于检查 v3.17 的专用安全关系模板、影响限定绑定和局部修复是否能改善形式化
候选生成。测试对象为 Monetrix、Intuition、GTE Spot、GTE Perps、Olas 五份已用于开发分析的
报告，因此这是**开发回归**，不是独立留出测试，也不能用于估计总体准确率。

经用户授权，调用 DeepSeek `deepseek-flash` 时仅发送已保存的阶段二结构化要素；未发送合约
源码。第一步 P/I/V 要素未重新提取，本报告只评价第二步形式计划和确定性规则化。

## 2. 汇总结果

| 指标 | 结果 | 含义 |
| --- | ---: | --- |
| 输入案例 | 5 | 均已有合法结构化要素 |
| 生成最终形式候选 | 2/5（40%） | Monetrix、Olas |
| 可带警告继续 | 2/5（40%） | 均仍为 `needs_review` |
| 被程序拒绝 | 3/5（60%） | GTE Perps、GTE Spot、Intuition |
| 候选离线重放 | 2/2（100%） | 文件、证据、SMT 和求解结果一致 |
| 外部模型调用 | 11 次 | 3 个失败案例各 3 次，2 个候选各 1 次 |
| Token | 78,886 | 输入 65,925；输出 12,961；缓存命中 51,200 |
| 模型响应耗时合计 | 95.778 秒 | 各请求 `elapsed_seconds` 之和，不等于批次墙钟时间 |

Z3 结果只验证生成公式内部的可满足性和 I/V 互斥关系，不证明公式忠于报告，也不证明 PoC
与报告一致。

## 3. 逐例分析

| 案例 | 工程结果 | 语义初评 | 主要原因 |
| --- | --- | --- | --- |
| Olas | 候选，可继续 | 核心 P/I/V 基本合理 | 已保留“偏差超过容忍度时校验仍通过”的阈值和状态限定；关系类别标成 `access_control` 不理想，但生成公式表达的是校验保护关系 |
| Monetrix | 候选，可继续 | 部分正确 | 对应关系 `reportedDecimals = underlyingDecimals + offset` 合理；但 P 混入漏洞返回值，且派生定义采用 `definition ⇒ I`，存在定义为假时 I 空真的风险 |
| Intuition | 拒绝 | 计划语义方向合理，来源修复失败 | 比例关系已使用交叉相乘；影响上下文引用 `epoch_length_seconds`，但该符号没有同时引用选中 impact，三次尝试后仍被来源门拒绝 |
| GTE Spot | 拒绝 | 计划接近报告，定义结构不合法 | “只剩小于 lot size 的 dust 时不应回退”方向正确；派生量引用另一派生量且使用未被当前白名单允许的 action 来源，局部修复未收敛 |
| GTE Perps | 拒绝 | 拒绝合理 | 选中影响是 fork/reference 的 LP 价值差，计划却生成单一 reserve 守恒式，无法直接表达该影响；同时限定符号没有由 impact 自身支撑 |

按核心语义作保守开发集初评：Olas 可视为 1 个较完整候选，Monetrix 为 1 个部分正确候选；
其余 3 个没有通过形式化门。这里的 `1/5` 或 `2/5` 仅是缺陷定位比例，不是准确率。

## 4. 本轮确认的改进与缺陷

已确认有效：

1. Olas 中原先遗漏的阈值限定已进入 `impact_context_terms`，说明限定类型反馈有效。
2. 12 类关系到专用确定性模板的映射已被真实模型使用；Olas、Monetrix 均生成了可编译计划。
3. 来源门阻止了 GTE Perps 用前提证据冒充 impact 限定，也阻止了 Intuition 的不完整来源绑定。
4. 两个候选均可零模型调用重放，实验产物具有可审计性。

仍需解决：

1. **派生定义的逻辑位置**：当前 `definition ⇒ I` 可能产生空真。不能直接修改 v3.17，
   否则会破坏既有结果重放；应在新 schema 中把定义作为全局约束，或与 I/V 同时合取。
2. **局部修复不够针对性**：模型常只修改报错字段，却遗漏相关符号的 `source_ids`，导致
   同一来源错误重复出现。
3. **派生表达式限制与提示不一致**：程序只允许派生量引用基础符号，但提示没有明确禁止
   派生量链；action/root-cause 能否作为定义证据也需统一规定。
4. **关系分类仍会错位**：Olas 的验证条件被标成权限关系；虽然本例公式核心尚可，类别错误
   会降低可解释性，并可能在其他案例选错模板。
5. **P 角色污染仍存在**：Monetrix 把漏洞输出 `decimals() = 6` 放入 P，说明来源合法不等于
   时序和语义角色正确。

## 5. 结论与下一步

v3.17 已证明“模型提出计划—程序合成公式—Z3 检查—离线重放”可在真实开发案例上工作，
但候选率仅 40%，严格语义仅有一个较完整案例，尚不适合无人工复核地投入使用。

下一版应建立 `semantic-v3.18`，保持 v3.17 产物不变，并只做三项通用修正：

1. 将派生定义改为不可空真的显式公理；
2. 让来源修复联动修改谓词和相关符号来源，并明确 action/root-cause 的证据资格；
3. 在形式化前增加 P 时序角色检查和“所选影响—关系模板”一致性检查。

完成后先用本五例做开发回归，再冻结规则，换一批未参与修改的新报告统计工程完成率、
语义误放行率和误拒绝率。
