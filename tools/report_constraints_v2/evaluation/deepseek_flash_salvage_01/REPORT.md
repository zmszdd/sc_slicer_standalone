# 阶段二部分继续与机械修复复验（2026-09-17）

在[三报告首次测试](../deepseek_flash_pilot_01/REPORT.md)的**原始成绩 0/3 完整流程**之外，单独建立本开发复验目录。用户要求允许非关键部分继续，同时保留核心语义校验。修复只处理两种不改变报告含义的形式瑕疵，均需显式使用 `--mechanical-salvage` 或离线重放工具：

1. 将唯一且无冲突的大小写不合规实体/陈述 ID 转成小写，并同步改结构化引用；原文、证据编号、陈述类型和模态不变。冲突或其他非法 ID 仍拒绝。
2. 仅删除**完全未被谓词引用**且 `entity_ids` 为空的无效符号声明；绝不为其补造实体或证据。原始模型输出不改，变更另存审计记录。

数值保真、来源角色、公式类型、证据编号、P/I/V 关系等校验**没有放宽**。`--mechanical-salvage` 默认关闭，历史结果不受影响；[`replay_mechanical_salvage.py`](../../replay_mechanical_salvage.py) 可以完全离线重放已保存的模型输出，不需要密钥或网络。

## 通用规则与待解决的核心问题

- **可机械修复**：仅可证明不影响谓词含义的 ID 大小写和未引用无效声明；记录原值、新值与原因，且防冲突。不要凭文本相似度改证据 ID、P/I/V 句子、角色、模态或数值。
- **可部分继续**：要素已过校验而形式计划失败时，保留其可审核的要素候选；公式仅在所有核心保真检查通过后生成。`needs_review`、`elements_candidate`、`pipeline_failure` 不得混用成“正确”。
- **必须阻断/待审**：显式数值条件丢失；I/V 极性颠倒；正常行为与违规行为的限定丢失；核心算术/时间关系只用无定义布尔量代替。这些不能靠 Z3 SAT/UNSAT 或机械清洗认定已解决。

下一步最有价值的通用改进是增加**报告锚定的正反场景审查**：分别从报告选取正常场景与违规场景，要求 I 在正常场景成立、在违规场景不成立，V 则相反；每个场景的变量取值/条件必须有证据编号或标 `unknown`。程序用已有公式做具体代入和反例检查；无法绑定报告事实时降为 `review`，而不是用公式自身生成一个自洽但反向的“正反例”。这应在新的开发批次实现与验证，不改写本次原始成绩。样本仍太少，同一助手审查不构成独立准确率。
