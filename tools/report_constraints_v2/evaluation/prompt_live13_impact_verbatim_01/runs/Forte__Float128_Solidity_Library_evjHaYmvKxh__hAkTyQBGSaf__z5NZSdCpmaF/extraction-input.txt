`Float128.sol` - `le` Function Fails to Include Mantissa Equality When Exponents Are Equal, Leading to Incorrect Comparison Logic

## Finding description and impact

The `Float128.le(a, b)` function, used to determine if floating-point number `a` is less than or equal to `b`, contains a logic error when handling cases where the two numbers have the same sign and equal exponents.

Specifically:
1.  **For Positive Numbers** (L930-L937): When `a` and `b` are both positive and have equal exponents (`eq(aExp, bExp)`), the code on line L932 uses `retVal := lt(aMan, bMan)`. This only covers the case where `a`'s mantissa is strictly less than `b`'s mantissa, missing the case where `a`'s mantissa is equal to `b`'s mantissa.
2.  **For Negative Numbers** (L938-L945): When `a` and `b` are both negative and have equal exponents (`eq(aExp, bExp)`), the code on line L940 uses `retVal := gt(aMan, bMan)`. This only covers the case where `a`'s mantissa is strictly greater than `b`'s mantissa (because the comparison is reversed for negative numbers), missing the case where `a`'s mantissa is equal to `b`'s mantissa.

While the initial check on line L900 `if (packedFloat.unwrap(a) == packedFloat.unwrap(b)) return true;` handles cases where the packed representations of `a` and `b` are identical, it's insufficient to cover all logical scenarios of `a <= b`. For instance, if two floating-point numbers are logically equal but have different packed representations due to normalization or other reasons, they might pass the L900 check and proceed to the erroneous logic branches.

**Impact**:
This error causes the `le` function to incorrectly return `false` in some cases where `a` is equal to `b`. Any protocol logic relying on the `le` function for critical comparison decisions (e.g., checking prices, boundary conditions, sorting, etc.) could therefore exhibit unexpected behavior or calculation errors. While this doesn't directly lead to theft of funds, it undermines the basic correctness of a library function and can indirectly impact the protocol's stability, state, or financial calculations, fitting the definition of a medium risk.
