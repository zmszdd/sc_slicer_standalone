Incorrect Token Address for NoCapLimit Override

## Finding description and impact

 
The issue is in the LatentSwapLEX.sol, 
 

The tokenNoCapLimit mapping is intended for quote tokens (as per the event comment: "for markets with this quote token"). 
 
Howevere,  in the function initMarket, 
It passes marketParams.baseToken (the collateral asset, e.g., ETH) instead of marketParams.quoteToken (the stable asset, e.g., USDT). This means default noCapLimit overrides set via setDefaultNoCapLimit (which takes a quote token address) will be ignored, and markets will fall back to an unintended (or zero) value based on the base token. Therefore, the code incorrectly passes marketParams.baseToken as the key to fetch this default, so new markets inherit the wrong cap limit (e.g., from the base token's override, or fallback to 1 if none exists), ignoring the intended quote-token-specific configuration. 

## Impact  
This issue causes newly initialized markets to apply incorrect default mint/redeem cap limits based on the base token instead of the quote token, potentially leading to overly restrictive or permissive operations that disrupt expected collateralization and trading behavior.  Meaning New markets will use incorrect noCapLimit values (e.g., defaulting to 0, meaning 1 baseToken cap), leading to unexpected mint/redeem behavior or DoS on initialization.
