TWAMM charges swap fees when cancelling an order before it starts, causing unjust fund loss

## Finding description and impact

TWAMM lets users schedule long-term swap orders between two timestamps ``(startTime → endTime)``.
However, the implementation charges LP swap fees even if the order has not started yet.

## Root cause

Inside ``TWAMM.handleForwardData`` (callType = 0: update sale rate):
This branch runs without checking whether any swap has actually occurred.

Thus:
- If a user cancels or reduces an order before startTime,
- TWAMM computes amountDelta < 0 and charges swap fees,
- even though zero TWAMM execution has taken place,
- and the user should not lose anything except possible rounding dust.

Severity justification

This is not a cosmetic bug:
- A user can lose up to full TWAMM fee amount even though no swap occurs
- This affects any contract or end-user relying on the “scheduled order” logic
- The loss scales linearly with order size
- A malicious interface could force users to create and cancel orders, accumulating unjust fees

Because this is direct, repeatable, user-fund loss caused by TWAMM logic—not market behavior—it qualifies as High severity.
