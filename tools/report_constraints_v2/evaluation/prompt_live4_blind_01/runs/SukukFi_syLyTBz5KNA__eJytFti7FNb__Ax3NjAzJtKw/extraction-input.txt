strict 0 balance check would enable DoS in `unregisterVault` by sending 1 wei of asset directly

## Finding description and impact

as we can see in [`WERC7575ShareToken::unregisterVault`](https://github.com/code-423n4/2025-11-sukukfi/blob/d7e734192a571511f47962e7f228ad5ed275e7db/src/WERC7575ShareToken.sol#L262-L279) there are strict balance check of asset that must be zero for each WERC7575Vault contract.
as we know the WERC7575Vault impose a 1:1 rate of USDC (asset) and its share counterpart (WUSD), which mean directly sending 1 wei asset to the vault would mean it would create 1 wei of asset that does not have shares, meaning it would never be able to withdrawn from the contract.

given how the share token also have strict `MAX_VAULTS_PER_SHARE_TOKEN`, the impact of DoS would be severe as the contract can have 10 maximum of asset to vault which if this is exhausted, there are no way to sunset an asset vault and add new one. creating new share token would not solve this problem as it would add unnecessary complexity to the already complex settlement/investment layer.

the issue also exist in `ShareTokenUpgradeable` counterpart.
