execute and pull* can accumulate residual ETH/tokens on the router

execute forwards msg.value into a delegatecall to Multicall3 without ensuring that the sum of per-call values equals msg.value. Any surplus remains on the router. pullAndExecute and pullAmountAndExecute transfer tokens from the caller to the router up front but do not guarantee those tokens are fully spent during the multicall; any leftovers remain on the router. There is no automatic refund path in these public functions.

Relevant code
- **Attack Path**:
  1. User or integrator overfunds `execute` or `pull*` relative to batch consumption.
  2. Leftover ETH/tokens remain parked on the router.
  3. Residual balances can later be expropriated (see Finding 1 and 3).
- **Impact**: Stranded ETH/tokens on the router that increase blast radius when combined with public draining vectors; user funds may be unintentionally exposed.
