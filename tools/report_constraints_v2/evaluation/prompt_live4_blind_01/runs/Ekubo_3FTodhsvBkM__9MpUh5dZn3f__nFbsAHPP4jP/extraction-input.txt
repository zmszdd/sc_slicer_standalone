Incorrect Event Emission in TokenWrapper.transferFrom can Leads to Protocol Integration Issues

## Summary
The `TokenWrapper` contract's `transferFrom` function incorrectly emits the `Transfer` event using `msg.sender` (the spender) as the source address instead of the `from` address (the token owner).

## Vulnerability Details
In the `transferFrom` function of `src/TokenWrapper.sol`, the code executes the transfer logic correctly (updating allowances and balances) but emits the wrong event data.


`msg.sender` in `transferFrom` is the `spender` (the account authorized to move funds), not necessarily the token owner (`from`). The ERC20 standard requires the `Transfer` event to show the movement of tokens from the `from` address to the `to` address.

## Impact
- **Broken Event Compliance**: The contract violates the ERC20 standard regarding event emission.
- **Incorrect Indexing**: Off-chain indexers, wallets, and block explorers will incorrectly attribute the source of the transfer. They will show the spender as the sender of funds, rather than the actual token owner.
- **Protocol Integration Issues**: Other protocols that rely on `Transfer` events to track balances or activity will receive incorrect data.
