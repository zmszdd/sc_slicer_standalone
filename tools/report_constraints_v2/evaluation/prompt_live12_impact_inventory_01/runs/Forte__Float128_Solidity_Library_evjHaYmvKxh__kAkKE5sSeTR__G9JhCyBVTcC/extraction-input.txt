Unhandled Zero Input in Natural Logarithm Function

## Finding description and impact

The ln() function in Ln.sol lacks an explicit zero input validation check, unlike other functions in the library. This creates two distinct vulnerabilities:

With a regular zero input (packedFloat.wrap(0)), the function returns an incorrect non-zero value (57664...) instead of zero or reverting with a clear error message.
With specially crafted zero inputs (where mantissa=0 but exponent > -38), the function reverts due to division by zero in ln_helper():

``uint q1 = Float128.BASE_TO_THE_MAX_DIGITS_M_X_2 / mantissa;``
