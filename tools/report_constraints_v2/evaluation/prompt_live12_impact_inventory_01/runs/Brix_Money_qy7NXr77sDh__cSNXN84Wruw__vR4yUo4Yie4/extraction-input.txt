Unrestricted rebalanceFunds allows draining vault buffer to custodian

## Summary
An access control gap allows any address to call `rebalanceFunds()` on the Fast Access Vault, transferring all buffer excess to the custodian without restrictions. This exposes on-chain redemption liquidity to depletion and potential misdirection if the custodian address is stale.

## Finding Description
`rebalanceFunds()` in `FastAccessVault` is declared `external` and lacks any role or ownership check, despite the interface documenting it as owner-only. When the vault balance exceeds the target, the function transfers the full excess to the custodian address. Because no caller restrictions or rate limits exist, any account can invoke it repeatedly whenever the buffer is above target, forcing excess liquidity off-chain and reducing instant redemption capacity. The vulnerable logic is between lines 164-180 of `FastAccessVault.sol`. 【F:src/protocol/FastAccessVault.sol::L164-L180】【F:src/protocol/interfaces/IFastAccessVault.sol::L139-L145】

## Impact Explanation
Unrestricted callers can repeatedly strip the vault’s on-chain buffer down to the target, degrading instant redemption availability and forcing users to rely on slower custodian pathways. If the custodian address has been rotated incorrectly or is compromised, excess funds can also be misdirected.

## Likelihood Explanation
Exploitation requires only sending a public transaction to `rebalanceFunds()`, with no prerequisites beyond paying gas; the action is straightforward and can be automated, making real-world abuse highly plausible.
