Swap `amountIn` incorrectly includes prior undistributed accrued fees, leading to distorted K-invariants, unfavorable swap pricing, and over-accrued fees until next-block distribution

## Finding description and impact

**Root cause (3 lines max):** In `swap()`, `amountIn` is calculated as the delta between current balance and reserves (`balance - (_reserve - amountOut)`), but prior `accruedLaunchpadFee` remains in the balance while reserves subtract it in `_update`. This makes prior fees appear as extra current input, inflating `amountIn` for same-block subsequent swaps. The K-invariant check and new fee accrual then use this inflated value, skewing math until fees distribute on next block's first `_update`.

**Impacts:** 
- Swappers get worse rates (less output for same input) due to "fake" higher input in pricing/reserves.
- New launchpad fees over-accrue (e.g., 0.1% fee on inflated input), diluting legitimate rewards.
- Distorts pool invariants mid-block; potential MEV (frontrun to exploit skewed pricing) or DoS (force bad rates via timed swaps). High impact if high-volume pairs, as it affects all same-block users post-fee accrual.

**Vulnerability flow (step-by-step with PoC math):**
1. Setup: Pool has 100 ETH base/quote reserves, launchpad owns ~100% LP (totalSupply=100 ETH). No prior fees.
2. First swap: User sends 10 ETH base input → pair balance_base=110 ETH. Swap outputs ~9.066 ETH quote (997/1000 fee). New fee0 = (10 * 1 * 100%) / (100 * 1000) = 0.01 ETH accrued. Reserves update to balance - totalFee0 = 110 - 0.01 = 109.99 ETH base (quote ~90.933 ETH). Event: `Swap(amount0In=10 ETH)`.
3. Same-block second swap: User sends actual 10 ETH base → pair balance_base=120 ETH (110 prior + 10 new). But reserves still reflect prior subtraction (109.99 base), so detected amount0In = 120 - (109.99 - 0) = 10.01 ETH (actual 10 + prior 0.01 fee). Outputs ~7.557 ETH quote (worse rate due to skewed reserves). New fee0 = (10.01 * 1 * 100%) / (100 * 1000) ≈ 0.01001 ETH (over-accrued on inflation). Reserves: 120 - 0.02001 totalFee0 ≈ 119.979 ETH base. Event: `Swap(amount0In=10.01 ETH)` (verifies inflation).
4. Next block: First `_update` (e.g., sync/swap) distributes 0.02001 ETH fees to distributor, resetting accrued=0 and aligning reserves=balances. Until then, mid-block swaps suffer distorted pricing.
