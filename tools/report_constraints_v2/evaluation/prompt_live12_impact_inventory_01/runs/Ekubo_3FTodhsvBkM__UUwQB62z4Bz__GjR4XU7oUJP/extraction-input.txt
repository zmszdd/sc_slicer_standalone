Router Swap Functions Lack Deadline Protection, Allowing Stale Transactions to Execute at Unfavorable Prices

## Vulnerability Details

### Finding Description and Impact

#### Overview

While auditing the Router contract, I discovered that **none of the swap functions include a deadline parameter**. This is a significant omission compared to industry standards - every major DEX (Uniswap V2/V3/V4, SushiSwap, Curve, PancakeSwap, etc.) implements deadline protection as a fundamental safety feature.

A deadline is a timestamp after which a pending transaction should revert if not yet executed. Without it, users cannot express: "Execute my trade within the next N minutes, or don't execute it at all."
