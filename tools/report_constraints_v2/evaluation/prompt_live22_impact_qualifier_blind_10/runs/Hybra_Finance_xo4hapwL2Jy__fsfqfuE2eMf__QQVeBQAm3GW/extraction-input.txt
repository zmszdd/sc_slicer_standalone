Attacker can create a malicious pool and cause a permanent Denial of Service on both `distributeFees` functions at the same time

## Finding description and impact

In the `GaugeManager.sol` contract, there is a function `createGauge`. This function allows anyone to push a pool into the `pools` array.

This function validates that the `_pool` we intend to add has some code and is not an EOA:
However, the function does not validate that the pool is not malicious.
As a result, an attacker can simply deploy a malicious pool which reverts in its `collectFees` function.

When the function `distributeFees(uint256,uint256)` is later called, it iterates through some pools depending on the input params.
However, because the attacker added a malicious pool that reverts in its `collectFees` function, the tx will always revert. Ideally for the attacker, if the first pool in the `pools` array is the malicious pool, all txs will revert, no matter the input params.
