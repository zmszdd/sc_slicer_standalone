Market Creation Fails for Pyth-Based Volatile Assets Due to Missing Oracle Price Update Mechanism

## Finding description and impact

### Summary
The createMarket() function cannot atomically update Pyth oracle price feeds before market initialization, causing market creation to systematically fail for volatile assets (ETH, BTC, MON) when the cached Pyth price exceeds the staleness threshold (typically 10 minutes). This directly contradicts the protocol's documented design where "volatile assets (e.g., ETH, BTC, MON) are priced through pull feeds from Pyth" (from audit README).

## Attack Scenario / User Impact

User wants to create ETH/USDC market using Pyth oracle
Pyth's cached ETH price is 11 minutes old (normal during low activity)
User calls createMarket(marketParams, initData)
Execution path: createMarket() → initMarket() → readBasePriceAndCalculateLiqRatio() → getQuote()
PythOracle checks: staleness = 11 minutes > maxStaleness (10 minutes)
Transaction REVERTS with PriceOracle_InvalidAnswer
User must now:

Call curator.updatePriceFeeds{value: fee}() separately
Immediately call createMarket() before price goes stale again
Hope no one else creates the market first (race condition)
