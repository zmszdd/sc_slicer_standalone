FOK fill orders WILL REVERT if only the amount rounded off is left unfilled

## Finding description and impact

From ReadMe : "On CLOB fill, filled amounts are rounded down to the nearest lot. FOK fill orders should not revert if only the amount rounded off is left unfilled, and the user is not charged for the dust." [link](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/README.md?plain=1#L31)

But right now, code enforce this instruction only if amountIsBase is false. If it is true the FOK fill Orders will get revert.

https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L817

Lets say for `price = 1 ether`, there is only 1 Buy Order of `size = 10 ether` in the order book.
Now the incoming Fill Ask Order has been executed with the same price and `baseAmount = 10 ether - 9` and the `lotSize = 10` , `amountIsBase = true`

the execution reaches, [@1](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L819)  => `matchData.baseDelta =  10 ether - 10`

[@2](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L821) => `matchData.matchedAmount = 10 ether - 10`

Function exits and reaches [here](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L797), 

`incomingOrder.amount = (10 ether - 9) - (10 ether - 10)  = 1` 

And it will exit this [loop](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L779) since there are no other matching Order. (Even if there is one more matching Order, the loop is exited from [here](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L795) in the next iteration since `currMatch.baseDelta =  (1 /10 )* 10 = 0` without updating incomingOrder.amount. So the `incomingOrder.amount stays 1` in this case too )

Since the `1` is the remaining value that has been rounded off while dividing with the lotSize(10) , the transaction should not revert.

But, inside the _processFillAskOrder() , this [condition](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L469) checks `newOrder.amount > 0` and will revert with `FOKOrderNotFilled()` message.
