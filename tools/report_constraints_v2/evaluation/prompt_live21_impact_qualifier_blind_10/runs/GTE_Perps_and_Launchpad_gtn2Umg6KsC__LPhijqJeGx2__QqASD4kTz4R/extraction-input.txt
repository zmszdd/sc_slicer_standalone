Margin Removal Allowed in Inactive Markets

### Summary  
The `removeMargin()` function lacks proper market status validation, allowing users to withdraw margin from subaccounts containing positions in INACTIVE markets. This bypasses the intended security mechanism where INACTIVE markets should prevent margin operations due to potential security incidents.

### Finding Description  
The perpetual trading system implements a market status mechanism with states: `INACTIVE`, `ACTIVE`, and `DELISTED`. When markets are set to `INACTIVE` status, it typically indicates a security incident or emergency situation requiring immediate action to protect user funds and system integrity.

The system enforces market status checks through the `onlyActiveMarket` modifier and `assertActive()` function in `MarketLib`. These checks are properly implemented for critical functions like `placeOrder()` and `amendLimitOrder()` to prevent trading activities in inactive markets.

However, the `removeMargin()` function in `PerpManager.sol` lacks this crucial validation. The function performs the following operations:

1. Loads account positions and assets from the clearing house
2. Realizes funding payments across all positions
3. Settles margin updates through the collateral manager
4. Validates post-withdrawal margin requirements
5. Updates position states

While the function validates margin requirements and prevents liquidation, it does not verify that all markets associated with the subaccount's positions are in `ACTIVE` status. This creates a critical security gap where users can extract margin from compromised or emergency-locked markets.

The issue becomes particularly severe in cross-margin scenarios where a single subaccount may contain positions across multiple markets. If any market becomes `INACTIVE` due to a security incident, users can still withdraw margin from the entire subaccount, potentially extracting funds that should be locked for investigation or recovery.
