Incomplete Equality Handling in `le()` Function Causes Edge Cases

## Finding description and impact

The `le()` (less than or equal) function in Float128.sol contains a subtle but important logical error in how it handles equality cases. While it does check for exact equality at the beginning of the function:


The function has a flaw in its main comparison logic where numbers have equal exponents:
[Link](https://github.com/code-423n4/2025-04-forte/blob/4d6694f68e80543885da78666e38c0dc7052d992/src/Float128.sol#L930-L933)

This issue results in inconsistent comparison behavior when working with floating point numbers that are mathematically equal but have different bit representations. For example, the numbers `1000 * 10^3` and `1000000 * 10^0` both equal `1,000,000`, but when comparing these values, the function may return different results depending on which value is on which side of the comparison.

The impact of this issue includes:
1. Inconsistent comparison results that break the expected mathematical properties of equality
2. Potential vulnerabilities in financial calculations where exact comparisons are critical
3. Logical inconsistencies between `le()` and `gt()` functions, where `!(a > b)` doesn't always equal `a <= b`
