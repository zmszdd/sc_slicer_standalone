## Summary

Passing a zero-weight split leg into `VotingEscrow.multiSplit` will cause a denial-of-service for withdrawing users as any gHYBR holder will invoke `withdraw` with a full exit

## Root Cause
In GovernanceHYBR.sol:190 the computed `remainingAmount` can be zero when a user exits their entire position (or fee rounds to zero) and `VotingEscrow.multiSplit` enforces every split weight to be strictly positive, so the contract forwards `[remainingAmount, userAmount, feeAmount]` with a zero element and reverts with `"ZW"`


1. User deposits HYBR and receives gHYBR shares via `GovernanceHYBR.deposit`, locking funds in the shared veNFT
2. User calls `GovernanceHYBR.withdraw` with all their shares
3. `remainingAmount` (or `feeAmount`) is zero, so `VotingEscrow.multiSplit` rejects the call
4. The revert propagates and the withdrawal fails, leaving the user unable to exit their position

## impact
Legitimate users cannot withdraw their locked HYBR when their remainder or fee share is zero, causing a self-DoS on exits
