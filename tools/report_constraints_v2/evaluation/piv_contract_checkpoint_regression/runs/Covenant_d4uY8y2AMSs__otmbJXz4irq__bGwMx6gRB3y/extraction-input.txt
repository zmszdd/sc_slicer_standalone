AND Logic Error in Mint Cap Check Allows Minting 79 Octillion Tokens in Small Markets

### Finding description and impact

The `mintLogic` function contains a critical logic error in the mint cap validation. The code uses `AND (&&)` when it should use `OR (||)`, allowing attackers to mint astronomical amounts of tokens in small markets, leading to complete protocol insolvency.

**The Bug:**

Using `&&` (AND) means BOTH conditions must be true to revert:
- Condition 1: `mintAmount > Q96` (79,228,162,514,264,337,593,543,950,335)
- Condition 2: `mintAmount > marketBaseTokenSupply`

**Attack Scenario:**

When `mintAmount == Q96` (exactly):
- Condition 1: `Q96 > Q96` = **FALSE**
- Condition 2: `Q96 > marketBaseTokenSupply` = TRUE (in small markets)
- Combined: `FALSE && TRUE` = **FALSE**
- Result: **No revert** - mint succeeds!

This allows minting **Q96 = 79,228,162,514,264,337,593,543,950,335 tokens** (79 octillion) even when the market only has 1,000 tokens.

**Economic Impact:**

For a market with 1,000 baseToken supply:
- **Normal mint cap:** ~1,000-10,000 tokens (reasonable leverage)
- **Exploit mint amount:** 79,228,162,514,264,337,593,543,950,335 tokens
- **Multiplier:** 79 × 10^30 times market size
- **Result:** Complete protocol insolvency, synthetic tokens unbacked
