`GTELaunchpadV2Pair` can be drained due to `totalLaunchpadFees` being subtracted from reserve calculation

# Finding description and impact

Within `GTELaunchpadV2Pair._update()`, if `timeElapsed == 0`, totalLaunchpadFees will be subtracted from reserves but the tokens will not actually be removed from the contract.

[GTELaunchpadV2Pair#L134-150](https://github.com/code-423n4/2025-08-gte-perps/blob/main/contracts/launchpad/uniswap/GTELaunchpadV2Pair.sol#L134-L150)

As you can see above, `_distributeLaunchpadFees()` is only called if `timeElapsed > 0`. This results in a state where `balance0 > reserve0` and/or `balance1 > reserve1`.

This results in a critical vulnerability in both the mint and swap functions where `amountIn` is calculated as `balance.sub(reserve)`.



After accruing some launchpad fees, a malicious user could repeatedly call mint or swap and be credited with an amount that they did not send to the contract. This is most easily seen via swap in the POC below.
