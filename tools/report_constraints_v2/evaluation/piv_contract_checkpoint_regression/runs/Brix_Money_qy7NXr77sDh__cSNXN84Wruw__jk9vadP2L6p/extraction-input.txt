FastAccessVault.rebalanceFunds() Lacks Access Control and Reentrancy Protection, Enabling Griefing and DoS Attacks

### Impact

**HIGH - Protocol Griefing and Denial of Service**

The `FastAccessVault.rebalanceFunds()` function has no access control modifier, allowing anyone to trigger vault rebalancing at will. Combined with the external call to the custodian address (which could be a contract), this creates multiple attack vectors:

**Attack Vectors:**

1. **Griefing via Spam Calls**
   - Any user can call `rebalanceFunds()` unlimited times
   - Each call emits events and triggers custodian transfers
   - Creates spam in event logs and monitoring systems
   - Custodian must handle arbitrary rebalance requests

2. **DoS via Gas Exhaustion**
   - Attacker can front-run legitimate rebalancing operations
   - Spam calls waste gas and create transaction congestion
   - False signals to monitoring systems about vault health
   - Operational overhead for custodian to filter real vs spam requests

3. **Race Conditions**
   - User redemption via `processTransfer()` reduces vault balance
   - Attacker immediately calls `rebalanceFunds()`
   - Vault temporarily under-collateralized between operations
   - Other redemptions might fail in this window

4. **Reentrancy Potential** (if custodian is contract)
   - Line 176: `_vaultToken.transfer(custodian, excess)` is external call
   - No `nonReentrant` modifier on `rebalanceFunds()`
   - Malicious custodian contract can re-enter during transfer
   - With ERC777 tokens or callback-enabled tokens, can drain excess twice

**Financial Impact:**
- **Gas Costs**: Spam attacks increase operational costs
- **DoS Risk**: Critical rebalancing operations delayed or blocked
- **Reputation**: False alarms damage protocol credibility
- **Operational**: Custodian must implement rate-limiting and filtering
- **User Experience**: Redemptions might fail during race conditions

**Affected Operations:**
- ✅ `rebalanceFunds()` - No access control
- ✅ `processTransfer()` - Only issuer-gated (affected by rebalancing spam)
- ✅ Custodian operations - Must handle spam requests
- ✅ User redemptions - Can fail if vault under-collateralized
