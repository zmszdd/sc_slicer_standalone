Normalization logic in Float128::toPackedFloat causes precision loss for floating numbers with high decimal places and digits > 38

## Description and Impact

In toPackedFloat we represent floating point numbers with mantissa size either 38 or 72 depending upon the floating point size. If the mantissa is not exactly 38 or 72 digit long we normalize it, i.e, convert it to either 38  digit or 72 digit long mantissa. And to decide whether the given input mantissa should be normalized to M_MANTISSA (38) or L_MANTISSA (72) we use a `isResultL` bool that checks if the `MAXIMUM_EXPONENT` is signed less than the `mantissaMultiplier + exponent`. But this logic for calculating the bool will result in huge precision loss for floating point numbers that have digits > 38 but the exponent is quite less than the `MAXIMUM_EXPONENT` that the `isResultL` calculation always results in false and those numbers will be wrongly stored in M_MANTISSA range instead of the L_MANTISSA range. This results in a significant precision loss. To further confirm this issue the sponsor has confirmed that floating points with 38 < digits < 72 are valid inputs for this library as seen [here](https://github.com/user-attachments/assets/00924b7c-9ed2-46d8-8b3f-da9495b36626)
