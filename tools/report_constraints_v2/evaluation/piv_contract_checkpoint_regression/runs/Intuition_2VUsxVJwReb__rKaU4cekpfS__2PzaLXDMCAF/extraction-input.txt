Incorrect execution order in _getPersonalUtilizationRatio applies penalty to first-time claimants, bypassing intended exemption

## Finding description and impact

The TrustBonding contract uses a utilization ratio to scale user rewards. If a user's utilization delta is less than or equal to zero (meaning they did not actively increase their participation in the MultiVault), their yield is slashed to the personalUtilizationLowerBound (default 2500, or 25%).

However, the developers explicitly intended to exempt new users from this penalty on their first claim. As noted in the comments at line 527: "If the user had nothing claimable last epoch, don't penalize them as it's their first ever claim." Due to an execution ordering error in _getPersonalUtilizationRatio, this exemption is unreachable for passive stakers. The strict penalty check (rawUtilizationDelta <= 0) is evaluated before the first-claim exemption check (userUtilizationTarget == 0).

## Root Cause
When a new user stakes TRUST purely for yield and does not interact with the MultiVault, their rawUtilizationDelta for their first epoch mathematically evaluates to 0.

When they attempt to make their first claim, the function evaluates rawUtilizationDelta <= 0. Because 0 <= 0 is true, the function returns early and applies the personalUtilizationLowerBound. The execution never reaches the intended exemption block.

Solidity
    // src/protocol/emissions/TrustBonding.sol

    int256 rawUtilizationDelta = userUtilizationAfter - userUtilizationBefore;

    // 1. Evaluated first. Slashes new passive users (whose delta is 0) instantly.
    if (rawUtilizationDelta <= 0) {
        return personalUtilizationLowerBound; 
    }

    uint256 userUtilizationDelta = uint256(rawUtilizationDelta);
    uint256 userUtilizationTarget = userClaimedRewardsForEpoch[_account][_epoch - 1];

    // 2. Unreachable for new users whose delta was 0.
    if (userUtilizationTarget == 0) {
        // If the user had nothing claimable last epoch, don't penalize them as it's their first ever claim
        if (_userEligibleRewardsForEpoch(_account, _epoch - 1) == 0) {
            return BASIS_POINTS_DIVISOR; 
        }
        return personalUtilizationLowerBound;
    }

## Impact
Any new user who locks TRUST to passively stake without interacting with the MultiVault will have up to 75% of their first epoch's matured yield permanently destroyed. This directly contradicts the protocol's explicitly documented economic design. As per Code4rena severity criteria, deterministic loss of matured yield due to incorrect logic implementation is classified as High severity.
