# semantic-v3.14 独立留出集报告（2026-09-19）

## 结论

本轮已真实完成 10 份冻结新报告的 DeepSeek `deepseek-flash` 测试。工程上，8/10 生成合法
要素，7/10 生成形式候选并运行 Z3，6/10 依照当前“关键项正确即可继续”策略进入后续交接。
但证据复核表明，当前主要瓶颈已经从**自然语言要素提取**转移到**P/I/V 的精确公式化**：
8 份合法要素的核心 P/I/V 文本均能在报告中找到依据，而 7 份形式候选中只有 1 份在本轮
单人证据审查下 P、I、V 均无明显核心偏差。

这里的 1/7 **不是总体准确率**：它只是对小规模输出的初步审查，没有独立人工金标准，
也没有执行 PoC。Z3 通过只证明生成公式内部的逻辑关系，不计作语义正确。

## P/I/V 复核

评分含义：`通过`表示核心语义得到保留；`部分`表示方向有用但存在遗漏、额外限定或范围偏差；
`失败`表示公式未表达报告的核心性质或直接违反。审查对象为 7 份实际形式候选。

| 案例 | P | I | V | 关键判断 |
| --- | --- | --- | --- | --- |
| Hybra | 通过 | 失败 | 失败 | 用 `owner_has_approval` 占位“转账是否成功/回退”；模型声明阻塞，程序正确停止 |
| Ekubo | 部分 | 部分 | 通过 | 漏用“意图已改变、滑点满足”，却把示例中的 gas 下降设为必要条件；截止期方向合理但未定义 |
| OLAS | 通过 | 失败 | 失败 | 把“不应接受操纵价格”写成“存在两项缺陷时禁止回购完成”，明显过强且坏结果不对应 |
| Merkl | 部分 | 部分 | 通过 | 捕获 topic 对调，但错误地依赖 off-chain 消费者；应直接约束事件字段等于链上字段 |
| SukukFi | 通过 | 部分 | 通过 | 单用户场景下 `count == 1` 合理，但通用性质应更接近成员仍在集合或 `count > 0` |
| GTE Spot | 部分 | 通过 | 通过 | I/V 方向正确，但一个 P 被映射成重复的错误符号，且把 bug 状态混入前提 |
| Covenant | 通过 | 通过 | 通过 | 嵌套 multicall、共享标志和支付检查回退的核心关系完整 |

按上述审查，P 为 4 通过、3 部分；I 为 2 通过、3 部分、2 失败；V 为 5 通过、2 失败。
这说明自然语言中的坏结果通常能被识别，最不稳定的是将安全意图 I 合成为恰当范围的公式。

## 三类未完成原因

1. **程序限制过严：GTE Perps。** 报告同时给出 mint、burn、swap 三个直接影响，模型两次
   都保留了它们，但当前模式只允许一到两个影响，因此被拒绝。这是模式设计问题，不是报告
   信息不足。后续应允许“一个核心关系 + 多个同源分支”，而不是删除真实影响。
2. **正确的保真拒绝：Panoptic。** 要素正确保留 `2^106`、`2^127` 等事实，但形式化把
   `2^106 - 1` 弱化为 `> 0`/`>= 0`，并出现“可被 106 整除”的臆造关系。数值门拒绝是合理的。
3. **模型输出格式：Intuition。** 第一步返回非法 JSON，尚未进入语义提取。这应通过一次
   受控 JSON 修复/重试解决，不能算作报告或 P/I/V 的错误。

## 客观判断与下一步

本轮证明了完整工程链可批量运行，也证明入口筛选并不是低通过率的主要原因。当前优先级应为：

1. 保持证据编号和数值保真门，不为了提高通过率放松关键错误。
2. 将“安全意图 I 必须由 V 直接否定”升级为对**语义对象**的检查：I 和 V 必须共享同一
   组关键观测量，禁止用 `buyback_completes` 等替代“价格被操纵/输出不公平”。
3. 形式化前先生成一个受限的 `relation frame`：主体、条件、应满足关系、实际违反关系、
   范围；公式只能从该 frame 组合，减少不必要条件和过强结论。
4. 放宽“最多两个影响”为同一根因下的分支列表，但每次只选择一条核心分支生成一个约束，
   解决 GTE Perps 的误拦截。
5. 对就绪阶段非法 JSON 仅做一次确定性修复或重试，并把格式失败与语义失败分开统计。
6. 完成上述通用修改后再冻结一批新报告复测；继续分别报告流程完成率、要素证据支持率和
   形式语义忠实度，避免合并成一个误导性的“准确率”。
