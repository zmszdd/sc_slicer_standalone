# 阶段二独立语义复核与筛选接入（已退役的历史开发复验）

> 2026-09-19 起该提取后筛选已退出活动工作流；当前改为 P/I/V 提取前的信息充分性入口门。本页只保留历史结果和缺陷记录。

## 范围与做法

仅复核本目录中已完成候选公式的 Hybra、Sequence 两份 `report.json` 运行；GTE 没有有效公式，维持原先的 `retain_elements_defer_formalization`。新增 `semantic_audit.py` 使用单轮 `deepseek-flash` 请求，只发送本次报告描述/影响的编号片段及已保存的 P/I/V、符号含义和 AST，不发送 PoC、合约代码或历史复核答案。API 密钥只从本地私有配置读取，不写入结果。筛选器再离线校验复核的 claim/证据 ID、报告与公式哈希，并按关键错误、无法判断、未发现关键错误分流；原始阶段二候选、首次筛选和 API 原始输出均保留。

[带复核的离线筛选结果](SCREENING_WITH_AUDIT.json)显示 2/2 暂缓自动继续；两例仍保留 P/I/V 候选供修正。三次请求均返回合规 JSON，筛选器自身零模型调用。Hybra 初审失败后，通用提示增加“数值/身份关系不得仅用语义标签布尔量替代”的显式检查；这属于**看到测试结果后的开发修订**，不能把修订后 2/2 拦截率称为泛化准确率，也不能把两个模型判断视为独立人工真值。

本地回归使用项目既有 Halmos Python（Z3 4.12.6）：279 项通过。另试用临时安装的 Z3 5.1.0 运行同一套历史重放测试时，有 2 项因旧 SMT 文本与新版本输出不一致而失败；并非此次语义复核代码导致，应按项目固定解释器复验历史产物。

## 尚未解决

- 审核与生成使用同一模型家族，且只有两份可形式化样本；语义审查会漏判，也可能误判。需要冻结提示后在全新项目报告上测关键错误召回与误拦截。
- 复核只审“报告文字 ↔ 候选规则”的忠实度；没有读取 PoC/合约代码，不能判断漏洞是否真实发生或 PoC 是否一致。
- `no_critical_found` 只代表单次审核未发现问题，筛选结果仍为 `continue_with_review`，不提升为已认证正确。
- `GTE` 在形式化前失败，须另行修正生成或保持部分成果，不能拿复核绕过原有结构校验。

本次修改仅涉及 `tools/report_constraints_v2/`，未改阶段一和阶段三实现。
