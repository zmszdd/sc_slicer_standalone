Uniswap v2 oracle slippage check always passes because twap collapses to spot price

## Finding description and impact
Location: UniswapPriceOracle.validatePrice(uint256)

`validatePrice()` is meant to compare the current spot price to a time-weighted average price (TWAP) derived from Uniswap V2 cumulative prices. In the current implementation, the “TWAP” calculation is built using the same spot price that is being validated, so the average becomes identical to the spot price whenever `elapsedTime > 0`

In `validatePrice()`:
1) `tradePrice` is computed from current reserves via `getPrice()`.
2) `cumulativePrice` is computed as `cumulativePriceLast + tradePrice * elapsedTime`.
3) `timeWeightedAverage` is computed as `(cumulativePrice - cumulativePriceLast) / elapsedTime`, which becomes exactly `tradePrice` for any `elapsedTime > 0`.
4) `derivation` becomes 0, so `validatePrice(0)` still returns true.

Concretely, the function reads the pair’s last cumulative price, computes `tradePrice` from current reserves via `getPrice()`, then constructs a new cumulative value by adding `tradePrice * elapsedTime`. The subsequent “average” is computed as `(cumulativePrice - cumulativePriceLast) / elapsedTime`, which simplifies back to `tradePrice`. Because of that, the difference between `tradePrice` and the computed average is 0, and the slippage check passes even if the pool price was heavily manipulated between blocks.


As a result, any contract that relies on `validatePrice(0)` (or any small slippage) as a manipulation-resistance gate can still be executed at attacker-controlled prices, since the oracle check does not meaningfully constrain price movement.
