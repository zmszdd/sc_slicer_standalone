Vault Unregistration DoS via Dust Donation

## Finding description and impact

The `unregisterVault()` function in `WERC7575ShareToken.sol` blocks vault removal when either `IERC7575Vault(vaultAddress).totalAssets()` or `ERC20(asset).balanceOf(vaultAddress)` is non-zero:


This logic assumes that any asset balance in the vault represents user liabilities. However, anyone can **grief the protocol** by sending (“donating”) even 1 wei of the asset directly to the vault. Since the vault may not have a withdrawal/sweep mechanism, this **permanently forces `vaultBalance != 0`**, causing `unregisterVault()` to **always revert**.

As a result, an attacker can **DoS protocol governance** and prevent vault lifecycle operations, including:

* Removing deprecated or faulty vaults
* Migrating users to a new vault implementation
* Cleaning up stale vault registry entries

No user funds are lost, but the protocol’s ability to manage and evolve vault infrastructure becomes hostage to any third-party donation.
