Silent Failure in claimWithRecipient Callback Leads to Permanent Loss of Funds

### **Vulnerability details**

#### Finding description and impact
The `Distributor._claim` function contains a critical flaw in its handling of callbacks to recipient contracts. When a user claims rewards using `claimWithRecipient` and specifies a contract recipient with callback data, the `Distributor` attempts to call `onClaim` on the recipient. This external call is wrapped in a `try/catch {}` block that completely swallows any error, including reverts.


This design creates a dangerous silent failure mode. If the recipient contract's `onClaim` function reverts for any reason (e.g., a downstream protocol is paused, slippage is exceeded, or a parameter is invalid), the `catch` block prevents the main `claim` transaction from reverting. The `Distributor` contract proceeds as if the operation was successful: it updates the user's `claimed` amount and considers the reward fully paid.

This breaks the atomicity of the claim-and-act operation. The reward tokens are successfully transferred to the recipient contract, but the intended subsequent action (e.g., staking, swapping) fails. The user's rewards become stranded in the recipient contract.

**Impact:**

This vulnerability leads to the **permanent loss of user funds** under realistic conditions. A user might employ a trusted "claim-and-stake" contract as their recipient. If the underlying staking protocol is temporarily unavailable when the claim is executed, the funds will be transferred, the callback will fail silently, and the `Distributor` will mark the rewards as fully claimed.

The user cannot re-attempt the claim, as their balance has been updated. If the recipient contract was not designed with a specific recovery function for such stranded funds, the user's rewards are permanently locked and irrecoverable. This directly violates the sponsor's primary security concern of **"Reward Claim Integrity"** and constitutes an irreversible loss of user assets.
