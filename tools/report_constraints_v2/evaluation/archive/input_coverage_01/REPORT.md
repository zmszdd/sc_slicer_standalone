# 输入覆盖与离线重放复验（2026-09-17）

本次只改阶段二。背景：从报告自然语言推导 P/I/V 前，首先必须保证模型读到完整的描述与影响；对模型输出的形式约束则应能够独立重放。证据分解与后续核验可能相互影响，这也是[ACL 2025 关于分解—核验协同的研究](https://aclanthology.org/2025.acl-long.254/)提醒的通用问题；该论文不证明本项目方法的准确率。

## 发现与修改

旧 `report-json-input/2` 在首次遇到 PoC 或修复建议标题时截断正文。本地 1,568 份 `report.json` 中有 1,316 份触发截断；至少 5 份在截断点后还有影响或漏洞细节标题。新 `report-json-input/3` 跳过 PoC/修复建议段落，但在同级或更高层级的描述、总结、影响等标题后恢复读取；嵌套在修复建议里的“Impact”不会恢复，代码围栏仍被排除。

对全部 1,568 份重新生成输入并和 v2 对照：1,533 份字面不变、13 份变长、22 份变短。变短主要是现在也排除了标题为 `Recommendations` 的修复建议；变长不等于语义更准确，仍需逐案核对。冻结案例见 [manifest.json](manifest.json)：Intuition 有效期报告的模型输入从 202 字节增至 2,211 字节，包含之前漏掉的 Summary、Vulnerability Details、Impact，且不包含模板修复段落。

另一个独立缺陷是 `verify_semantic.py` 未处理 v3.8–v3.11 的严格 P/I/V、形式计划及重试产物。现已支持新旧输入策略的精确重放，并重新检查 v3.10 数值和 v3.11 零地址保真守卫。已保存的 Hybra v3.11、Intuition v3.10、Forte 重试和 Intuition v3.8 结果均离线重放成功；这仅验证生成物可复现，不验证报告语义正确。

## 测试与外部调用边界

- 本地单元回归：245/245 通过；包含输入恢复、嵌套章节不泄漏、v2 历史重放、重试路径保护。
- 冻结的 Intuition 报告尝试一次真实模型提取，运行时以 `model runtime exit 1` 结束，没有可评估的 P/I/V 候选。随后在允许外部访问的执行环境中重试的请求被安全审查拒绝，**未执行该次重试**。因此不能声称本次改动提高了提取准确率，也不能提供新的准确率数值。
- 外部调用若继续，需明确确认拟发送的具体公开报告及目标模型服务；在此之前可以继续做本地输入覆盖和历史结果重放测试。

下一步是用全新、预先冻结且未用于改规则的报告，比较 v2/v3 输入下证据覆盖、P 完整性、I/V 直接否定与未决项；再按可信审核标准衡量语义，而不是把 Z3 内部 SAT/UNSAT 当作正确率。
