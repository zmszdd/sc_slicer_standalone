Rebalancing Race Condition Vulnerability leads to Denial of service for redemptions, user fund loss through failed transactions

## Finding description and impact.
Root Cause.
The `rebalanceFunds` function in `FastAccessVault.sol` is publicly callable without any access control. This allows anyone to trigger the rebalancing, which can interfere with the vault's balance during redemption operations.
Description:
The `rebalanceFunds` function is intended to adjust the vault's balance to a target level based on the total collateral under custody. However, because it is external and has no access control, an attacker can call it at any time. In particular, an attacker can front-run a user's redemption transaction. If the vault's current balance is above the target, the rebalancing will transfer the excess to the custodian, potentially reducing the vault's balance below the amount required for the pending redemption. This causes the redemption to fail, resulting in a loss of gas fees and a denial of service for the user.

# Attack Vectors:
1. An attacker monitors the mempool for redemption transactions from the `iTryIssuer` contract.
2. When a redemption transaction is seen, the attacker checks the vault's current balance and the target balance. If the vault has excess funds, the attacker front-runs the redemption by calling `rebalanceFunds` to transfer the excess to the custodian.
3. The redemption transaction then fails due to insufficient balance in the vault.

# Impact:

1. Denial of service for legitimate redemptions.
2. Loss of user funds due to failed transactions (gas fees).
3. Potential for repeated attacks leading to a protocol-wide liquidity crisis or "bank run" scenario.
