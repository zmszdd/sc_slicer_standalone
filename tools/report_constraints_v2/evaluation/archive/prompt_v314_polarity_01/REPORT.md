# semantic-v3.14 开发复验报告（2026-09-19）

## 目的与边界

本轮只修改第二阶段，使用 `deepseek-flash` 检查三个通用问题：复合限定是否保留、I/V
方向是否正确、明确公式和数值是否进入可观察约束。GTE 与 Hybra 均已参与规则修改，属于
**开发回归**，不是独立留出集，不能据此计算总体准确率。未读取合约或 PoC，未修改第一、
第三阶段。

## 实现改进

- `semantic-v3.13` 增加 `all_of`/`any_of` 复合谓词及有单位的乘积关系，避免用一个未定义
  Boolean 代替全部性质。
- `semantic-v3.14` 增加 I/V 极性检查：安全公式必须表达正常意图，程序生成的 V 必须对应
  报告坏结果并直接否定 I。
- 要素提取必须保留报告明确给出的公式、比较方向、操作数及 expected/actual 数值。
- 已知非 action 的 `attack_steps` 引用会被移出冗余索引；无冲突的混合大小写 ID 可机械
  小写化。两类变化均写入审计文件，不修改陈述文本、P/I/V 或证据。
- DeepSeek 分块响应中断现作为可重试传输故障处理；完整性、证据、类型及数值错误仍拒绝。
- P 谓词中的符号必须由至少一个已选 P 陈述支持；允许多个 P 共享同一观测量，但不允许用
  impact 或 I 的符号冒充前提。

## 结论

当前程序已证明能够在真实 GTE 报告上完成“要素 → P/I/V → 形式约束 → Z3”，且 v3.14
修正了已观察到的 I/V 极性反转。Hybra 证明定量信息能够被保留、核心 I/V 能被表达，但
也证明数值 P 仍会被模型弱化；该例应保持拒绝，不能为了提高通过率放宽。当前只能报告
开发案例上的错误发现与修复效果，不能报告总体提取准确率。

下一关应冻结 v3.14，在未参与修改的新报告上分别统计：入口通过率、结构完成率、关键
P/I/V 语义正确率和误拦截率。Z3 结果继续只作为公式内部检查，不作为语义正确率。
