# semantic-v3.20 新报告盲测（5 例）· 呈现层修订版

> **修订说明**：本文件是 `REPORT.md` 的**呈现层修订**。测量数据、逐例评级、运行参数
> 一字未改，也没有重跑任何模型调用。相对原版只做三件事：
> ① **统一分母**并显式标出不可评项；② 每个比例附 **Wilson 95% 区间**；
> ③ 新增**误差归因表**（区分"要素层已错"与"形式化引入"）。
> 区间算法见附录 A，可直接复算。

## 0 · 读法（三项前置声明）

1. **本报告有两类指标，不可混读。**「工程指标」由机器判定（文件产出、校验、重放）；
   「语义指标」由助手逐例复核（判断，非事实）。原版把两者列在同一张表里，
   容易让人以为同等可靠。
2. **语义分项分母统一 = 5**（全部冻结报告）；无法评的记 `not_evaluable` **并计入分母**。
   只在有产物的子集上算比例会隐性地剔除最难的一例，因此可评子集另列作参考、不与总表混用。
3. **区间宽到跨 50% 时不要解读为优劣。** n=5 时一个比例的置信区间通常是 60 个百分点宽，
   点估计的精度是假精度。

## 3 · 误差归因汇总 ★本版新增，最重要

| 维度 | 公式层失败数（可评 4 例中） | 其中「要素层已错」 | 其中「要素层对、形式化引入」 |
| --- | ---: | ---: | ---: |
| P | 3 | **3 / 3** | **0** |
| I | 4 | **0 / 4** | **4 / 4** |
| V | 0 | — | — |

**读法（这决定了下一步该改哪里）：**

- **P 的瓶颈在第一步，不在形式化。** 公式层 P 的 3 个失败，**3 个都与要素层 P 的失败同源**；
  要素层 P 唯一 pass 的 Olas，其公式层 P 也是 pass → **形式化没有新增任何一个 P 错误**，
  它只是**放大**了要素层的 P 缺陷。
- **I 的瓶颈在第二步。** 5 例的要素层 I **全部 pass**，但公式层 I **4/4 变成 partial**
  → 这 4 个 I 缺陷**完全是形式化引入的**。
- **V 两层都稳。**

因此修复优先级应为 **① 要素提示词的 P（时间角色 + 触发事实完整性）
→ ② 形式化的 I（适用条件保留）**；而**不是**原版写的笼统"公式层 P"。

## 4 · 跨批次可比性警告 ★本版新增

| 批次 | 版本 | 要素 P | 要素 I | 要素 V | 要素重试 | 形式重试 | 报告集 |
| --- | --- | --- | --- | --- | ---: | ---: | --- |
| `prompt_v316_holdout_01` | v3.16 | 4 pass + 1 partial | 5/5 | 5/5 | 1 | **2** | 旧 5 例 |
| `prompt_v320_blind_03` | v3.20 | **2/5** | 5/5 | 5/5 | 1 | **1** | **新 5 例** |

两批**不可直接比较**，有两个独立原因：

1. **`formal_retries` 不一致（2 vs 1）**：本批的修复预算少一次，且与本批 GTE Spot
   那例「修复后语义正确却被 numeric guard 拒掉」的结局直接相关。
2. **要素提示词自 v3.16 起一字未改**，但要素层 P 从「4 pass + 1 partial」降到「2/5」。
   所以这个下降**不是版本回归**，只能是**报告难度不同 / 抽样波动 / 评审者或标准漂移**
   （报告集确定不同；评审标准尚未冻结成可执行检查，故也可能漂移）。

**结论：跨批次的 P 比率对比，必须同时声明报告集与评审标准都变了**，
否则会把难度差读成能力差。

## 5 · 局限与未做的对照（如实列出）

- **无阴性 / 阳性对照** → 无法给出评审者的检出率与误报率，「40%」缺少可解释性锚点。
  建议：取一例 pass 的试样机械反转 P 的方向，看能否检出；原样样本能否保持 pass。
- **单次运行** → 无法区分能力与抽样波动。历史实测中，同一 prompt、同一输入，
  同一调用曾出现本轮 2/2 失败而另一轮成功。建议同一批重复 k=3，报告**稳定率**。
- **评审者单方、未盲化** → `reviewer_kind: assistant_artifact_review`、
  `independent_gold: false`；评审可见 `route` 与版本号；无第二评审、无一致率。
  建议：剥掉版本号与 route，用 `prompts/definitions.py` 作冻结评分表，双评并报一致率。

## 7 · 下一步（按归因重排优先级）

1. **【第一步·P】** 要素层明确区分「执行前事实」与「动作后派生结果」，
   禁止 `claimable unchanged`、`ratio stays zero` 一类后置观察量进入 P。
2. **【第一步·P】** 要求要素层覆盖报告的关键攻击动作与排序，
   例如 `pair already exists because attacker mined first`。
3. **【第二步·I】** I 的适用条件必须保留报告中的数值界限或授权主体，
   不允许用宽泛 Boolean（`spot_price_manipulated`、`caller_is_any_address`）替代。
4. **【机械】** 把上述三条尽量变成自动检查，减少对人工复核的依赖：
   P 中符号的 `checkpoint` 必须早于 V 的观测点（抓「结果混入 P」）；
   P/I/V 若用布尔替换了报告中的数值符号则报警（抓「布尔退化」）；
   比对 `attack_steps` 的排序事实是否出现在 P（抓「缺攻击排序」）。
5. **【机械】** 调整 numeric guard：允许当前 DSL 无法表达的位运算关系
   作为显式、有证据的 Boolean，避免 GTE Spot 这类语义正确的候选被机械误拒。
6. **【流程】** 批处理相对输出路径已修复；后续须**在另一批新报告**上复验，
   不能用本批样例继续调分后再报盲测成绩。

## 附录 A · 区间算法（可复算）

```python
import math

def wilson(k, n, z=1.959963985):
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = (z / d) * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return max(0.0, c - h), min(1.0, c + h)
```

本文件中所有 `[Wilson 95%: a–b%]` 均由该函数对本表的 k/n 直接计算得出。
