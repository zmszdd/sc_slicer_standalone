Non–hour-multiple campaign durations accepted, stranding creator funds in Distributor

## Finding description and impact

Campaign durations are supposed to align to hourly epochs, but _createCampaign only enforces duration >= HOUR and never checks duration % HOUR == 0 (see DistributionCreator.sol#L247-L287). An operator can create a campaign with a duration like HOUR + 1, which passes all on-chain checks and pulls the creator’s funds into the Distributor. The off-chain engine expects integer-hour epochs; a non–hour-multiple is likely rejected or ignored, so no Merkle root is ever produced for this campaign. Result: the creator’s reward tokens are stranded in the Distributor with no on-chain recovery path (except governor sweep), violating the “campaign pre-deposit protection” and “creator autonomy” assumptions.
