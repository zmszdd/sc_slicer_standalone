EloCalculator.battleElo Update Rating Logic Inverted, Leading to Completely Incorrect Rating Calculation

## Finding description and impact

The `battleElo` function within the `EloCalculator` contract is responsible for simulating and calculating the final Elo ratings based on a series of battle results. This function calls the `ratingChange` function from the external library `Elo.sol` to obtain the rating change amount (`change`) for one party and a direction flag (`negative`) after a single battle.

**The core issue is:** When the `battleElo` function applies `change` and `negative` to update the internally simulated `eloA` and `eloB` scores, its logic is completely the reverse of what is expected.

Relevant code snippet:

According to the Elo rating mechanism, `Elo.ratingChange(eloB, eloA, ...)` calculates the rating adjustment for `eloB` relative to `eloA`. If `negative` is `true`, it typically signifies that `eloB`'s rating should decrease (e.g., `eloB` lost or performed below expectations).
* In this scenario (`negative = true`), the correct logic should be to decrease `eloB` by `change` (`eloB -= change`) and simultaneously increase `eloA` by `change` (`eloA += change`).
* However, the current code executes `eloA -= change` and `eloB += change`.

Similarly, when `negative` is `false` (indicating `eloB`'s rating should increase), the code's execution of `eloA += change` and `eloB -= change` is also incorrect.

**Impact:**
This logical inversion leads to the direction of Elo rating adjustments being completely wrong. The party that performs better or wins will see their rating decrease, while the party that performs worse or loses will see their rating increase. This fundamentally violates the core principle of the Elo rating system, which is to measure relative skill levels.

If any protocol functionality (such as rankings, matchmaking mechanisms, reward distribution, eligibility determination, etc.) relies on the Elo ratings calculated by this contract, these functions will operate based on entirely incorrect data. This will lead to severe consequences like distorted rankings, unfair matchmaking, and mismatched rewards, posing a high-risk threat to the integrity of core functionalities.
