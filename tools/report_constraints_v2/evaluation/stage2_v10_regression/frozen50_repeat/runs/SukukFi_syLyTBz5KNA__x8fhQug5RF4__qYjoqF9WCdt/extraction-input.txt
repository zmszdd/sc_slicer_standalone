Premature Removal from Active Set

## Finding description and impact


 
Users who have both pending and claimable deposits can become permanently invisible to the Investment Manager after claiming their fulfilled shares, causing their still-pending deposits to be ignored and potentially stuck forever. 
 
In the ERC7575VaultUpgradeable.sol: 
 
Same issue exists in the deposit(uint256 assets, ...) function. 

 

The vault removes a user from the activeDepositRequesters set as soon as they fully claim their claimable shares, without checking whether they still have pending deposits waiting to be fulfilled. If a user has both claimable and pending deposits, claiming the claimable portion makes them disappear from the active list → the investment manager may skip fulfilling their remaining pending assets → funds get stuck forever. 
 

Exploit Scenario: 

Alice calls requestDeposit(100). (Status: Pending: 100, ActiveSet: Yes) 

Manager calls fulfillDeposit(Alice). (Status: Pending: 0, Claimable: 100, ActiveSet: Yes) 

Alice calls requestDeposit(50). (Status: Pending: 50, Claimable: 100, ActiveSet: Yes) 

Alice calls deposit(100) to claim her shares. 

Result: The contract sees availableAssets == assets (100 == 100) and removes Alice from activeDepositRequesters. 

Consequence: Alice still has 50 pending assets, but she is no longer in the activeDepositRequesters list. The Investment Manager will not see her in the active set when looking for requests to fulfill. 

 

Impact  

Users with both pending and claimable deposits risk having their pending requests ignored or stuck indefinitely because claiming the claimable part removes them from the active tracking set used by the Investment Manager for fulfillment
