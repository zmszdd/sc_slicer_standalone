Quote-Denominated Fill Order Amount Tracking Bug

## Description
This bug exists in the `_matchIncomingOrder` [function](https://github.com/code-423n4/2025-07-gte-clob/blob/9f06332ebd4cfe2577d9eae81aeb58d3662ffccd/contracts/clob/CLOB.sol#L823-L827) in `CLOB.sol` where quote-denominated fill orders (`amountIsBase: false`) incorrectly track remaining amounts when lot-size flooring occurs.


The issue is in the `matchedAmount` [calculation logic](https://github.com/code-423n4/2025-07-gte-clob/blob/9f06332ebd4cfe2577d9eae81aeb58d3662ffccd/contracts/clob/CLOB.sol#L823-L827)

When `baseDelta != matchedBase` (which happens when lot-size flooring reduces the tradeable amount), the system incorrectly sets `matchedAmount = takerOrder.amount` (the full remaining quote amount) instead of `quoteDelta` (the actual quote amount consumed).

The incorrect `matchedAmount` is used to decrement the incoming order's remaining amount in both [bid](https://github.com/code-423n4/2025-07-gte-clob/blob/9f06332ebd4cfe2577d9eae81aeb58d3662ffccd/contracts/clob/CLOB.sol#L763) and [ask](https://github.com/code-423n4/2025-07-gte-clob/blob/9f06332ebd4cfe2577d9eae81aeb58d3662ffccd/contracts/clob/CLOB.sol#L797) matching loops. This over-subtraction causes the matching loop to terminate prematurely, preventing the order from continuing to match against additional liquidity.

For Fill-or-Kill orders, this creates a critical failure mode. The FOK validation check

This check passes because `newOrder.amount` has been incorrectly reduced to 0, even though dust quote amount remains unfilled. This violates the FOK guarantee that orders either execute completely or fail entirely.

Users receive fewer base tokens than their quote amount should purchase. Settlement uses the correct (smaller) `quoteDelta` and `baseDelta` values, but the user's order is marked as fully filled despite only partial execution.


Consider a bid fill order with:

- `amountIsBase = false`
- `lotSizeInBase = 1e18`
- `price = 1e18` (normalized)
- `remaining taker.amount = 2.5e18` (2.5 quote units)
- `maker base = 3e18`

The calculation proceeds as:

1. `potential_base = getBaseTokenAmount(price, 2.5e18) = 2.5e18`
2. `matchedBase = min(2.5e18, 3e18) = 2.5e18`
3. `baseDelta = floor(2.5e18 / 1e18) * 1e18 = 2e18` (lot-size flooring)
4. `quoteDelta = getQuoteTokenAmount(price, 2e18) = 2e18`
5. Since `baseDelta (2e18) != matchedBase (2.5e18), matchedAmount = takerOrder.amount = 2.5e18`

The order amount is reduced by 2.5 units, but only 2 units worth of base tokens are actually traded, resulting in a 20% loss of expected value.
