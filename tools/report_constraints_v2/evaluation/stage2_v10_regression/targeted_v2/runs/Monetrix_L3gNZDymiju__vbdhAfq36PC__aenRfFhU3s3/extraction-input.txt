Portfolio Margin Accounting Omits 0x811 Borrow Debt

# Summary

The Accountant counts Portfolio Margin supplied balances from HyperCore precompile 0x811, but it does not subtract Portfolio Margin borrow debt. A Vault account can therefore owe USDC borrow debt while Monetrix still reports the supplied collateral as full backing.

This creates false surplus. The normal yield flow can bridge, settle, and distribute that false surplus as yield, leaving USDM undercollateralized by the ignored borrow.

# Root Cause

PrecompileReader.suppliedBalance() decodes the 0x811 response as four uint64 words and returns only the fourth word:


HyperCore's `0x811` state contains both borrow and supply values. Monetrix adds the supply side into `_readL1Backing()` but never subtracts `borrow.value`.

https://hyperevmscan.io/address/0x0d547f267d9efc4b6601b255507120daff34a581#code


`bridgeYieldFromL1()` then trusts accountant.surplus() and does not reduce outstandingL1Principal, so ignored borrow debt can be converted into declared yield.

https://github.com/code-423n4/2026-04-monetrix/blob/3d94be1361ca01d959f9165a78f0d75c5657fe3e/src/core/MonetrixVault.sol#L247-L252


# Attack Path

1. Users deposit USDC and receive USDM.
2. Principal is bridged to HyperCore and held in Portfolio Margin / supplied positions.
3. The PM account borrows USDC against eligible collateral.
4. accountant.totalBacking() counts supplied collateral but ignores the borrow liability.
5. vault.yieldShortfall() treats the omitted borrow amount as surplus.
6. The Operator bridges that false surplus as yield.
7. settle() and distributeYield() route principal to the Foundation, Insurance Fund, and sUSDM as if it were real yield.

# Impact

USDM can become undercollateralized while the protocol still reports full backing.

The ignored borrow debt is effectively socialized to USDM holders, while the false surplus is distributed as yield.
