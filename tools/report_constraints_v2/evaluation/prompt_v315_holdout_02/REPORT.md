# semantic-v3.15 第二批独立小规模留出集报告

## 结论

本批 5 份冻结新报告均包含足够的触发条件、安全意图和直接影响，且均成功生成合法
结构化要素；但只有 1 份生成最终公式，工程完成率为 **1/5（20%）**。因此这次低完成率
主要不是报告信息不足，而是第二步形式计划生成与确定性校验之间仍不稳定。

唯一完整候选 Monetrix 的关系分类 `state_correspondence` 合理，但公式没有约束
`expected_decimals = usdm_decimals + decimals_offset`，同时把错误的
`reported_decimals = 6` 放入 P。严格 P/I/V 全部正确仍为 **0/1**。Z3 和离线重放通过仅表明
这套未充分定义的公式内部可执行，不能证明它忠于报告。

与第一批合并观察，10 份冻结报告中 9 份生成合法要素、5 份生成最终候选；5 份候选的
严格 P/I/V 全通过仍为 **0/5**。这个累计数字是小样本诊断结果，不是总体准确率。

## 冻结与输入

选择清单、报告哈希、Prompt 哈希和核心实现哈希见 [SELECTION.json](SELECTION.json)。本批

产出结果，因此应记为**适合输入未完成 4/5**，而不能归因于报告质量。

## 效率

- 外部模型调用/有效响应：24 次；
- 累计模型耗时：119.87 秒，平均约 5.00 秒/响应；
- 累计 tokens：102,944（prompt 80,617，completion 22,327）；
- Prompt cache hit tokens：51,072；
- Monetrix 离线复验：通过，额外模型调用为 0。

完成率低并非 API 超时：24 次调用均保存了 usage。主要成本来自四份失败报告反复执行到
形式化重试上限。

## 本批暴露的问题

1. **生成器与 DSL/分类约束不对齐**：模型能选出合理关系，却经常返回该类别不允许的模板。
2. **来源绑定粒度过粗**：合理观测量可能因来源覆盖形式不满足而被拒绝；另一方面，Olas
   说明不能简单放松校验，否则会放行没有 P 证据的关键条件。
3. **派生量缺少定义**：Monetrix 的 `expected_decimals` 有文字含义，却没有算术定义，导致
   公式看似完整、实则未表达报告结论。
4. **错误结果混入 P**：事实抽取没有稳定区分触发前提与漏洞状态/结果。
5. **JSON 鲁棒性仍不足**：GTE Spot 的有效方向最终因多余响应文本丢失。

## 下一步建议

保持本批结果和 v3.15 判据冻结。下一开发版本优先做三项通用修复：

1. 由程序按关系类别提供唯一允许的模板骨架，让模型只填条件、观测量和算术关系；
2. 增加“派生符号必须有定义表达式”检查，并将 bug 状态从 P 重分类为 V/根因；
3. 对多余 JSON 文本做受限解析恢复，但恢复后仍完整执行证据、类型和关系校验。

修复应先在本批失败案例做开发回归，再用第三批全新报告测工程完成率、要素证据支持、
公式忠实度和适合输入未完成率；不得用本批回归成绩冒充新留出集准确率。
