MEVCapture fee asymmetry between ExactIn and ExactOut swaps

## Finding description and impact


The `MEVCapture` extension charges an additional fee when swaps cross tick spacings, calculated as `additionalFee = ticksCrossed * poolFee`. This fee is designed to capture MEV from large swaps that significantly move the price. However, the fee calculation logic differs between ExactIn and ExactOut swaps. For ExactOut swaps, the code first removes the base pool fee from the input amount, and then calculates the additional fee on the reduced amount. This means the additional fee is computed on a smaller base. For ExactIn swaps, the code calculates the additional fee directly on the full output amount without any prior deduction of the pool fee. This inconsistency results in ExactIn users paying a higher effective fee than ExactOut users for equivalent trades. The difference becomes more pronounced as more tick spacings are crossed and the additional fee grows larger. The PoC demonstrates this with two identical pools using 1% pool fee and tickSpacing of 10. An ExactIn swap paying 100,000 tokens receives a certain output. An ExactOut swap requesting that same output only costs 95,209 tokens - a difference of 4,790 tokens (4.79%).

### Impact
- ExactIn users are overcharged compared to ExactOut users for identical effective trades
- The discrepancy scales with tick spacings crossed
- Sophisticated traders gain an advantage by always using ExactOut swaps
