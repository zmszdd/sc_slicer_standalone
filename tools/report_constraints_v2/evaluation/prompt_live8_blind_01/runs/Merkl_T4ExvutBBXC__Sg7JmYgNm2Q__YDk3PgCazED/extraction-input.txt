Denial of Service via Perpetual Dispute Loops due to Governance Lock

Finding description and impact

Description

The Distributor contract implements a dispute mechanism that pauses Merkle tree updates when disputer != address(0). While this mechanism is intended to prevent malicious root updates, it allows a malicious actor to permanently freeze the protocol by perpetually renewing disputes.

The vulnerability relies on two factors:

    Immediate Re-dispute: Upon resolveDispute(false) execution, the disputer is reset to address(0). An attacker can back-run this transaction in the same block (or submit in the next block) to call disputeTree again, immediately re-locking the contract.

    Governance Lock: The Governor is unable to mitigate the attack by increasing the disputeAmount. The function setDisputeAmount reverts if disputer != address(0).

Since the attacker can maintain the disputer != address(0) state nearly 100% of the time (except for the atomic moment of resolution), the Governor calls to setDisputeAmount will consistently revert. This creates a race condition where the attacker can block parameter updates indefinitely at a linear cost (e.g., current disputeAmount per cycle).

Impact

    Permanent Denial of Service: Reward distributions are halted. The updateTree function remains inaccessible.

    Governance Paralysis: Administrators cannot adjust dispute parameters (disputeAmount, disputeToken) to make the attack economically unviable.
