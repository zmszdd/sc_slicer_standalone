Batch Transfer Functions Bypass Pause Mechanism

## Vulnerability Details

### Description

The WERC7575ShareToken contract implements a pause mechanism to halt token transfers during emergencies or security incidents. The standard `transfer` and `transferFrom` functions properly include the `whenNotPaused` modifier, ensuring they revert when the contract is paused. However, the `batchTransfers` and `rBatchTransfers` functions omit this critical modifier, allowing bulk token movements to continue even when the contract owner has explicitly paused the token.

The pause functionality exists as a safety mechanism for situations where token transfers must be immediately stopped, such as when a vulnerability is discovered, during protocol upgrades, or when suspicious activity is detected. By pausing the contract, administrators expect all token movement to cease until the situation is resolved. The batch transfer functions undermine this expectation entirely, as they provide an alternative pathway for moving tokens that remains operational regardless of the contract's paused state.

### Impact

The impact is significant because the pause mechanism represents the protocol's last line of defense during security incidents. The `batchTransfers` function allows the validator to execute multiple transfers in a single transaction, moving tokens between arbitrary addresses. When the contract is paused, a compromised or malicious validator can still use these functions to move tokens, completely bypassing the emergency brake the protocol owner attempted to engage. This defeats the purpose of the pause functionality and could allow fund extraction during the critical window when administrators believe transfers have been halted. The inconsistency between single and batch transfer pause behavior also creates confusion about the contract's security guarantees.
