The dependency of ShareTokenUpgradeable::unregisterVault() on (totalCancelDepositAssets == 0) is incorrect

## Finding description and impact
For the owner to unregister a vault, one of the condition that should be satisfied is `metrics.totalCancelDepositAssets != 0`. This variable states that user deposited some asset to the vault and not requesting the admin to cancel their deposits so they can withdraw they assets back. It occur in 3 stages.
- User calls cancelDepositRequest()
- Protocol approves using fulfillCancelDepositRequest()
- User withdraws using claimCancelDepositRequest()

All the above flow is not dependent on the `shareToken`. Even if the vault is unregistered, the above flow can function. So, the dependency of `ShareTokenUpgradeable::unregisterVault()` on `totalCancelDepositAssets` is incorrect. As now if there is some user who never calls `ERC7575VaultUpgradeable::claimCancelDepositRequest()` the protocol can never unregister this vault.
