## [H-01] Epoch boundary lock creation captures previous epoch rewards via inclusive timestamp snapshot

#### Description:
[claimRewards()](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/protocol/emissions/TrustBonding.sol#L361) computes rewards for `prevEpoch = currentEpoch - 1`. The user's reward share is determined by their balance at `epochTimestampEnd(prevEpoch)`:

- [userBondedBalanceAtEpochEnd](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/protocol/emissions/TrustBonding.sol#L212) → `_balanceOf(account, _epochTimestampEnd(epoch))`
- [totalBondedBalanceAtEpochEnd](https://github.com/code-423n4/2026-03-intuition/blob/314b7d4d9ccbaf27e4484a6c0706af83d3f75f36/src/protocol/emissions/TrustBonding.sol#L199) → `_totalSupply(_epochTimestampEnd(epoch))`

Two properties create the vulnerability:

1. **Shared boundary timestamp:** `epochTimestampEnd(N)` equals `epochTimestampStart(N+1)` since `_calculateEpochTimestampEnd(epoch) = START + epoch * LENGTH + LENGTH`, which is identical to `_calculateEpochTimestampStart(epoch + 1) = START + (epoch + 1) * LENGTH`.

2. **Inclusive VotingEscrow lookup:** The binary search in `_find_user_timestamp_epoch` uses `<=` comparison (`user_point_history[addr][_mid].ts <= _ts`), so a checkpoint created exactly at the boundary timestamp is included in the lookup for epoch N's end.

Therefore, a user who creates a lock at the exact epoch boundary (`block.timestamp == epochTimestampEnd(N) == epochTimestampStart(N+1)`) will:
- Be in epoch N+1 (so `currentEpoch = N+1`, `prevEpoch = N`)
- Have their checkpoint at ts = boundary included in the epoch N balance snapshot
- Successfully claim epoch N rewards despite never being bonded during epoch N

### Impact

An attacker can capture prior-epoch emissions by timing lock creation to the exact epoch boundary. This directly dilutes rewards of honest stakers who were bonded throughout the earning epoch. In the PoC, the attacker captures ~50% of epoch 0 emissions (~504.85 ETH) by creating a lock at the boundary and claiming in the same transaction.
