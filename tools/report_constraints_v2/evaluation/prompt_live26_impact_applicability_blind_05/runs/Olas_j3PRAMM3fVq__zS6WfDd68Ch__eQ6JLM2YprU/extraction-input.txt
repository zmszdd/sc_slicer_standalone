Oracle Bypass via Stale Observation and Failure Fallback

## Finding description and impact

The protocol's safety reliance on `checkPoolAndGetCenterPrice` creates a false sense of security. 


The `checkPoolAndGetCenterPrice` function contains a logic flaw where it returns `centerSqrtPriceX96` (Spot Price) directly, bypassing all deviation checks under two conditions:

*  1. When `oldestTimestamp + SECONDS_AGO < block.timestamp` (TWAP window expired).


*  2. When the oracle query fails (`!success`).


The protocol's safety reliance on `checkPoolAndGetCenterPrice` creates a false sense of security. The function contains a critical logic flaw where it silently falls back to the `centerSqrtPriceX96` (Spot Price), bypassing all deviation checks and providing any downstream contract (like `LiquidityManager`) with a poisoned baseline.
