Validator Can Bypass Emergency Pause on Settlement Layer

## Finding description and impact

**Description**: The `WERC7575ShareToken` contract inherits from OpenZeppelin's `Pausable` and implements a `pause()` function, which is intended to serve as a circuit breaker during emergencies (e.g., smart contract exploits, key compromises, or critical bug discoveries). While standard ERC20 state-changing functions such as `transfer`, `transferFrom`, `mint`, and burn are correctly protected by the whenNotPaused modifier, the specialized bulk settlement functions—batchTransfers and rBatchTransfers—are explicitly missing this protection.

Impact: The `batchTransfers` and `rBatchTransfers` functions constitute the primary operational engine of the protocol, handling high-volume settlement transactions. If the Validator key is compromised or a logic error is found within the settlement accounting, the Protocol Owner would intuitively trigger the pause() function to secure user funds.

However, because these functions lack the whenNotPaused modifier, the pause would fail to stop the Validator. A malicious actor holding the Validator key could continue to execute batch transfers, move liquid funds, and corrupt restricted balance (rBalance) accounting even while the contract claims to be "paused." This completely negates the utility of the emergency stop mechanism for the protocol's most critical operations.
