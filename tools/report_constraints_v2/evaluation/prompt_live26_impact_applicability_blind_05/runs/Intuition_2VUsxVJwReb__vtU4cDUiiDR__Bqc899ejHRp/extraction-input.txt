ProgressiveCurve.previewWithdraw reverts at production minShare floor violating PR #136 low-share invariant

## Finding description and impact

`ProgressiveCurve.previewWithdraw` (lines 148–158) reverts when `totalShares` is at the production floor (`minShare = 1e6`) and `assets` is a small value (e.g., 1 wei). This occurs because `PCMath.square(wrap(totalShares))` rounds down to zero in UD60x18, while `PCMath.divUp(wrap(assets), HALF_SLOPE)` rounds up to at least 1, leading to an underflow in `sub(0, 1)`. The function should return 0 shares in such edge cases, as per the invariant stated in the contest: *"redeem/convert-to-assets path uses consistent conservative rounding and must not revert in low-share edge cases where result should be zero (PR #136 behavior)."* The revert violates this invariant, potentially breaking integrations that rely on `previewWithdraw` for estimations or UIs.

**Impact:** The function becomes unusable for valid low-share inputs, affecting availability and correctness of the curve math. While no funds are directly at risk, the protocol's intended behavior is broken.
