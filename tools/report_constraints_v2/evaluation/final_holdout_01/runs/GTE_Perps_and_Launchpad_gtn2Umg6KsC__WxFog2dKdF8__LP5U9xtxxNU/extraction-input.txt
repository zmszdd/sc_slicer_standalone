Launchpad Pair Creation Vulnerability

## Finding Description and Impact

The `Launchpad` contract's `_createPairAndSwapRemaining` function is vulnerable to a front-running attack where a malicious user can create a Uniswap V2 pair for the token and quote asset before the `buy` function triggers graduation. The function uses a `try-catch` block to handle the `UniswapV2: PAIR_EXISTS` error from `uniV2Factory.createPair`. If the pair creation reverts, the catch block executes without updating the `pair` variable, causing it to retain the value returned by `uniV2Factory.pairFor(token, data.quote)`. However, if a malicious user creates the pair first, the address returned by `pairFor` differs from the actual pair created by the malicious user. This mismatch causes subsequent operations in `_createPairAndSwapRemaining` to fail, as they operate on an incorrect pair address, leading to a transaction revert.

**Impact**: 

This vulnerability prevents the `buy` function from completing the graduation process, blocking liquidity locking in `LaunchpadLPVault` and reward distribution. The attack is trivial to execute, as any user can call `createPair` on the `GTELaunchpadV2PairFactory`, making it a critical disruption to the protocol's core functionality.
