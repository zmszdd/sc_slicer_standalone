Missing EIP-1271 Support in TrailsIntentEntrypoint

## Finding description and impact
The ``TrailsIntentEntrypoint contract`` is designed to work with Sequence v3 wallets (smart contract wallets) but uses ECDSA.recover() for signature validation, which only works with EOA (Externally Owned Account) signatures. This makes the contract completely incompatible with its intended user base - smart contract wallets.

## Root Cause
This fails when user is a smart contract wallet (like Sequence), because:
- The signature is produced by the wallet owner (EOA).
- ECDSA.recover() returns the owner, not the wallet address.
- recovered != user → revert.

Smart wallets require EIP-1271 (isValidSignature) to validate signatures.


## Impact
The contract is completely unusable by its intended primary user base as stated in the doc: Sequence v3 wallets.
- Users with smart wallets cannot deposit via intents.
- All off-chain signed intents fail on-chain.
- The core value proposition ("deposit to intent addresses with signed intents") fails silently.
- Users may lose gas and believe the system is broken.
