Malicious trader can realize stale-price arbitrage against Covenant market users

## Summary
The absence of an L2 sequencer uptime gate in the Chainlink curator path will cause stale-price valuation for Covenant market users as a malicious trader will wait for a sequencer outage, let the feed go stale, and execute trades before the data refreshes.

## Root Cause
In [src/curators/oracles/chainlink/ChainlinkOracle.sol:15](src/curators/oracles/chainlink/ChainlinkOracle.sol:15) the Chainlink adapter simply inherits Euler’s implementation, which only enforces `maxStaleness` against the feed heartbeat and never checks the L2 sequencer status. When combined with [src/curators/oracles/CrossAdapter.sol:52](src/curators/oracles/CrossAdapter.sol:52), which forwards quotes without additional gating, the router accepts quotes so long as they fall inside the configured heartbeat window—even if the sequencer is down and the data is no longer trustworthy. This design omission leaves the protocol blind to sequencer restarts and the recommended post-outage grace period.

1. Chainlink oracle exposes quotes without sequencer awareness:
   - Only the heartbeat window is respected; there is no sequencer uptime feed check or grace-period enforcement.

2. CrossAdapter forwards the quote directly to markets:
   - There is no additional sentinel or freshness validation; the stale Chainlink quote propagates unchanged.

3. LatentSwap consumes the stale price to value positions:
   - User balances are updated using the stale oracle output, enabling profitable arbitrage against honest participants.

## Impact
Users trading or maintaining positions during the outage can be forced into unfair liquidations or lose value relative to attackers who trade against the stale quote.
