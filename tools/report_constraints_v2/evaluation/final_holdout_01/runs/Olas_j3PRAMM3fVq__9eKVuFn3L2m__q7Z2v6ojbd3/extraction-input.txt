validatePrice() computes TWAP as the current spot price

## Finding description and impact

Root Cause: validatePrice() reconstructs a “cumulative price” using getPrice() and elapsedTime, forcing timeWeightedAverage == tradePrice and neutralizing the slippage check.

Toy example:

In block N, an MEV actor manipulates the Uniswap V2 pool reserves and ends the block with an off-market spot price.
In block N+1, the actor calls BuyBackBurner.buyBack() using protocol-held secondToken.
UniswapPriceOracle.validatePrice() returns true because the computed “TWAP” equals the current spot price.
BuyBackBurnerUniswap._performSwap() executes with amountOutMin = 0, allowing execution at the manipulated price.
Location: UniswapPriceOracle.sol#L53-L91

BuyBackBurner supports permissionless V2 buybacks of OLAS using protocol-held funds via buyBack(address,uint256). Before swapping, _buyOLAS() enforces slippage protection through IOracle(poolOracle).validatePrice(maxSlippage). The V2 swap itself is executed with amountOutMin = 0 in BuyBackBurnerUniswap._performSwap().

However, UniswapPriceOracle.validatePrice() does not compute a TWAP. It reads cumulativePriceLast and blockTimestampLast from the pair, then sets tradePrice = getPrice(), computes cumulativePrice = cumulativePriceLast + tradePrice * elapsedTime, and finally computes timeWeightedAverage = (cumulativePrice - cumulativePriceLast) / elapsedTime (validatePrice()). This algebraically forces timeWeightedAverage == tradePrice whenever elapsedTime > 0, which makes derivation == 0 and causes validatePrice() to accept any spot price. The only exception is the same-timestamp guard (block.timestamp == blockTimestampLast) where the function returns false, which does not provide multi-block manipulation resistance. As a result, price manipulation around buyBack() is not meaningfully constrained by the intended oracle check, and swaps can execute at materially unfavorable prices due to amountOutMin = 0.
