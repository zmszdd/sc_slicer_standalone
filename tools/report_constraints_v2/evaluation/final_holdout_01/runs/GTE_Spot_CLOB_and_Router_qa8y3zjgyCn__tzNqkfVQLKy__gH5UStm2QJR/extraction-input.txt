Off-by-One Error in Fee Rate Indexing Prevents Access to Valid Fee Tiers

## **Finding description and impact**

**Root Cause:**
The `PackedFeeRatesLib::getFeeAt` function contains an off-by-one error in its bounds checking that prevents access to the last valid fee tier. The vulnerable code is:


The function incorrectly limits access to index 14 maximum, when it should allow up to index 15. This creates an inconsistency where 16 fee rates can be packed but only 15 can be accessed.

**Flow:**
- **Constant**: `U16_PER_WORD = 16` indicates 16 fee rates can fit in a uint256
- **Packing**: `packFeeRates()` accepts up to 16 fee rates (indices 0-15)
- **Access**: `getFeeAt()` only allows indices 0-14 due to `index >= 15` check
- **Result**: The 16th fee rate (index 15) becomes inaccessible after packing
- **Deployment failure**: Systems expecting 16 fee tiers cannot access the highest tier
- **Feature limitation**: Fee tier systems limited to 15 tiers instead of 16
- **Integration issues**: Components using maximum fee tier index will fail

1. **Data accessibility**: Successfully packed data becomes partially inaccessible
2. **System inconsistency**: Packing allows 16 rates, accessing allows only 15
3. **Integration failures**: Functions expecting full tier access will revert
4. **Wasted storage**: 16th fee tier data is stored but never usable

## **Recommended mitigation steps**

**Primary Fix: Correct Bounds Check**

**Alternative Fix: Consistent Documentation**
