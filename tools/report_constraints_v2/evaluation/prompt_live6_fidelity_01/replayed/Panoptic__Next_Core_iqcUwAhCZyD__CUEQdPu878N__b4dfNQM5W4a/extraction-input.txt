`BuilderWallet.init()` is permissionless and re-initializable, allowing anyone to take over `builderAdmin` and sweep builder fees

## Finding description and impact

`BuilderWallet` is the fee recipient for “builder split” commissions. It exposes:

- `init(address _builderAdmin)` (external) which writes `builderAdmin` with **no access control** and **no one-time initialization guard**.
- `sweep(address token, address to)` which allows the current `builderAdmin` to transfer the wallet’s full token balance.

Because `init()` is callable by anyone at any time, any attacker can:

1. Call `BuilderWallet.init(attacker)` to overwrite `builderAdmin`.
2. Call `BuilderWallet.sweep(token, attacker)` to drain any assets held by the wallet.

This is especially impactful because the protocol can route commissions directly to `riskParameters.feeRecipient()` (the builder wallet address) during option mint/burn settlement:

- In `CollateralTracker.settleMint`, when `riskParameters.feeRecipient() != 0`, shares are split and transferred to both `riskEngine()` (protocol split) and `feeRecipient` (builder split).
- In `CollateralTracker.settleBurn`, when `riskParameters.feeRecipient() != 0`, shares are similarly split and transferred.

As a result, any accumulated builder fees (shares/tokens) that reach the `BuilderWallet` can be stolen permissionlessly, causing direct loss of funds intended for builders (and any downstream accounting/fee distribution relying on this mechanism).
