Public `ServiceNft.updateImpact` Function Allows Anyone to Reset Service and Dataset Impact Scores to Zero

## Finding description and impact

In the `ServiceNft` contract, the `updateImpact` function is intended to calculate and update the impact scores (`_impacts`) for a service NFT (`proposalId`) and its associated dataset (`datasetId`). Although designed to be called internally by the `mint` function, its visibility is incorrectly declared as `public`, allowing it to be called by any external account.

This configuration leads to the following critical issues:

1.  **Improper Access Control**: The `updateImpact` function is `public` and lacks necessary access control checks to restrict callers.
2.  **Incorrect Dependency on Post-Execution State**: When an external account calls `updateImpact` *after* the `mint` function has completed execution, the function reads an unexpected state, rendering the calculation logic ineffective. The specific flow is as follows:
    * After the `mint` function successfully executes `updateImpact`, it records the current `proposalId` as the latest service for its core (`_cores[proposalId]`) via `_coreServices[virtualId][_cores[proposalId]] = proposalId;` (L86).
    * Subsequently, when an external caller triggers `updateImpact(virtualId, proposalId)` again, the internal read `prevServiceId = _coreServices[virtualId][_cores[proposalId]]` (L96) will fetch `proposalId` itself, because the state has already been updated by `mint`.
    * Therefore, when calculating `rawImpact = (_maturities[proposalId] > _maturities[prevServiceId]) ? _maturities[proposalId] - _maturities[prevServiceId] : 0;` (L97-L99), it effectively computes `_maturities[proposalId] - _maturities[proposalId]`, which always results in 0.
3.  **Impact Scores Reset to Zero**: Because the calculated `rawImpact` is 0, the function proceeds to execute `_impacts[proposalId] = rawImpact;` (L103) and (if `datasetId > 0`) `_impacts[datasetId] = (rawImpact * datasetImpactWeight) / 10000;` (L105). This forces the impact scores (`_impacts`) of the service NFT (`proposalId`) and its associated dataset NFT (`datasetId`) to be set to 0.

**Impact:**
Any external user can exploit this vulnerability by calling the `updateImpact` function to reset the impact scores of any existing service NFT and its associated dataset to zero. The impact score is a core metric for measuring contribution value and directly affects reward distribution, reputation systems, and the proper functioning of other key protocol mechanisms. Allowing arbitrary users to corrupt this critical data severely undermines the protocol's fairness and incentive effectiveness, constituting a high-risk security vulnerability.
