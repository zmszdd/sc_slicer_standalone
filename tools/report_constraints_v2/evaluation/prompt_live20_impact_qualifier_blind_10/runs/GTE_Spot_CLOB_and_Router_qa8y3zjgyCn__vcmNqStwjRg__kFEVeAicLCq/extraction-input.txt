Order Book Linked List Corruption Due to Improper Storage Update of order in _updateLimitPostOrder

## Finding description and impact
The vulnerability originates in the `_updateLimitPostOrder` function where new orders are linked into the order book's doubly-linked list. The critical error occurs when setting the previous order reference:
The order parameter is passed as a memory variable, but the function modifies `order.prevOrderId` which only affects the temporary memory copy, not the actual storage. This creates a disconnect in the linked list structure where:

- The previous tail order properly points forward to the new order
- The new order fails to point backward to the previous tail order in storage

## Impact:
This corruption leads to several severe consequences:
1) #### Order Book Integrity Failure 
 - The linked list becomes partially one-directional
 - Traversal from head to tail works, but reverse traversal fails
 - Orders appear orphaned
2) #### Order Removal Corruption
Removing an order with missing prev reference causes:
- Incorrect head order reassignment in the limit price struct
- Permanent loss of preceding orders
3) #### Operational Failures
- Orders become unfillable due to broken links
- Cancellation attempts may affect wrong orders
- Price level accounting becomes inaccurate
- Potential loss of funds as orders get "stuck"
- Corruption propagates as more orders are added/removed
