Redeem Validation Vulnerability - Protocol Fee Theft

### Description

The `redeem` function in the Covenant contract contains a validation flaw in the `checkRedeemOutputs` function. The validation checks that the redeem amount does not exceed the current `baseSupply`, but fails to account for protocol fees that will be deducted during the state update. This allows users to redeem more tokens than should be available after protocol fees are accounted for, effectively stealing accrued protocol fees.

  

### Impact

- **Protocol Fee Theft**: Attackers can redeem the full base supply amount even when protocol fees have accrued, stealing fees that should belong to the protocol

### Internal Pre-conditions

1. Protocol fees must be configured for the market (non-zero fee rates)

2. Protocol fees must have accrued over time (market state updated after time has passed)

3. User must have sufficient synth tokens (aTokens/zTokens) to attempt a full redeem

  

### External Pre-conditions

1. Market must be active and not paused

2. User must have minted synth tokens previously

3. Sufficient time must have passed for protocol fees to accrue

  

### Attack Path

1. **Setup**: Attacker mints tokens to establish base supply in the market

2. **Fee Accrual**: Time passes, allowing protocol fees to accrue and reduce available base supply

3. **Exploit**: Attacker redeems all their synth tokens, requesting the full current base supply amount

4. **Validation Bypass**: `checkRedeemOutputs` validates against the current base supply (ignoring accrued fees)

5. **State Update**: Contract deducts both the redeem amount AND protocol fees, but validation allowed more than available

6. **Result**: Attacker receives full redeem amount, protocol fees are effectively stolen
