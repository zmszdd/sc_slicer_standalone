Vulnerability details

Finding description and impact

Root Cause In 
AtomWallet.sol
, the abstract account intercepts ERC-4337 validateUserOp requests through _validateSignature and subsequently calls extractValidUntilAndValidAfter to decode transaction expiration bounds from the first 24 bytes of the callData payload.

To achieve this, the contract attempts to slice the calldata into 12-byte chunks and dynamically decodes them using abi.decode:

solidity
validUntil = abi.decode(callData[:12], (uint256));
validAfter = abi.decode(callData[12:24], (uint256));
This is fundamentally invalid in Solidity. abi.decode strictly enforces EVM ABI encoding specifications. For a statically-sized type like uint256, the EVM expects exactly 32 bytes (1 padded word) of input data. Providing a 12-byte slice (callData[:12]) violates length bounds-checking.

As a result, abi.decode throws an out-of-bounds InsufficientDataBytes error and guarantees a revert on every execution attempt.

Impact Because extractValidUntilAndValidAfter is inextricably linked to the core _validateSignature ERC-4337 flow, this single strict bounds violation causes every single validateUserOp sequence to crash.

The transaction EntryPoint evaluator will irrevocably reject all relayed/gasless operations. This permanently locks all users out of ERC-4337 execution abstractions globally across the protocol and completely bricks the AtomWallet smart wallet infrastructure.
