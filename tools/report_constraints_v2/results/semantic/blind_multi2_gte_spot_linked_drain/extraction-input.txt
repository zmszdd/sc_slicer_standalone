Cancelling an order X can cancel all the orders preceeding the X with same price ; can make the orderBook always empty

## Finding description and impact

While adding a new Order to the orderBook , it doesnt store the `order.prevOrderId` to the storage. And hence, every Orders  always has its `prevOrderId`  set as null. 

The Impact is when a user cancel their Order, all the orderd  preceeding that order will also get cancelled considering all orders are of same limit price and the limit.headOrder is made to null. When an incomingOrder tries to find matching order, [orders[limit.headOrder]](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L747) will return null Order and breaks the loop because of zeroCostTrade. So an atacker can make the orderBook always empty by just creating an order for each price and then cancel it with minLimitBaseAmount. 


fn `addOrderToBook()` initially calls `_updateBookPostOrder(self, order)` where it update the `self.bidLimit[order.price]` . Apart from that it also stores the new order to the storage which is actually an issue here. 


Then the fn calls, `_updateLimitPostOrder(self, limit, order)`. Here one of the parameter passed is memory variable `order`. And later in the fn , mem var `order` has been updated. 


But the updated `order` has not been stored in the storage and fn exits simply. 
Hence all the new Orders will be added with its `prevOrderId` = `0`;
