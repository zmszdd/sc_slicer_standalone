Incorrect Handling of Zero in `Float128::sqrt` Function

## Finding description and impact


The `sqrt` function in the floating point library contains an implementation flaw when handling a zero input. Instead of returning an encoded representation of 0 (i.e. √0 = 0), the function executes the `stop()` opcode. This causes the contract to halt execution without returning any data, potentially breaking downstream computations that rely on a proper square root result.

The `stop()` opcode halts the EVM execution immediately and returns no data. However, mathematically √0 should return 0. This leads to a mismatch between expected and actual behavior.



### Impact
- **Incorrect Return Value:** The absence of a return value for zero violates mathematical expectation (i.e., √0 ≠ 0).
- **Execution Termination:** The abrupt termination due to `stop()` can disrupt contract logic, potentially causing unintended reverts or contract-level errors when zero is processed.
- **Potential Denial-of-Service:** If parts of the system rely on `sqrt` to return a valid value for zero, an attacker or faulty data input might trigger a halt in execution, leading to Denial-of-Service (DoS).


**Expected Behavior**:
  - `sqrt(0)` should return a valid `packedFloat` representing zero (e.g., mantissa = 0, exponent = 0).
