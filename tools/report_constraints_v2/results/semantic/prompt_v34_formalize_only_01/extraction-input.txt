FOK Orders Incorrectly Revert on Dust Amounts Violating Protocol Specification

## Finding description and impact

Fill-or-Kill (FOK) orders incorrectly revert when any amount remains unfilled, including acceptable dust amounts. According to the protocol's documentation, FOK orders should not revert if only the amount rounded off due to lot size constraints is left unfilled.

From the README:
> "FOK fill orders *should* not revert if only the amount rounded off is left unfilled, and the user is not charged for the dust."

However, the current implementation reverts on any unfilled amount regardless of whether it's just dust from lot size rounding:


This breaks core CLOB functionality by making legitimate FOK orders fail unnecessarily. Users cannot execute valid trades when small dust amounts remain unfilled due to lot size constraints, reducing protocol availability and contradicting the intended behavior.
