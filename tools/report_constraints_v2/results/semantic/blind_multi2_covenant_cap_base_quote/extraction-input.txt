Default noCapLimit Uses Base Token Instead of Quote Token

## Finding description
In the `LatentSwapLEX` contract, the `initMarket()` function is responsible for initializing the new market configuration, including setting the `noCapLimit` parameter within `LexConfig`. According to the public documentation (`ILatentSwapLEX.setDefaultNoCapLimit`) and code comments, the default `noCapLimit` is intended to be mapped per quote token, as liquidity risk and operational requirements are typically determined by the denominated asset (e.g., USDC, DAI, USDT).

However, the current implementation retrieves the value from the `tokenNoCapLimit` mapping using `marketParams.baseToken` instead of `marketParams.quoteToken`:
As a result, `LexConfig.noCapLimit` for each new market does not reflect the default policy based on the quote token, but instead follows the base token. This creates inconsistencies across markets that use the same quote token but different base tokens.

The root of the problem is that the fifth parameter passed to `LatentSwapLEX.initMarket()` in `LatentSwapLogic.getInitMarketInfo()` is derived from `tokenNoCapLimit[marketParams.baseToken]`. The `tokenNoCapLimit` mapping itself is set via `setDefaultNoCapLimit()`, which, according to the documentation, assumes it accepts the quote token.

## Impact
Mint/redeem limit policies are inconsistent, where two markets with identical token quotes can have different noCapLimits. Admins cannot enforce centralized policies per token quote, which would make some markets too loose (bypass mint caps) or too tight (fail to serve users). Users can choose specific base tokens to obtain higher noCapLimits, then mint large amounts of liquidity when it should be restricted.

## Recommendation
Change the default fetch by using `quoteToken` during market initialization.
