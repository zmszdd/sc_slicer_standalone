veNFT can be transferred to address(0), permanently losing locked HYBR tokens

The `VotingEscrow` contract allows veNFTs to be transferred to `address(0)`, which permanently locks the underlying HYBR tokens. The documentation says it should revert, but the code doesn't check for zero address.

---

## Vulnerability Details

### The Bug

The `_transferFrom` function doesn't check if the recipient is `address(0)`. The documentation says it should revert, but it doesn't.

**Vulnerable Code**:

**What happens when transferred to address(0)**:
- veNFT ownership goes to `address(0)`
- Locked HYBR stays in contract
- No one can withdraw it
- Tokens are lost forever

---

## How This Can Happen

**User makes typo**:
- Wants to send to: `0x1234...5678`
- Types: `0x0000...0000` (address(0))
- veNFT goes to address(0), HYBR locked forever

**Contract bug**:
- Integration contract has uninitialized address
- Calls `transferFrom(user, address(0), tokenId)`
- User loses veNFT and locked HYBR

**Malicious operator**:
- User approved operator for convenience
- Operator transfers to address(0)
- User's funds stolen

**2. ERC721 standard requires it**:
