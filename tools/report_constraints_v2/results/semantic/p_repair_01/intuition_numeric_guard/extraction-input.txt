OffsetProgressiveCurve Panics at Full Withdrawal When offset18 < 1e9

## Finding description and impact

##Description

In OffsetProgressiveCurve.sol, an arithmetic underflow ensures users cannot withdraw their full deposit if the curve was initialized with an offset18 parameter smaller than 1e9.



When initialize stores the OFFSET18 parameter, it calculates the raw parameter OFFSET = PCMath.divDown(OFFSET18, 1e18). If OFFSET18 is less than 1e18, OFFSET strictly evaluates to 0. During deposit and withdrawal calculations, this truncated OFFSET influences internal rounding mechanics differently than ProgressiveCurve.



When a user attempts a full withdrawal:

The conversion rounds up the cost: inner = PCMath.mulDivUp(assets, SLOPE, 1e18) + PCMath.square(OFFSET). The offset squares to 0.


The comparison squaredShares = PCMath.square(totalShares + OFFSET) also strictly drops the OFFSET modifier.


This mathematical construction mirrors ProgressiveCurve, retaining the strict inequality squaredShares < inner.


Therefore, subtracting shares = squaredShares - inner produces a deterministic PANIC(0x11) arithmetic underflow.





##Impact

Any OffsetProgressiveCurve instantiated with offset18 < 1e9 collapses in mathematically equivalent conditions to ProgressiveCurve. Users will be permanently blocked from fully closing their positions, causing trapped funds whenever liquidating assets.
