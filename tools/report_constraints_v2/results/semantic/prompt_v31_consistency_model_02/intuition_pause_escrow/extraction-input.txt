### Description

`TrustBonding` exposes an emergency pause, but only `claimRewards()` is guarded by `whenNotPaused`. The inherited `VotingEscrow` entry points such as `create_lock()`, `increase_amount()`, `increase_unlock_time()`, and `withdraw()` never consult `paused()`, so core escrow state transitions remain live while the contract is paused.

### Impact

During an incident, the protocol cannot actually freeze lock creation, lock modification, or withdrawals even though the pause flag is set. This weakens emergency response and allows reward-relevant state to keep changing while operators believe the bonding contract is paused.
