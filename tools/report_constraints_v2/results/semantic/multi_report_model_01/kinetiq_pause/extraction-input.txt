## Finding description and impact

**Description:**
The `confirmWithdrawal` and `batchConfirmWithdrawals` functions in the `StakingManager` contract allow users to finalize queued HYPE token withdrawals after a mandatory delay. However, neither function includes the `whenWithdrawalNotPaused` modifier, which is intended to block withdrawals when the contract’s withdrawal functionality is paused. While both functions use the `whenNotPaused` modifier (for general contract pauses), the lack of `whenWithdrawalNotPaused` enables users to bypass withdrawal-specific restrictions.
This vulnerability undermines the protocol’s ability to enforce withdrawal pauses, which may be activated during emergencies (e.g., security incidents or liquidity issues).

**Impact:** 
The absence of the `whenWithdrawalNotPaused` modifier allows users to confirm and withdraw HYPE tokens even when withdrawals are paused, violating the protocol’s security controls. This could lead to:

Unauthorized Fund Drains: Users withdrawing HYPE during a pause intended to protect the contract (e.g., during a suspected exploit).
