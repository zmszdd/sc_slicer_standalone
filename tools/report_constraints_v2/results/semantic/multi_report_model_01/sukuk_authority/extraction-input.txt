## Finding description and impact

The `WERC7575Vault` contract's `redeem` and `withdraw` functions (via internal `_withdraw`) fail to correctly validate the caller's authority to spend the `owner`'s shares when `msg.sender != owner`.

The implementation calls `_shareToken.spendSelfAllowance(owner, shares)`, which checks if `owner` has approved themselves. In the WERC7575 system, active users are required to have self-allowance to use the token. The contract **fails to check** if `msg.sender` has an allowance from `owner`.


**Impact:**
Any user can call `redeem` specifying another user as the `owner`. Since the victim (if active) has self-allowance, the check passes, and the victim's shares are burned, with assets sent to the attacker (specified as `receiver`). This allows for direct theft of funds from any user.
