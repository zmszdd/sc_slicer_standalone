## Finding description and impact

The CLOB.sol contract contains logic intended to prevent "zero-cost" trades, in which one party might receive assets without returning anything, often due to rounding or dust values.

However, the current implementation uses a bitwise AND operation (&) to detect such cases:

https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L503-L505
https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L544-L546

This logic is flawed. The bitwise AND between two valid, non-zero values can be zero if they don’t share any set bits (e.g., powers of two like 8 and 16). This leads to false positives, causing legitimate trades to revert.

For example:
8 & 16 == 0 despite both being valid, non-zero amounts.

This misbehavior introduces a Denial of Service (DoS) vector for certain trade sizes, potentially allowing malicious actors or unfortunate users to experience repeated failed transactions.
