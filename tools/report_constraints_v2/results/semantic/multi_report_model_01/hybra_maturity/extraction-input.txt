> A user can deposit, earn rewards, and pull out the very next block because the contract never writes the lock timestamp it later checks.

### Summary

GaugeV2 was designed to enforce a cooldown (“maturity”) before liquidity can be withdrawn, protecting the protocol from mercenary farming and short-cycle reward extraction. The mechanism hinges on the `maturityTime` mapping: deposits should set `maturityTime[user] = block.timestamp + lockPeriod`, and withdrawals should revert until that time passes.

The withdrawal path does include a `require(block.timestamp >= maturityTime[msg.sender], "!MATURE")`, but the deposit path never sets the mapping. Solidity’s default for a mapping value is zero, so the check always passes. Any user can therefore enter and exit the gauge instantly, capturing emissions without respecting the intended lock. This undermines the tokenomics assumptions documented under “Locks & Voting Power” and “G-1/G-2 invariants,” effectively nullifying the maturity design.

### Impact

Removing the mandatory hold period turns the gauge into a yield faucet for fast-moving liquidity. Users can cycle in and out before price-impact protection or emission decay applies, siphoning a disproportionate share of HYBR rewards and undermining fee alignment. Long-term LPs are disincentivised, trading depth erodes, and bribe economics suffer because nothing forces sustained stake.
