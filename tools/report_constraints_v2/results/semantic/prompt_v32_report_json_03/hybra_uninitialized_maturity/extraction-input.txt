# Uninitialized `maturityTime` Mapping Allows Instant Withdrawals, Completely Bypassing Lock-up Mechanism

## Severity
**Medium**

### Root Cause

The `GaugeV2` contract implements a maturity check in the `_withdraw` function to enforce a time-based lock-up period before users can withdraw their deposited tokens:


However, the critical flaw is that the `maturityTime` mapping is **never initialized or updated** anywhere in the contract. In Solidity, uninitialized `uint256` mappings default to `0` for all keys. This means:

- `maturityTime[user]` always equals `0` (Unix epoch: January 1, 1970)
- `block.timestamp` in any real-world scenario is always greater than `0`
- The condition `block.timestamp >= maturityTime[msg.sender]` **always evaluates to `true`**

The maturity check becomes a no-op, providing zero protection against immediate withdrawals.

### Impact

This vulnerability has several significant impacts:

1. **Complete Bypass of Lock-up Mechanism**: Users can deposit and immediately withdraw their tokens in the same transaction or block, rendering the intended maturity/vesting period completely useless.

3. Users could potentially:
   - Deposit tokens just before reward distribution
   - Claim rewards
   - Immediately withdraw without any lock-up penalty
   - This enables "flash-staking" attacks on the reward system

4. **Protocol Design Failure**: The presence of unused maturity tracking code suggests the protocol intended to implement time-locked staking but failed to complete the implementation, leaving a security gap.
