# semantic-v3.16 开发回归报告

## 目标与范围

v3.16 不改写冻结的 v3.15，而是把第二步从“模型自由选择公式模板”改为“模型提取关系，
程序固定逻辑骨架”，并增加派生量定义和字段级局部修复。开发集复用
`prompt_v315_holdout_02` 的 5 份已见报告及其已验证要素，只重跑形式化步骤，因此所有结果
都是开发回归，不是泛化准确率。

## 实现

1. `report-formal-plan/4`：`relation_class` 唯一决定模板；除单调性和守恒外统一编译为
   `relation_obligation`，模型不再自由切换 requires/forbids 等模板。
2. `derived_definitions`：任何被引用且标为 derived 的整数必须由报告支持的
   add/sub/mul 表达式定义；定义进入 I 和 V，不能留下无约束 expected/fair 变量。
3. 字段级局部修复：首个合法 JSON 计划成为修复基线，后续只能修改校验器允许的顶层字段；
   关系类别、意图和其他冻结决策被改动时拒绝，并在 attempts 中记录修改范围。
4. v4 来源对齐将安全意图归因到 I 属性本身，核心观测量仍必须由所选直接影响支撑，避免
   为通过检查而把 intent ID 重复附到每个变量。
5. 增加 P/根因/V 时间角色提示、比例公平交叉相乘提示、同一未知乘法因子两侧重复检查，
   以及未限定数值被改写为其他常量的检查。

## 三轮开发结果

| 轮次 | 最终候选 | 可继续 | 主要观察 |
|---|---:|---:|---|
| development_01 | 1/5 | 1/5 | 派生定义首次修复 Monetrix；模板/来源/修复范围仍不稳 |
| development_02 | 4/5 | 3/5 | 固定模板和比例交叉相乘开始生效；Olas 被非必要 blocking 限制阻断 |
| development_03 | 5/5 | 5/5 | 五例均形成候选并保留 `needs_review`；共 8 次模型响应、49,153 tokens |

最终开发轮的工程完成率不能当作准确率。独立产物复核只有 Monetrix 的 P/I/V 公式基本
完整：它正确生成 `expected_decimals = underlying_decimals + decimals_offset`，并不再把
错误的 `reported_decimals = 6` 放入 P。其余案例仍出现以下语义错误：

- GTE Perps 用“储备一致”布尔量替代所选“LP 价值低于参考池”影响；
- Intuition 在比例式两侧重复同一个 `snapshot_balance_weight`，关系可约掉关键量；
- Olas 把“偏差超过容差”缩成一般 validatePrice 调用，I 过强；
- GTE Spot 将 100.5 取整/放宽为 101，P 数值不忠实。

上述错误转化为冻结前的通用提示或硬检查。完整本地回归为 **311/311**，v3.15 历史逻辑
仍可重放。开发结果不进入后续留出集分数。

## 结论

固定模板、派生定义和局部修复显著提高了工程完成率，并阻止重试时任意更换语义决策；但
它们没有自动解决“公式是否与选中影响同义”。因此 v3.16 仍需独立留出测试，且 Z3 通过
继续只表示生成公式内部一致。
