# semantic-v3.15 通用安全关系与 I/V 对齐实现报告

日期：2026-09-20

## 本轮目标

针对 v3.14 留出集中“自然语言要素有依据、但形式公式失真”的主要问题，在阶段二内部
增加通用安全关系分类和核心观测量对齐检查。不修改阶段一、阶段三，也不覆盖 v3.14
冻结结果。

## 已实现

1. `report-formal-plan/3` 新增 12 类 `relation_class`，覆盖权限、数值、边界、单调性、
   守恒、比例、状态对应、时间、序列、数据结构、活性和范围容量关系。
2. 新增 `relation_obligation`、`monotonicity`、`conservation` 三种确定性模板；历史四种
   模板继续为旧计划服务。
3. 数量表达从乘法扩展为有单位的加、减、乘；程序继续执行类型和单位检查。
4. 要素层可保留 1–4 个直接影响；单个形式计划严格选择一个影响，避免混合不同关系。
5. 增加类别—模板兼容表。类别和模板不匹配时，在生成 SMT 前拒绝。
6. 增加核心观测量对齐：程序从 pattern 中机械提取定义 I/V 的变量，要求这些变量的
   `source_ids` 合并后同时覆盖 `intent_id` 和每个 `impact_id`。
7. 每次成功的 v3.15 神经形式化生成 `relation-alignment.json`，记录关系类别、模板、核心
   观测量、来源覆盖和“V 由程序直接取反生成”的审计状态。离线复验会重新计算并比较该文件。
8. 对齐失败加入固定重试反馈，只描述缺少哪类来源绑定，不提供目标公式。

## 能解决什么

- OLAS 一类候选若 I/V 核心变量只由无关的 `buyback_completes` 支持、没有同时连接安全
  意图和所选影响，将被新的来源对齐门拒绝。
- Merkl 可使用 `state_correspondence + relation_obligation` 直接表达事件字段与状态字段相等。
- Panoptic 可使用 `monotonicity` 表达 `total_assets_after >= total_assets_before`。
- 资产总量与费用关系可使用 `conservation` 和加减表达，而不必压成自由布尔量。

## 仍不能证明什么

来源覆盖只证明模型声明“这些变量来自这些陈述”，不能独立证明模型理解正确。模型仍可能
把错误变量绑定到正确 ID。当前一个计划仍只生成一个核心 claim；同一报告中的多个不同关系
尚未自动拆分。真实留出测试进一步发现跨分支拼接、P 来源不蕴含谓词、额外授权项弱化 I
等错误；来源覆盖和 Z3 都无法单独发现这些问题。v3.14 的历史准确率结论保持不变。

下一步应增加独立、只降级不升级的公式忠实度复核，再建立新版本和新留出集。
