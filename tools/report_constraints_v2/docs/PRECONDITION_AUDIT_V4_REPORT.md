# 阶段二：P 条件证据与时序审查小测

日期：2026-09-16。目标是减少 P 的两类错误：无原文依据的限定、以及把动作或坏结果
误写成结果发生前的条件。只审查报告提取出的语句和已编号原文片段；不读取合约、PoC、修复代码，
不执行阶段一或阶段三。

## 发现与修正

初版审查把报告中的“如果 X 则发生漏洞”误解为“必须证明 X 曾实际发生”，
在 Sukuk 和 Intuition 各误报两条条件。v2 改为检查 X 是否可作为**条件场景**，
同时保留无依据权限、额外历史事实的拒绝。之后发现仅查来源仍会漏掉“坏结果混入 P”。
v3 把“证据支持”和“是否为前置条件”分开，但没有时序参照，误把先前授权配置当作当前漏洞动作。
v4 只补充已提取的动作/影响摘要来定位检查点；这些摘要**不作为证据**，证据轴仍只看该条 P
引用的原文片段。此拆分参考了对原子事实与证据逐项核对的研究
([HalluMeasure](https://aclanthology.org/2024.emnlp-main.837/)、
[RECV](https://aclanthology.org/2025.findings-acl.1059/))，但本项目结果须独立验证。

| 保存的提取输出 | v4 审查结果 | 关键核对 |
| --- | --- | --- |
| 旧 Forte | 2 条 P 中 1 条待审 | “任何人/未授权者可调用”缺原文依据；零输入条件保留 |
| v3.8 Intuition | 3 条 P 均不触发待审 | `<1e9` 初始化、截断为零、持有存款作为条件场景；不要求历史交易证明 |
| v3.8 Sukuk | 3 条 P 中 1 条待审 | “此前已注册”没有其所引片段支持；配置 token 和先前 max allowance 保留 |
| v3.9 Sukuk | 3 条 P 中 1 条待审 | 新提示去掉上述历史断言，但仍把注销后的未撤销结果放进 P；角色轴识别 |

原始结果位于 `results/semantic/support_audit_04/`。v4 共 5 次模型尝试：
4 次有结构化结果，1 次空响应后受控重试；记录合计 171.426 秒、29,171 tokens、
估算费用 0.011360316 美元。空响应在 `sukuk_v39/` 原样保留；脚本此后会在失败时
写 `status.json`，不再仅留下异常堆栈。成功运行若有原 `auto-triage.json`，
还会写 `audited-triage.json`：**只能把 candidate 降为 review，不能升级候选或判断真假**。

v3.9 是独立可选 Prompt，只做了一次 Sukuk `elements-only` 真实调用；它消除了旧历史前提，
但仍产生 P/坏结果混合，因此**未证明生成准确率提升，也未测试完整形式化链**。
默认 Prompt 与 v3.8 冻结结果未替换。当前 226 项本地回归通过。

这些是三个问题样例、四份保存输出的针对性回归，不是随机样本或人工确认的金标准；
模型审查也可能漏报。下一步应先扩充未参与提示设计的留出报告，核对 P 的证据与角色，
再扩展到 I/V 的证据、方向和范围；准确率只能在独立审核样本上报告。
