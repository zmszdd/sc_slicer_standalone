## 1. 与目标对齐

核心目标保持不变：从报告描述与影响推导报告隐含的安全性质，并转成第三阶段可分析的约束。最终研究问题是 PoC 是否支持报告声称的具体效果，不是泛化发现所有漏洞。

不能把所有性质强制写成传统状态不变量。报告可能需要状态不变量、授权条件、前后状态关系、拒绝条件或有界时序义务。当前用 P（场景前提）、I（预期安全）、V（声称坏效果）及命名检查点统一表达有界关系；无界最终到账、跨链收敛、复杂量化性质无法表达时明确保留未形式化。

V 对报告一致性判断更直接；I 说明为何 V 破坏安全意图。仅违反某个 I 不代表报告全部效果成立。局部权限接管不等于全部资产被盗，余额增加不等于全部资金取走，交易回退不等于永久锁仓。

## 2. 方法调研与取舍

以下是代表性论文方法，不是声称所有工具都有可直接用于本项目的商业接口，也不以其论文效果数字推断本项目效果。

- **nl2spec（CAV 2023）**：将自然语言翻译为时序逻辑，并将子公式回溯到输入片段以处理歧义。借鉴为本项目的“原文证据位置＋子公式来源映射”；不引入其交互前端，不要求用户手写每份公式。[原论文](https://arxiv.org/abs/2303.04864)
- **PropertyGPT（NDSS 2025）**：从既有人工性质检索参考，生成合约性质，并用编译/静态分析反馈及验证器处理候选。借鉴其中间规格与检查反馈架构；它主要针对代码生成性质，不能替代对某份报告含义的忠实提取。本项目暂不加入性质向量库，以免预设公式污染报告解释。[原论文](https://www.ndss-symposium.org/wp-content/uploads/2025-1357-paper.pdf)
- **SmartInv（IEEE S&P 2024）**：使用合约代码与自然语言上下文进行分层推理，推断不变量并检查违反。借鉴分层语义推理，不直接复用其漏洞发现目标、训练管线或代码输入策略。本项目首先报告独立推导，代码只在后续绑定阶段进入。[作者论文](https://arxiv.org/abs/2411.09217)
- **AutoSpec+（ACL 2026 System Demonstrations）**：采用模型候选规格与符号验证批评者组成受约束的规格合成流程。借鉴职责分离与拒绝候选机制；其程序验证目标与本项目报告一致性仍不同。[原论文](https://aclanthology.org/2026.acl-demo.66/)

这些取舍是根据本项目目标作出的设计判断，并不是复现或直接调用上述系统。InvCon/Trace2Inv 可作为以后轨迹/状态处理背景，不进入报告声明推导主线。

## 3. 先提取核心要素，不直接跳到公式

第一步输出 `report-elements/1`：

| 核心要素 | 当前表示 | 必须保留的信息 |
|---|---|---|
| 场景范围 | scope.flow/environment | 操作、链/环境、条件范围，不扩大为整个协议 |
| 行为主体 | entities.role/name | 攻击者、受害者、授权主体；报告未提供的主体不虚构 |
| 资产/资源/目标 | entities + statement.entity_ids | 哪种资产、哪方状态、哪份合约；具体数量在陈述和后续观测中表达 |
| 攻击前提与能力 | precondition/assumption 陈述 | 已初始化、未授权、持有资产、可调用能力、外部条件；假设与原文事实分开 |
| 操作路径 | action 陈述 + attack_steps | 作者声称的操作顺序；这是报告里的路径，不是第一阶段切片分析结果 |
| 根因 | root_cause 陈述 | 作者声称的根因，不能当成已验证实现事实 |
| 具体影响 | 多条 impact 陈述 | 效果、受影响对象、全部/部分、金额、方向、时间及持续性，不把所有影响混成一个标签 |
| 安全意图 | security_intent 陈述 | 正常应该怎样；隐含意图标 inferred，与坏效果分离 |
| 证据与不确定性 | evidence/modality/ambiguities | 精确引文、asserted/potential/inferred、缺失与歧义 |

核心要素中的数量、能力和因果说明目前仍含自然语言，不声称全部都已机器形式化。第二步才定义对应观测符号并生成 AST。

系统为引文记录所有字符区间和行号；重复引文记录所有出现位置，不自动猜选。主体和陈述使用稳定 ID，使公式可以追溯到提取材料。输入排除 PoC/修复段落和多行代码块，保留描述里的行内标识。这不是能保证零代码语义的自然语言清洗器。

## 4. 再生成形式化候选

第二步输出 `report-formalization/1`：

- 动态观测符号：sort、单位、主体/资产关联、语义、输入或 before/after 检查点、原文证据。
- 每个 claim 单独包含 P/I/V、作用范围、模态、假设、限制。多个 claim 不合成一个未经解释的全局 V。
- 每个性质同时保存自然语言解释、AST、推导说明和陈述来源 ID。
- 每个布尔子公式均有 AST 路径到来源陈述的映射，便于定位错误而非重写整份规格。
- 每条影响显式标记 formalized/partial/unformalized，并说明原因。这是模型/助手声明的覆盖情况，不能自动当成经人工确认的真实覆盖率。

P 仅引用前提/假设；I 仅引用安全意图；V 仅引用影响。符号、主体、路径、引文及引用必须合法。这样可限制角色混淆，但模型仍可能给安全意图配上方向错误的 AST，因此必须再做符号关系审查。

当前后端复用数学整数、布尔值和非数值地址身份。支持加减、比较、逻辑组合、蕴含，
并支持报告明确给出的整数乘积两侧比较；v3.15 计划层也允许有单位的加减表达、单调性和
守恒模板。仍不支持一般除法、单位消去、函数调用、量化及
无界时序。明确数值界限须作为公式条件，不假装等价于 Solidity uint256、溢出或 EVM
行为。无法表达就保留阻塞性未决项，不能用过弱公式冒充完整性质。

## 5. 符号验收自动进入流程

`semantic_pipeline.py` 每次生成 bundle 时自动执行：

1. 结构、实体/陈述引用、精确证据与公式来源检查。
2. 类型、单位和布尔性质检查。
3. P 可行性、I/V 可行性及空真/恒真风险检查。
4. 每个 claim 的 P∧V、P∧V∧¬I、P∧V∧I 关系审查。
5. 潜在效果升级、缺少影响覆盖、遗漏 claim 及声明歧义的审查。

若 P∧V 可行而 P∧V∧¬I 不可行，V 在 P 下满足 I，可能是 I/V 写反、I 太弱或对应关系不对；系统标 needs_review。这不是万能语义判定器：即使有违反见证，也可能主体错、单位错、过度推断，仍需抽样或针对警报审查。

保存三层状态，避免再次把代码绑定门槛混入核心目标：

- `core_formalization_status`：是否形成候选 I（不要求 V 或切片成功）。
- `acceptance_status`：候选是否有关系、覆盖、模态或歧义警报。
- `code_alignment_status/execution_ready`：代码阶段状态；当前始终 not_attempted/false。

`candidate_checks_passed` 也仅是候选检查通过，不是语义正确、执行就绪或报告真实。需要审查不等于必须用户逐份手写公式；原则是自动生成、自动拒绝/告警、重点核对不确定样例。

## 6. 与第一、三阶段的接口

第二阶段支持独立 `--report` 输入，无 PoC 也能开展；精确配对案例 `--case-dir` 另外只读核对 UID 和代码 SHA。第一阶段与核心报告推导可并行。

新 `stage3-semantic-spec/1` 保存规范/要素/每个 claim 的 SMT 路径和哈希。它是待绑定规范，不兼容旧 consumer 的执行就绪格式。后续绑定器应根据语义主体、单位和检查点映射代码变量；无法映射不得猜测，也不得反改报告声明。

第三阶段需从实际 PoC 与保真的关键路径建立 T，再检查 P∧T、P∧T∧¬I、P∧T∧V、P∧T∧¬V。不能把 I/V 直接作为执行前提。交易回退、外部调用、token 特性、执行版本与有界探索都由第三阶段显式建模。

最终宜输出“支持/不支持/无法判断某个报告效果”。SAT 只支持建模范围内可达，UNSAT 也受前提、代码保真和探索界限约束；不能直接换成报告真/假标签。

## 7. 成本、反馈与评测

当前神经路径先调用一次信息充分性筛选；通过后再调用核心要素和形式化，因此无重试时
最多三次。任一步被拒绝即停止后续调用。不向模型提供 PoC 或既有样例答案，无无限修复
循环。外发默认关闭，需明确用户授权及 `--extract --allow-report-upload`。

当前要素步骤可选一次、形式化步骤可选至多两次有预算反馈；每次尝试单独保存。反馈只指出
结构、类型、来源、数值、关系兼容或恒真式错误，不提供目标公式，也不在本地静默改写模型
语义。默认重试数仍为零，避免无界调用成本。

建议评测分开报告：

- 要素忠实性：主体、对象、前提、数量/全部性、时间和模态是否正确。
- I/V 语义正确性：正常意图与坏效果是否区分；不要只比较字符串，允许等价公式。
- 影响覆盖：每条影响完整/部分/未形式化，特别区分经济影响与权限/时间代理指标。
- 约束质量：类型、单位、可行性、空真、过弱/过强及弃权比例。
- 实用性与成本：代码可绑定比例、每份调用/用量/时延；第三阶段结果另行测量。

先用已有失败 Brix 作为回归样例，再选 5–10 份不同类型的精确配对报告；独立核对时不拿报告 validity 标签充当语义标准答案。无需先上微调、向量数据库或大规模多代理。
