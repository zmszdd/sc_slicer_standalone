UniswapPriceOracle.validatePrice collapses to spot price, allowing slippage checks to pass under manipulation

## Summary
`UniswapPriceOracle.validatePrice()` computes a TWAP that is always equal to the current spot price, so the slippage check effectively never fails.

## Finding Description
`validatePrice()` uses the pair’s cumulative price at the last update (`cumulativePriceLast`) and the current spot price (`tradePrice`) to synthesize a new cumulative price. It then computes the TWAP using:


But since `cumulativePrice` is computed as `cumulativePriceLast + tradePrice * elapsedTime`, the TWAP simplifies to `tradePrice`. This makes the `derivation` always 0, causing `validatePrice()` to return `true` whenever at least one block has elapsed. As a result, the slippage guard in `BuyBackBurner._buyOLAS()` becomes ineffective and the contract can execute swaps at manipulated prices.

This breaks the expected security guarantee that buybacks are protected by a TWAP-based slippage check. A malicious actor can temporarily skew the Uniswap V2 pool (e.g., with a flash loan) and call `buyBack`, causing the protocol to trade at a distorted price. Because the check uses the manipulated spot price as the “TWAP,” it passes even for extreme deviations.

## Impact Explanation
Buybacks can be executed at arbitrarily manipulated prices, enabling extraction of value from the treasury/BuyBackBurner contract. This is a direct loss scenario when the pool is manipulated around the buyback transaction.

## Likelihood Explanation
The bug is deterministic and always present when `validatePrice()` is used. Uniswap V2 pools are trivially manipulable within a single transaction via flash liquidity, and `buyBack` is permissionless. A motivated attacker can exploit this whenever funds are available.

## Recommendation
Implement a true TWAP calculation using two different cumulative price observations over time. For example:
- Store `cumulativePriceLast` and `blockTimestampLast` in the oracle, update them on a fixed interval, and compare the current cumulative price to the stored values; or
- Use UniswapV2OracleLibrary’s `currentCumulativePrices()` and compute TWAP over a minimum window.

Additionally, set `amountOutMinimum` on swaps based on the oracle to avoid trading at bad spot prices even if oracle validation is bypassed.
