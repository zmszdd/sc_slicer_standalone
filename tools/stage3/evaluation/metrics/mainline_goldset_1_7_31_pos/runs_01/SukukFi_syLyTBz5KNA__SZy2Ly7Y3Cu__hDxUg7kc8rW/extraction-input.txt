Authorization Bypass in WERC7575Vault.withdraw() Allows Fund Theft

## Finding description and impact

The `withdraw()` function in `WERC7575Vault` fails to verify that `msg.sender` is authorized to withdraw on behalf of the `owner`, allowing anyone to steal funds from users who have self-allowance.


### Root Cause

The `WERC7575Vault.withdraw()` function does not implement the authorization check described in its comment. While the comment states "msg.sender must be owner OR have allowance for the shares", the function only calls `_shareToken.spendSelfAllowance(owner, shares)` which checks the owner's self-allowance, not the caller's authorization.

### Attack Path

1. Victim obtains self-allowance through validator permit signature
2. Attacker calls `withdraw(assets, attacker_address, victim_address)`
3. Function burns victim's shares and transfers assets to attacker
4. Victim loses funds while attacker receives the assets

### Impact

Complete loss of funds for any user with self-allowance. Since self-allowance is required for normal operations (transfers, withdrawals), all active users are vulnerable to having their entire balance stolen.
