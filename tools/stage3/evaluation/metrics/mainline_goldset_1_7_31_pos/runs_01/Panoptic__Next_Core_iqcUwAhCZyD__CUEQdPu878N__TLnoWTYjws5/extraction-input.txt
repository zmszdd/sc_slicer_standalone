BuilderWallet.init() lacks access control, allowing anyone to hijack admin and steal accumulated fees

## Finding description and impact

The BuilderWallet.init() function has no access control:
While BuilderFactory.deployBuilder() correctly sets builderAdmin atomically after deployment, there is no restriction preventing subsequent calls to init(). Anyone can call this function at any time to overwrite the builderAdmin. BuilderWallet contracts receive protocol fees as they are used as fee recipients via _computeBuilderWallet() which is referenced in getFeeRecipient().

### Attack scenario
1. BuilderFactory owner deploys a BuilderWallet with legitimate builderAdmin
2. Protocol fees accumulate in the wallet over time
3. Attacker calls init(attackerAddress) to hijack admin role
4. Attacker calls sweep(token, attackerAddress) to drain all tokens

Impact: Direct theft of all accumulated builder fees with no preconditions required.
