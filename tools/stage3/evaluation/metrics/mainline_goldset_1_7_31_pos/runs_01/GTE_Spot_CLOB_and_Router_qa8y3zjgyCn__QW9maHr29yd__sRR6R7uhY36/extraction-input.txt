Invalid check of `maxNumLimitsPerSide` allows more orders to be added without removal of non competitive orders

## Finding description and impact

Clob orderBooks have a `maxNumLimitsPerSide` from which on addition of new orders, the non competive orders should be removed. But the contract makes an assumption that there will be only one order in the worst price limit queue.

For cases where the worst price limit queue has more than one order, the limit will not be removed and if the new order being added introduces a new limit/price queue, the `maxNumLimitsPerSide` variable will be exceeded and the check  of `ds.askTree.size() == maxNumLimitsPerSide)` will return false hence the least competitive price order will not be removed from the orderBook while it should be.

[Link to code](https://github.com/code-423n4/2025-07-gte-clob/blob/92a8839e3eb9715d53e24f0168442cecdc9b784b/contracts/clob/CLOB.sol#L625-L630)

This will make the side's tree to grow to a non intended size with very many non competitive orders that should be removed to  give room for new ones. It also breaks a significant protocal invariant that should hold.

## Recommended mitigation steps

Consider modifying the check from `ds.askTree.size() == maxNumLimitsPerSide)` to `ds.askTree.size() >= maxNumLimitsPerSide)` to allow continued removal of non competitive orders.
