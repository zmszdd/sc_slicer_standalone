Attacker can front-run user withdrawals to steal funds in WERC7575Vault

### Vulnerability Details

The `WERC7575Vault` contract acts as an intermediary for the `WERC7575ShareToken`. A critical vulnerability exists in the `redeem` and `withdraw` functions, where the `owner` parameter is exposed and potentially lacks sufficient control checks against `msg.sender`.


This implementation allows an attacker to execute a front-running attack. By monitoring the mempool for a user's pending transaction (or simply exploiting an existing approval), an attacker can call `redeem` or `withdraw` specifying the victim's address as the `owner` and the attacker's address as the `receiver`.

**Scenario:**
1. The user creates an approval via permit, which is executed by the settlement.
2. The user submits a redeem request to the vault.
3. An attacker front-runs the user’s redeem transaction.
4. The user permanently loses their funds.

### Impact

An attacker can permanently steal the user's underlying assets during the withdrawal or redemption process. This leads to a direct loss of user funds.
