Operator address can be used as instance address to permanently block the operator from creating agent instance

## Finding description
The `ServiceRegistry.registerAgents` function do not check whether the given instances addresses are already in use as operator address. It only checks that an operator address has not been used as an instance address.


The function only checks that the instance address is not the same as the operator address registering the instance which is not enough as it is only effective for the current operator/tx.

An attacker can create a service with many slots just for this purpose. This attack cannot be stopped by pausing the `ServiceManager` as there is not pause check in the `ServiceManager.registerAgents` function.

The operator whitelist too is not helpful in this case as it is per service not global.

The victim operators can use another address but this will make managing instances harder for the operators. Plus the design supports multiple/unlimited instances per operator so this feature will be broken. Even worse, the malicious operator can keep registering any new operator address to ensure the DOS.

## Impact
Any operator can use any other operator's address as an instance address while registering agent instances for a service. This will permanently block the other operator from registering any agent instance for any service in the future, resulting in a Denial of Service (DoS) attack.

## Mitigation
Add another mapping in the service registry contract to keep track of all operator addresses so that it will be checked before registering instances.
