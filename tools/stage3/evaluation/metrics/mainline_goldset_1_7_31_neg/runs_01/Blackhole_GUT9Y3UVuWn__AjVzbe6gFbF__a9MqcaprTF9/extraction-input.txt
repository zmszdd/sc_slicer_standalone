Incorrect reward calculation when splitting SMNFT

## Finding description and impact

In the split function split, for SMNFT type locks, the split logic is as follows:

1. The user specifies the original number of tokens to be split (_amount).

2. Then, the contract calculates the amount after the split (including the bonus), which is calculated as: _splitAmount = _amount + calculate_sm_nft_bonus(_amount).

3. The remaining amount of the original locked position is newLocked.amount - _splitAmount. Note that newLocked.amount is the total amount of the original locked position (including the bonus).

The problem is that the total amount of the original locked position (ie newLocked.amount) already includes the bonus. When splitting, the split part calculates the bonus again, resulting in repeated calculation of the bonus.

## Recommended mitigation steps

1. When splitting an SMNFT locked position, the total amount should be split proportionally instead of recalculating the reward. That is, the split amount should be the corresponding proportion of the original locked position amount.
2. For the split function, when the locked position is of SMNFT type, _locked.amount should be split directly proportionally without recalculating the reward.
