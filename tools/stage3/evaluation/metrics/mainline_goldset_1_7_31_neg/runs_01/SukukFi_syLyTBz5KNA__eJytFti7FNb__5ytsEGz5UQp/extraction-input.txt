External Balance Check in WERC7575ShareToken::unregisterVault Enables Vault Registry Denial-of-Service

## Summary
The `unregisterVault()` function in `WERC7575ShareToken` can be permanently blocked by sending 1 wei of the underlying asset directly to the vault address. Combined with the `MAX_VAULTS_PER_SHARE_TOKEN = 10` limit, this allows an attacker to fill all registry slots and then "dust" each vault, permanently locking the vault registry.

## Vulnerability Details

### Root Cause
The `unregisterVault()` function enforces a strict balance check:


This check uses `balanceOf()` (external balance) rather than internal accounting (`totalAssets()`). Neither `WERC7575Vault` nor `ERC7575VaultUpgradeable` implements a `sweep()` function to remove excess tokens not backed by shares.

### Attack Vector

1. Attacker sends 1 wei of the underlying asset directly to the vault contract address
2. Admin attempts to call `unregisterVault()`
3. Transaction reverts with `CannotUnregisterVaultAssetBalance()` because `balanceOf(vault) == 1`
4. Vault remains registered indefinitely
