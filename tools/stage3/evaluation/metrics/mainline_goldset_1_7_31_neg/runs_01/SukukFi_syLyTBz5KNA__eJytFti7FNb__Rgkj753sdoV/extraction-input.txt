DoS on `unregisterVault` via Asset Donation

## Finding description and impact

### Description

An attacker can permanently prevent the contract owner from unregistering a vault by sending a dust amount of the vault's underlying asset directly to the vault's address. This constitutes a permanent denial-of-service attack on a core administrative function.

### Code Analysis

The `unregisterVault` function includes a safety check to ensure the vault holds no assets before it can be removed. It does this by checking the result of the vault's `totalAssets()` function, which in turn reads the vault's ERC20 balance of the asset.

If an attacker transfers even 1 wei of the asset token to the `vaultAddress`, its `balanceOf()` will be greater than zero. This will cause the `totalAssets != 0` check to be true, making the `unregisterVault` call revert.

### Impact

This is a permanent Denial of Service on a core governance function. The `WERC7575Vault` contract does not have a "sweep" or rescue function for the owner to remove these donated, non-share-backed assets. Because the assets cannot be removed, the owner can never unregister the vault.

This attack has several consequences:
-   The owner cannot remove old, compromised, or buggy vaults.
-   It hinders the owner's ability to perform upgrades or migrate the system to a new set of contracts.
-   It creates a permanent, undeletable entry in the Share Token's vault registry, which can lead to clutter and confusion for off-chain systems.

The cost of this attack is negligible (a single token transfer), but its effect is permanent.


## Recommended mitigation steps

The safety check in `unregisterVault` should be changed. Instead of checking that the vault's asset balance is zero, it should verify that there are no outstanding shares that need to be honored. Since shares are managed by the `WERC7575ShareToken`, this check is more complex.

A more direct and practical solution is to provide a way for the owner to recover donated assets from a vault. Add a privileged `sweep` function to the `WERC7575Vault.sol` contract. This function would allow the owner to withdraw a specified amount of the asset token, enabling them to zero out the balance and proceed with unregistering the vault.

With this function, the owner can remove the dust assets sent by an attacker and successfully call `unregisterVault`, mitigating the DoS vector.
