Dust Donation Permanently DoS unregisterVault via Raw balanceOf Check

## Finding description and impact

The unregisterVault(address asset) function in ShareTokenUpgradeable.sol is intended to safely remove a vault from the registry once it is empty and deactivated. As a safety measure, it performs two checks:

IERC7575Vault(vaultAddress).totalAssets() must return 0
ERC20(asset).balanceOf(vaultAddress) must return 0

The second check uses the raw ERC-20 balance, which includes any tokens sent directly to the vault contract (donations, dust, airdrops, etc.).
An attacker can permanently DoS the unregistration of any vault by sending 1 wei (or any non-zero amount) directly to the vault:
``` token.transfer(address(vault), 1); ```


After this transaction:

totalAssets() can still return 0 (vault is deactivated / uses internal accounting)
balanceOf(vault) is now > 0  unregisterVaultpermanently reverts with CannotUnregisterVaultAssetBalance

## Impact

Permanent denial-of-service on a core administrative function required for:
Migrating to a new vault implementation
Decommissioning a stablecoin/asset
Emergency cleanup or protocol shutdown

Affects every asset in the multi-vault system (USDC, HONEY, USDT0, etc.)
Attack cost: < $0.001 on Berachain
No recovery mechanism exists (no sweep/dust removal function)
