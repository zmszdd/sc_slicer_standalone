Double Bonus Application in updateToSMNFT() Inflates Voting Power and Corrupts Global Balance Tracking

## Summary

The VotingEscrow contract manages vote-escrowed tokens with special Super Massive NFT (smNFT) functionality that provides bonus voting power. The `updateToSMNFT()` function converts regular locked positions to smNFTs, which should apply a one-time bonus while maintaining accurate balance tracking. This conversion is critical for the voting mechanism and affects user voting power calculations across the entire protocol.


The function incorrectly assumes that `_locked.amount` contains only the base token amount without any existing bonuses. However, analysis of other contract functions reveals that `_locked.amount` may already include bonuses from previous operations:

The contract provides `calculate_original_sm_nft_amount()` specifically to extract base amounts from bonused values, but `updateToSMNFT()` fails to use it.

## Impact
This vulnerability creates multiple severe issues affecting the core token economics:

The `smNFTBalance` global variable becomes inflated because it receives bonused amounts instead of base amounts. This corrupts voting power calculations since `smNFTBalance` is used in `totalSupplyAtT()` and other critical functions.

Users converting existing smNFTs or previously bonused positions receive additional unintended bonuses, creating unfair voting power advantages and potential governance manipulation.

The function burns the wrong amount of tokens, leading to supply accounting errors that cascade through the entire protocol's token economics.

Sophisticated users could potentially trigger multiple conversions to accumulate excess bonuses, gaining disproportionate voting power and protocol influence.

## Remediation


This bug directly affects core token economics, voting power calculations, and protocol governance. The state corruption and potential for economic exploitation make this a critical issue requiring immediate attention.
