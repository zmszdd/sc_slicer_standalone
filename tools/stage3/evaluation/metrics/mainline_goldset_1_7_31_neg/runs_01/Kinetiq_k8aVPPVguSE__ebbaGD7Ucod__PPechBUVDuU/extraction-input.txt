Stake function does not account for slashing amount when checking stakingLimit in StakingManager

### Description and Impact
The `StakingManager` contract implements a `stakingLimit` parameter to control the maximum HYPE tokens that could be staked in the system. However, the current implementation fails to accurately track the actual amount of tokens under management due to not accounting for slashed tokens for the `StakingManager`. 

The `stake` function performs a check
> require(netStaked + msg.value <= stakingLimit, "Staking limit reached"); 

Where `netStaked` is calculated as 
> // Get rewards from ValidatorManager to account for earned rewards
> // This approach uses global rewards but provides a reasonable approximation
> // for this StakingManager's available capacity
> uint256 rewardsAmount = validatorManager.totalRewards();
> uint256 netStaked = totalStaked + rewardsAmount - totalClaimed;   <@   

However, the `netStaked` fails to account for the total slashed amount resulting in a higher `netStaked` value than originally is. This creates a situation where the contract will reject new stakes even when the actual amount under management is well below the limit, effectively reducing the protocol's capacity unnecessarily.


### Recommendation
Include the `ValidatorManager::totalSlashing` global value in the calculation of `netStaked`.
