Agent instance registration can be blocked permanently by malicious services

## Finding description and impact

The `ServiceManager::registerAgents` function allows operators to register agent instances to a service. Internally, it calls `ServiceRegistry::registerAgents`, which includes a check to ensure that each agent instance is not already registered to another service:


This check can be exploited by an attacker to prevent a legitimate instance from being registered to a valid service, effectively locking it indefinitely.

Example scenario:
1. Bob owns an agent instance and intends to register it to a legitimate service.
2. Alice, knowing Bob’s instance address, quickly creates a fake service with minimal bond requirements (e.g., 1 wei).
3. Alice registers Bob’s instance to her fake service and deploys it. Once deployed, the instance cannot be unbonded.
4. When Bob attempts to register the same instance to the legitimate service, the transaction fails due to the instance already being registered elsewhere.
5. Because Alice controls the fake service, she can keep it alive indefinitely, permanently blocking Bob from using his instance.

The attack is extremely low-cost, as the attacker can set bond requirements to trivial values (e.g., 1 wei) and incur minimal gas fees.

This type of griefing only requires the attacker to know the victim's instance address before it is officially registered. Several realistic scenarios make this feasible:
- The attacker monitors the mempool and frontruns the victim's registration.
- If a DAO or governance mechanism deploys instances at deterministic addresses, the attacker can register those addresses pre-deployment.
- If instances are deployed via a factory contract, their future addresses can be predicted and registered ahead of time.

In cases where an agent instance holds funds and is non-upgradeable, being registered to a malicious service can render it permanently unusable, leading to a complete loss of those funds.

## Recommended mitigation steps

Enforce that all agent instances expose an `operator` function or equivalent. 

`ServiceManager::registerAgents` should verify that the caller is the designated operator of each instance being registered. This would ensure that only authorized entities can register a given instance, preventing this form of griefing.
